# 03 · 인물

PC, NPC, 적을 만들고 움직이는 기준이다. 세계가 살아 있다는 느낌은 인물에서 나온다.

## 1. PC 생성

PC는 **시나리오 뼈대가 정해진 뒤** 만든다. 시나리오의 PC 자리(02-scenario)에 맞는 인물이어야 처음부터 사건과 연결된다.

### 흐름

1. **AI가 플레이어당 4명을 제안한다.** 역할이 정해져 있다(아래). 인물마다 직업이 기대는 능력치 2개(`keyStats`), 직업 기술 6개(기술 목록에서), 시작 물건 후보 정확히 3개, 허당끼(`quirk`)를 함께 낸다. 시작 물건과 간직한 물건에는 짧은 설명(무엇이고 어떤 상태인가)과 사연(이 사람과 어떻게 얽혔나)을 붙인다.
2. **엔진이 후보마다 능력치를 굴린다.** 직업의 핵심 능력치 2개는 60·65·70 중에서, 나머지 6개는 35~60(5 단위)에서, 8개 합은 420이다. 직업이 무엇에 기대는지 엔진이 보장하므로 "지능 30인 학자"는 생기지 않는다.
3. **플레이어가 한 명을 고른다.** 나이·성별·이름을 고칠 수 있다. 성별을 바꾸면 그 성별의 이름(`altName`)으로 바뀐다. 준비 화면에서 기술을 카테고리별 버튼으로 **2개 더 고른다**(아래 기술).
4. **엔진이 나머지를 확정한다.** 기술 수치와 파생 능력치. 시작 물건은 아직 주지 않는다.
5. **돌잡이: 프롤로그 끝에 시작 물건을 고른다.** 프롤로그가 끝날 때 카드가 그 PC의 시작 물건 후보 3개를 버튼으로 띄우고 플레이어가 하나를 고른다(04 0절). 무작위 지급은 없다. 세계에는 세 후보 모두가 결정적으로 쓰일 자리가 준비돼 있다(02 6절 `kitMoments`). 간직한 물건은 이와 별개로 처음부터 지닌다.

**인물 생성은 한국어로만 쓴다.** 이름, 직업, 기술, 물건 이름에 영어를 쓰지 않는다(괄호 병기도 안 된다). 기술은 아래 목록의 이름 그대로 쓴다(엔진 반려).

### 능력치와 파생치

| 항목 | 값 |
|---|---|
| 핵심 능력치 2개 | 60·65·70 중 무작위 |
| 나머지 6개 | 35~60, 8개 합 420 |
| 체력(HP) | (건강+크기)/10+2, 최소 10 |
| 이성(SAN) | 55+0.4×(정신−50), 최소 45 |
| 행운 | 35~65 |

### 기술 (목록 v3.3.1)

- **직업 기술 6개**: 60·55·50·50·45·40. **플레이어가 고르는 기술 2개**: 각 50. 같은 기술을 두 번 고르지 않는다.
- **늘 보이는 기술**: 관찰·듣기 40, 격투·사격 20, 회피 = 민첩/2+15. 직업 기술이나 고른 기술로 정하면 그 값과 기본값 중 높은 쪽이다.
- **모국어** = 교육. 기술 칸을 쓰지 않는다. **크툴루 신화**는 고를 수 없다(게임 중 금단의 지식으로만 오른다).
- 목록에 없는 기술의 기본값은 20이다. 능력치를 그대로 굴리는 판정(근력으로 버티기, 민첩으로 건너뛰기)은 기술이 아니라 능력치로 한다.
- 플레이어의 추리를 대신하는 기술(직감, 추리, 통찰, 위험감지)은 쓰지 않는다.

| 카테고리 | 기술 |
|---|---|
| 학문 | 회계, 인류학, 고고학, 천문학, 생물학, 화학, 지질학, 역사, 법률, 물리학, 약학, 의학, 자연사 |
| 사회 | 흥정, 신용, 말주변, 설득, 심리학, 정신분석, 변장, 위압, 매혹 |
| 조사 | 관찰, 자료조사, 듣기, 추적, 위치파악, 감식, 신비학 |
| 잠입 | 숨기, 은닉, 잠행, 자물쇠 다루기, 손놀림 |
| 생존 | 응급치료, 생존, 수영, 승마, 등반, 도약 |
| 테크 | 컴퓨터, 제작, 전기수리, 전자공학, 기계수리, 운전, 중장비 운전, 조종, 사진술 |
| 전투 | 회피, 격투, 던지기, 사격 |
| 언어 | 외국어(언어 이름을 괄호로: 외국어(라틴어)) |
| 예술/공예 | 분야를 괄호로: 예술/공예(목공), 예술/공예(음향) |

응급치료는 지금 살리는 기술, 의학은 몸에 무슨 일이 일어났는지 알아내는 기술이다. 생존·조종은 분야를 괄호로 적을 수 있다.

의료품인 필수품·세계 물품에는 이름뿐 아니라 `medicalKind`(붕대 `bandage`, 구급상자 `firstAidKit`, 전문 처치 키트 `surgicalKit`)를 지정한다. 크기·수량·소유와 설명을 함께 남긴다. 기존 저장의 명확한 의료품 이름을 분류하더라도 새 물건이나 수량을 지급하지 않는다.

엔진 담당: 능력치 배열, 기능·파생 수치 계산, 장비 칸.

### 제안할 인물의 조건

**직업이 핵심 능력치를 정한다.** 직업이 기대는 능력치 2개(`keyStats`)를 함께 내면 엔진이 그 둘을 높게 굴린다. 몸을 쓰는 일이면 근력·건강, 배운 사람의 일이면 교육·지능, 사람을 상대하는 일이면 외모·정신 같은 식이다. 네 인물의 기본 역할 구성은 다음과 같다. 앞 PC의 선택으로 막힌 역할은 아직 가능한 테마/일반/조커 역할과 다른 핵심 능력치의 인물로 대체해, 표시된 후보 4명이 실제로 선택 가능하게 한다. 이미 고른 팀원과의 중복 금지 자체는 유지한다:

| 역할 | 수 | 내용 |
|---|---|---|
| 원작 테마 (`theme`) | 2 | 하나는 원작의 대표 기관·사건 쪽, 하나는 그 세계의 다른 생활·산업 쪽 |
| 일반 (`general`) | 1 | 그 시대·지역에 흔한 평범한 직업 |
| 조커 (`joker`) | 1 | 의외지만 실제로 쓸모가 있는 직업. 우스꽝스러울 필요는 없다 |

**PC끼리 성향이 겹치지 않는다.** 앞 PC가 고른 역할(원작 테마는 둘이 같아도 된다)이나 같은 핵심 능력치 2개에 기대는 인물은 고를 수 없다(엔진 반려). 둘 다 서류를 다루는 사람이면 같은 방식으로만 사건에 들어간다.

**좋은 인물 예 (1971년 로드아일랜드, PC 자리: "사라진 수녀의 조카")**
- (원작 테마: 교구) 교육·지능 높음 → **주립대 라틴어 강사.** 고모에게 교구 옛 기록의 번역을 부탁받은 적이 있다.
- (원작 테마: 시골 생활) 힘·체력 높음 → **농가 우물 파는 인부.** 페론 농가 옆 땅의 우물을 지난달 팠다.
- (일반) 힘·체력 높음 → **도로 공사장 인부.** 고모(수녀)가 매주 보내던 편지가 3주째 끊겼다.
- (조커) 외모·의지 높음 → **순회 보험 판매원.** 고모 명의의 작은 생명보험을 직접 팔았다.

모두 같은 자리에 맞지만 사건에 들어가는 방식과 쓸 수 있는 수단이 다르다.

**나쁜 조합:** 경찰관, 사립탐정, 기자. 모두 "조사하는 직업"이라 능력치와 상관없이 같은 방식으로 사건에 들어간다.

### 인물마다 쓸 것

| 항목 | 내용 |
|---|---|
| 직업과 지금 하는 일 | 이 세계에서의 실제 업무, 지위, 생활 |
| PC 자리와의 연결 | 왜 이 사람이 이 자리에 있는가, 무엇이 이미 걸려 있는가 |
| 성격 | 남들이 보는 모습과 실제 모습 |
| 원하는 것 | 이 사람이 삶에서 원하는 것 |
| 두려워하는 것 | 잃고 싶지 않은 것, 피하고 싶은 것 |
| 결점 | 판단을 흐리게 하는 약점 |
| 말버릇 | 실제 말투 예시 한두 문장 |
| 허당끼 (`quirk`) | 진지한 사람도 가끔 드러내는 엉뚱한 버릇이나 서툰 구석 하나. 공포 사이의 웃음은 여기서 나온다(04a 7절) |
| 외형 카드 (`looks`) | face 얼굴형·눈매, hair 머리 모양과 색, mark 한눈에 알아볼 특징(흉터·점·안경), outfit 늘 입는 옷. 외모 능력치를 인상에 반영한다(높으면 단정하고 눈에 띄게, 낮으면 초췌하거나 거칠게). 그림을 다시 그려도 같은 사람으로 보이게 하는 기준이고, 인물끼리 머리와 특징이 겹치지 않게 한다. 배우를 떠올려 써도 되지만 실존 인물의 이름은 적지 않는다 |
| 다른 성별의 이름 (`altName`) | 플레이어가 준비 화면에서 성별을 바꾸면 쓸 이름 {gender, name}. 성은 같게, 그 성별에 자연스러운 이름. 플레이어는 이름을 직접 고칠 수도 있다 |
| 아끼는 물건 | 늘 지니는 물건 하나와 그 이유 (시작 물건과 별개, 0칸 소형) |
| 과거의 한 장면 | 이 사람을 보여 주는 구체적인 일화 하나 |
| 개인 목표와 비밀 (초안) | 고른 뒤 02의 개인 이해관계 단계에서 완성한다 |

이것은 **처지와 바탕**이다. 동기화 뒤 이 인물이 무엇을 느끼고 선택할지는 플레이어가 정한다. 플레이어가 성격이나 과거를 직접 정하면 그것이 우선이다.

### 공개와 비공개

**후보를 고를 때** 플레이어는 그 인물이 **이미 아는 처지**를 보고 고른다. 숨은 원인이나 진상과의 연결은 보여 주지 않는다.

| 보여 준다 (그 인물이 아는 것) | 숨긴다 (키퍼만 앎) |
|---|---|
| 고모가 해리스빌 교회의 수녀다 | 고모가 왜, 무엇 때문에 사라졌는가 |
| 매주 오던 편지가 3주째 끊겼다 | 사라진 기록과 원작 사건의 연결 |
| 교회에 전화했더니 "잠시 자리를 비웠다"는 답만 들었다 | 이 처지가 진상과 어떻게 이어지는가 |

후보 화면은 모든 플레이어가 함께 보므로 **공용 정보만** 띄운다: 직업, 성격(겉), 처지, 말버릇, 허당끼, 능력치, 직업 기술, 아끼는 물건, 시작 물건 후보. 개인 목표와 비밀 초안은 고른 뒤 해당 플레이어만 따로 연다. 동료가 어떤 처지의 인물을 골랐는지는 서로 안다.

- **공용 프로필:** 이름, 나이, 직업, 외형, 공개 과거, 능력치와 기능. 모두가 본다.
- **개인 자료:** 개인 목표, 비밀, 그 PC만 아는 시작 지식. 게임 시작 전에 해당 플레이어만 본다. 같은 화면에서 플레이하므로 화면에서 한 명씩 열어 보고 닫는다.

### 출발 위치

함께 시작할지, 각자 다른 곳에서 시작할지는 시나리오 상황에 따른다. 함께 시작하면 서로 아는 사이(동료, 이웃, 가족, 오래된 지인)로 만들고, 함께 겪은 일 하나를 준다. 따로 시작하면 유예 30턴 안에 위험 없는 계기로 만나게 한다(02 4절).

## 2. 이름

PC와 NPC 모두 같은 기준을 따른다.

- **시대·지역·계층에 맞는 이름.** 1971년 미국 시골, 1930년대 경성, 현대 도쿄의 이름은 서로 다르다. 이민자, 노동자, 상류층의 이름도 다르다.
- **흔한 이름을 피한다.** 그 문화에서 누구나 떠올리는 첫 번째 이름(John Smith, 김철수, 다니엘, 네이선 같은)은 쓰지 않는다.
- **한 시나리오 안에서 겹치지 않게.** 첫 글자, 발음, 길이가 비슷한 이름을 나란히 두지 않는다.
- **이름에 이야기를 담는다.** 가문, 고향, 종교, 별명이 이름에서 드러나면 좋다.
- 엔진이 지금까지 쓴 이름을 기록한다. 창작 PC·NPC는 이전 캠페인에서 쓴 이름을 다시 쓰지 않는다. 고정 원작 인물은 정체와 이름을 보존하고 원작 인물임을 구별해 기록한다. 같은 인물을 다른 이름으로 위장해 중복 검사를 피하지 않는다.

엔진 담당: 사용한 이름 기록, 중복 반려.

## 3. NPC

NPC는 그 세계에서 자기 삶을 사는 사람이다. PC가 만나지 않아도 존재하고 움직인다.

### 깊이

| 깊이 | 수 (2인 기준) | 준비할 것 |
|---|---|---|
| **핵심** | 6~8명 | 아래 정본 전체. 이야기의 중심 인물들 |
| **고정** | 나머지 (이름 있는 NPC는 모두 15명 안팎) | 정본 중 이름·외형·역할·목적·위치·말투·아는 것 |
| **행인** | 필요할 때 | 지금 하는 일, 위치. 개별 대사를 하면 이름과 최소 외형을 정하고 기록 |

### 정본 (핵심 NPC)

| 항목 | 내용 |
|---|---|
| 이름, 나이, 직업, 외형 | 외형은 처음 정한 대로 유지한다. 외형은 처음 보는 PC에게 이름 대신 쓰이므로 한눈에 구별되게 쓴다. 핵심 NPC는 PC와 같은 외형 카드(`looks`)도 단다 |
| 처음부터 아는 PC | 지인·가족·동료처럼 이름을 이미 아는 PC(`knownBy`). 나머지 PC는 겉모습으로 만난다 |
| 목적 | 지금 이 사람이 원하는 것. 사건이 없어도 하고 있는 일 |
| 지키려는 것 | 사람, 물건, 비밀, 지위 |
| 아는 것 / 모르는 것 | 사건과 진상에 대해 실제로 아는 범위 |
| 숨기는 것 | 왜 숨기는가 |
| 관계 | 다른 NPC와의 신뢰, 갈등, 빚, 두려움 |
| 말투 | 실제 대사 예시 두세 문장. 호칭과 존대 |
| 허당끼 (`quirk`) | 진지한 사람도 가끔 드러내는 엉뚱한 버릇이나 서툰 구석 하나. 유쾌한 사람(`jolly`)이 한두 명 있으면 좋다 |
| 위치와 동선 | 하루 동안 어디에 있는가 |
| PC 없을 때의 다음 행동 | PC가 오지 않으면 이 사람은 무엇을 하는가 |
| 도움과 거절의 경계 | 무엇까지 도와주고 무엇은 거절하는가 |
| 변심 조건 | 동료가 되거나, 등을 돌리거나, 배신하게 되는 조건 |
| 중시하는 성격 (`values`) | 용감함·정직함·배려·호기심·유머 중 1~2개. PC가 그런 행동을 하면 관계가 1점 더 오른다 |
| 관계의 끝 (`ceiling`) | 끝까지 비밀을 지키는 사람은 '호의'까지만 오른다. 생략하면 '신뢰' |
| 처음 사이 (`startRelation`) | 배경상 처음부터 사이가 있으면 PC별 −10~+10. 생략하면 아는 사이(`knownBy`)는 +3, 그 밖은 0 |
| 말 상대하기 실력 (`socialSkill`) | 이 사람을 말로 움직이기 어려운 정도. 50 이상이면 설득이 어려움, 90 이상이면 극한 |
| 프로필 (`profile`) | 좋아하는 것·싫어하는 것·두려워하는 것. 함께 시간을 보내면 하나씩 드러난다(지키고 싶은 사람·중시하는 것·숨기는 것도 차례로) |
| 좋아하는 선물 (`favoriteGift`) | 세계 안에서 구할 수 있는 것 |
| 개인 이야기 (`personalStories`) 2개 | 호의(첫째)·신뢰(둘째)가 되면 이 사람이 먼저 꺼내는 부탁(`ask`), 할 일(`steps`), 끝내면 위기 때 한 번 해 주는 결정적 도움(`reward`), 본편 단서 조각(`clueFragment`) |
| 거짓말 (`lie`) | 거짓말하는 사람만(02 2절) |
| 수치 | 능력치, 현재·최대 HP/SAN, 전문 기능 3~4개, 실제 소지품·수량. 동행/인계 후보는 시작 전에 실제 값이 있어야 한다(엔진 담당). PC와 함께 다닐 핵심 NPC 1~2명에게 `sheet`(능력치 8종, `san`, `luck`, 전문 기능 3~4개, 소지품)와 `stats.HP`를 둔다. 누락 수치를 진행 중 임의로 채워 치료·인계 성공을 주장하지 않는다 |

### NPC가 움직이는 방식

- **무료 부하가 아니다.** 자기 목적, 안전, 신뢰에 따라 승낙하고, 조건을 걸고, 역제안하고, 거절한다. 동행을 승낙했다고 모든 위험한 지시에 따르지 않는다.
- **거절에는 이유와 다른 길을 붙인다.** "안 돼요"로 끝내지 않는다. 왜 안 되는지(그 사람의 사정)와 대신 할 수 있는 것, 또는 누구에게 가 보라는 말을 함께 준다. 막힌 곳마다 다음 길이 보여야 재미가 이어진다.
- **구한 사람은 남는다.** PC가 구한 NPC는 살아서 이야기에 다시 나온다(고마움, 정보, 도움, 때로는 새 걱정). 분위기를 위해 나중에 아무렇지 않게 죽이지 않는다.
- **아는 것만 말한다.** 보고 듣고 전해 들은 것만 안다. 같은 공간에 있었다고 모든 대화를 들은 것은 아니다.
- **말할 이유가 있으면 먼저 말한다.** 정보를 늘 거래로만 주지 않는다.
- **배신은 미리 있던 동기와 기회로만.** 처음부터 해칠 의도가 있던 사람은 그 동기와 준비가 정본에 있다. 분위기를 위해 갑자기 배신자를 만들지 않는다. 모든 동료를 배신자나 희생자로 만들지도 않는다.
- **기억한다.** 도움, 다툼, 약속, 모욕을 기억하고 태도가 바뀐다. 한 번 도왔다고 무조건 충성하지 않는다.
- **NPC끼리 부딪친다.** 서로 다른 목적을 가진 NPC들이 다투고, PC에게 편을 들라고 한다. PC의 선택이 누구를 살리고 누구를 잃게 하는지 달라진다.
- **스스로 돕는다.** 다친 사람을 보면 자기 수단과 안전이 허용하는 처치를 제안·시도하고, 위험을 보면 경고하거나 도망친다. 요청을 기다리기만 하지 않는다. 위치·도구·처치 조건과 판정은 PC와 같은 원칙을 따른다.
- **자기 일을 끝낸다.** 할 수 있는 수리·정리·이동은 목적과 수단에 맞춰 스스로 고른다. 이동·작업 계획은 이유와 함께 엔진에 먼저 보고하고, 승인된 시간과 결과 뒤에 묘사한다. 경로를 건너뛰거나 이동 중인 NPC를 이미 도착한 것으로 쓰지 않는다. 진행 중 계획과 완료 결과를 기억하며 매 턴 같은 부탁을 PC에게 돌려주지 않는다. PC의 동의·선택이나 최종 해결까지 대신하지 않는다.

### 엔진이 주는 지침

매 턴 엔진은 PC 주변 NPC들의 현재 상태를 지침으로 준다: 누가 어디에 있는가, 지금 무엇을 하려 하는가, 이 PC에 대해 무엇을 알고 어떤 태도인가, 이번 턴에 할 행동. AI는 이 지침 안에서 연기하고 대사를 만든다. 지침에 없는 행동(새 정보, 새 동의, 위치 이동)이 필요하면 엔진에 보고한다.

엔진 담당: NPC 정본 보관, 위치·목적 진행, 지식·관계 기록, 매 턴 지침.

## 4. 적

### 정본

| 항목 | 내용 |
|---|---|
| 이름·외형 | 처음 정한 외형을 유지한다. 원작 대표 적의 모습에서 나온다 |
| 등급 | 1 일반 개체 / 2 강한 개체 / 3 특정 수단으로만 무력화. 생사·퇴거 조건과 혼동하지 않는다(05 7절) |
| 출처 | 원작의 적 / 그 세계관의 다른 존재 / 더 강한·변형 개체 / 사람. 근거는 분석서 대표 위협이나 `worldBestiary` (02 6절) |
| 역할 | 추적 / 경비 / 배회 |
| 감각 | 무엇으로 PC를 찾는가 (소리, 빛, 냄새, 체온, 생각) |
| 행동 | 평소 무엇을 하고, PC를 발견하면 어떻게 하는가 |
| 공격 | 실제 발사·접촉 부위, 사거리, 피해, 고유 효과와 발동·해제 조건 |
| 싸움 수치 (필수) | `stats`에 HP, **장갑**, 공격마다 쓰는 **기술 값**(공격의 `skill` 이름 그대로)을 넣는다. 장갑은 맞을 때마다 피해에서 빠진다: 맨몸 0, 비늘·껍질·두꺼운 가죽 1~2, 갑각·갑옷 3~4. 원작에 비늘이나 갑옷이 있으면 반드시 장갑으로 옮기고, 맨살(눈·배·틈)은 약점에 적는다. 기술 값: 평범한 사람 30~50, 숙련된 적 50~65, 괴물 우두머리 60~80. 빠지면 엔진이 반려한다(`enemy_numbers_missing`). 빠진 채 굴리면 모든 적이 장갑 0·명중 50이 되어 원작보다 약하고 서로 똑같다 |
| 약점과 한계 | 관측하고 배울 수 있는 것 |
| 추격 패턴 | 05-checks 추격에서 쓰는 이 적만의 방식 |
| 퇴각 | 언제 물러나고 어디로 가는가 |

- 지성 없는 적과 지성 있는 적은 다르게 움직인다. 지성 있는 적은 길목을 막고, 덫을 놓고, 동료를 부르고, 정보를 모은다. 그래도 PC의 숨은 계획을 알지는 못한다.
- 정당하게 숨으면 찾지 못하고, 정당하게 죽이면 죽는다. 텔레파시로 다시 찾아내거나 되살아나지 않는다. 비PC HP 0은 사망이며, 근원을 남기는 퇴거·봉인은 HP 0 사망과 구별한 사전 해결 조건이다. 불사·특수 무력화 조건은 3등급의 실제 능력과 한계로 준비하고 사망 뒤 부활을 붙이지 않는다. **예외는 슬래셔 하나다:** 인간 살인마 장르에서만 살인마 한 종에 `returns`를 달 수 있고, 그 살인마는 HP 0이 되면 죽은 것처럼 쓰러졌다가 키퍼가 가장 무서운 순간에 한 번 다시 일으킬 수 있다(`slasherReturn`, HP 절반). 두 번째로 쓰러지면 정말 죽는다.
- 적의 수와 공급은 시작 전에 정한 풀 안에서만 늘어난다. 종의 정본과 현장의 개체를 구별한다. 사건·배회 풀의 개체별 id로 HP·상태를 보존하며, 한 마리의 부상·죽음을 그 종 전체에 적용하지 않는다. 다른 장면의 같은 개체를 새 개체로 바꿔 되살리지 않는다.
- `origin:source`는 분석서의 실제 공격 부위·고유 효과·행동·한계와 대조한다. 달라진 존재라면 `variant`와 변경 근거를 쓰고, 원작 개체인 척 공격이나 약점을 바꾸지 않는다.

엔진 담당: 수치를 굴리는 일(명중·피해·장갑 차감), 위치, 감지, 이동.
