# 1차 정리의 결정 기록

## 사용자와 확정한 항목

- 아르카나, 장기 생존(Survival), 캠페인 간 영구 성장, MP, 소설화 기능을 제거한다.
- 연대기(Chronicle), 일반 생존 판정, 현재 PC의 캠페인 내부 기능 성장·전문 분야 발전은 유지한다.
- 원작은 난수 기반 실제 작품 후보 A~F 중 플레이어가 선택한다. 직접 작품 지정도 유지한다.
- 모든 PC를 먼저 만들고 세계를 생성한다. 세계는 원작과 개연성을 우선하며 필요한 부분에 PC 설정을 선택적으로 활용한다. 고정적인 독립/종속 비율을 강제하지 않는다. 복수 PC의 참여 경로를 확인한다.
- 세계 법칙은 **원작의 정수와 테마를 살리는 최소 2개**다. 개수를 채우기 위한 원작과 무관한 기믹은 만들지 않는다.
- 비공개 세계·NPC·증거·난수·PC 상태를 계속 추적하며 Supabase의 검증 Checkpoint를 유지한다.
- 시작 전에 1~3명을 명시적으로 확정한다. 미입력은 질문하고 기다리며 기본 2인을 자동 적용하지 않는다. 세계/PC 확정 사실과 플레이어 주도권을 유지한다.
- 시작 설정 전체도 플레이어가 결정한다. 핵심 시드·시작 시드·인원·인지도·이야기 규모만 필수로 입력받는다. 배제할 세계관·직접 지정 장르/오마주/시대·PC 사전 관계는 미입력·빈칸일 때 추가 질문 없이 자동 `없음`으로 처리한다. 필수 입력이 갖춰질 때까지 원작 탐색·웹 검색·생성을 하지 않는다.
- `규모 미입력=사건`, 키퍼의 시작 시드 자동 보충, 인지도 난수 선택을 제거한다. 인원에 대한 단독 숫자는 인원만 확정한다. 원작은 전체 시작 설정 확정 뒤 선택하며, PC 생성은 원작 확정 뒤다.
- 정의되지 않은 신비주의자 아키타입의 광기 4점 예외를 삭제하고 전원 단일 SAN 5점 이상 손실 기준을 적용한다.
- 적용한 패치는 GitHub에 반영하고 개발 일지를 기록한다.
- 테스트 피드백: 첫 생활 목표 뒤 사건 연결을 유지하고 30턴 안에 본격 사건 입구를 제공한다. 세계/NPC가 먼저 움직이며 PC는 대응을 선택한다. 예시 영화의 사건을 고정 패턴으로 복제하지 않는다.
- 업무·수리는 선언한 목적 단위로 처리한다. 프로필의 붙들고 있는 것·연기 참고 항목과 종속 생성축을 제거한다. 연기 참고는 역할극 가이드로 해석했고 외형용 배우 레퍼런스는 유지했다.
- 일반 텍스트 응답은 20초 이내를 목표로 불필요한 조회·도구 호출·출력을 줄인다. 모델/도구 지연은 미측정이며 속도를 보장하지 않는다.
- 원작은 분위기뿐 아니라 구체적인 세계·인물·위협·대응 방식으로 구현한다. 핵심 특징마다 실제 세계 ref와 플레이에서의 차이를 연결한다.
- 중심 진실·흑막·위협은 공포스러워야 하고, 막지 못하거나 방치했을 때 중대한 손실이 있어야 한다. 규모는 원작과 사건에 맞추며 PC의 안전·관계·생활·선택한 보호 대상과 연결한다.
- 도주는 허용하되 미해결 위협의 대가를 실제 상태와 결말에 남긴다. 몸은 살았지만 사람·거처·공동체·미래의 안전을 잃을 수 있다. 도주 자체의 임의 벌점이나 성공한 구조·봉쇄의 취소는 하지 않는다.
- 기이한 소문·의뢰·사건을 듣고 조사하러 오는 시작도 허용한다. 진행 중의 교류·피해·발견으로 대응 이유가 깊어지게 하며, 모든 시나리오에 같은 클리셰나 정면전을 강제하지 않는다.

- 조사자 자동 외형은 특성 Draft의 APP가 확정된 뒤 완성한다. APP의 시각적 의미를 프로필·초상·장면·엔딩에 일관되게 적용하며 실제 외형 변화는 상태에 기록한다.
- 직업·풍경·상황 설명에는 적합한 웹 이미지를 출처가 있는 참고 자료로 활용한다. 일반 사진을 실제 PC/지도/증거로 확정하지 않으며 일반 턴마다 검색하지 않는다.
- 직업 Draft는 A/B에 생활권·특별을 하나씩, C/D에 원작 테마와 직접 연결되는 테마 생활권·테마 특별을 하나씩 배치한다. 각 쌍의 순서는 독립 생성 시드로 정하며 문자별 역할을 고정하지 않는다. 선수·감독·CEO·고위 관료·왕도 시대/원작에서 성립하면 가능하다. E/F는 자유형이며 생활권·특별 쌍을 강제하지 않는다.
- HUD는 Markdown 제목·아이콘·굵은 수치·3열 자원표·분류된 소지품 목록을 사용한다. 모바일/표 미지원 시 자원은 세 줄로 표시한다. 장식용 도구 호출이나 신규 상태/난이도·위험 판정을 추가하지 않는다. 값·공개 범위·입력 Gate와 수첩 Writer 계약은 유지한다.

- 공개된 PC 장면·단서는 P1~P3의 공통 지식이다. 플레이어 간 FOG·전용 장면·전달 전 차단을 제거한다. 미발견 세계·NPC 비밀은 계속 숨기며 물리적 위치·자원·행동권·직접 노출은 구분한다.
- 프로젝트 지침에 상황별 파일/규칙 ID 라우팅을 둔다. 같은 판 본문과 작업 상태가 있으면 규칙 검색·DB 조회 없이 처리한다. Supabase 조회는 로드·유실/충돌·저장 검증·복구·명시적 대조와 첫 연결/실제 계약 변경에 한정한다.
- 판정 기능/절차는 룰북, PC 수치·NPC 비밀·단서·발동 조건은 현재 작업 상태에서 확인한다. 기록 탐색은 자료조사, 시대적 의미의 전문 해석은 역사로 구분하며 실제 난관이 있을 때만 판정한다. 기능 선정·굴림 요청 자체로 DB를 읽지 않는다.
- 비공개 작업 상태는 실제 생성/로드한 데이터와 변경분이며 모델의 무제한 영구 메모리가 아니다. PC·세계 핵심·관련 장면·다른 장소를 포함한 발동 조건을 유지하고, 문맥에 실제 필요한 값이 없을 때만 한정 복구한다. 공개 메모에 비밀을 복사하지 않고 별도 서버의 존재를 가장하지 않는다.
- 비전투 Spotlight는 의미 있는 선택·결과 3회를 목표로 하고 대기자가 있으면 5회 뒤 첫 안전 경계에서 넘긴다. 이는 이번 요청에 따른 초기 운영 기준이다. 판정 연속 단계·메타·A는 제외하고 긴급 반응·실제 종료·참여 요청은 우선한다.
- 통상 이동은 20~30분이어도 실제 인과 충돌이 없으면 한 응답으로 완료한다. 분 수만으로 병렬 선언을 요구하던 기준은 제거했다. 선언 충돌·공유 인과·즉시 대응 또는 다른 PC 선택을 통째로 지워 버릴 대규모 생략만 조정한다. 다른 PC의 미선언 작업·대사·성과를 만들거나 두 장면을 정산 보고서로 섞지 않는다.
- 서술은 공포 소설처럼 풍부하고 영화처럼 장면이 보이는 문체를 기본으로 한다. 플레이어의 실제 대사는 본문의 직접화법으로 보존하고, 일반 장면을 짧은 상태 보고로 줄이지 않는다. NPC의 검증 해설·자동 면책 논평을 제거한다.
- 실제 읽는 자료에는 시대·작성자에 맞는 본문/발췌와 핵심 숫자·날짜를 제공한다. 기존 정본 안에서 처음 구체화한 원문은 저장·재열람에 유지하며 새로운 정답·비밀을 추가하지 않는다.
- 정상 행동 UI는 번호·아이콘·대상 — 할 일 요약과 4번 직접 행동으로 고정한다. 클라이언트에 실제 버튼 기능이 있으면 같은 계약을 사용하고, 일반 채팅은 선택 가능한 번호 행으로 표시한다.

## 편집 판단으로 정리한 충돌

- 회피 기본값: 일반 설명의 일괄 20을 제거하고 기존 전문 생성 규칙 floor(DEX/2)로 통일했다.
- 페이싱 수치: 시작 프롬프트의 다른 기준을 제거하고 주 룰북의 사건 약 2회/200~300 Turn, 대사건 약 3회/300~450, 연대기 현재 챕터 약 2~3회/200~450을 참고 기준으로 남겼다. 수치로 종료·피해를 강제하지 않는다.
- 영구 보상용 회차 참가 자격·정산 계산은 제거했다. 실제 플레이 회차라는 일반 표현은 남겼다.
- 1~100을 N개 표에 floor 매핑하는 방식은 유지하되, 100의 약수가 아닌 N에도 완전 균등하다는 잘못된 설명을 바로잡았다.
- 최종 종료 Checkpoint는 영구 보상 절차가 없어져도 최종 세계 상태를 보존하기 위해 유지했다. 같은 이벤트의 중복 종료 방지 역시 유지한다.
- 이미지·공개 수첩은 정본 게임 진행을 대신하지 않는 선택 연동으로 정리했다. 과거 운영 버전·배포 성공 설명은 실행 규칙에서 제외했다.

## 다음 게임 설계에서 판단할 항목

이 항목은 임의로 새 수치나 시스템을 만들지 않고 기존 동작을 보존했다.

1. **페이싱:** 이번 피드백으로 3:7 비율은 제거하고 초반 전달 기준을 추가했다. 기존 후반 Turn 참고선은 유지했으며 전체 캠페인 길이의 추가 조정은 실제 플레이로 판단한다.
2. **정확히 3개 캐릭터 태그·배우 참조·시각화 선택:** 캐릭터 재현에는 유용하지만 설정 단계가 길어질 수 있다. 사용자 경험을 본 뒤 간소화 범위를 정한다.
3. **SAN 장기적 광기 분모:** 원문은 '한 시나리오 내 현재 SAN의 1/5'이다. 시작 SAN/당일 SAN 등 다른 기준으로 바꾸지 않았다. 누적 손실의 기준 시점은 다음 판에서 명확히 정의할 필요가 있다.
4. **교대 기준의 실제 체감:** 공개 지식 공유와 시간 길이만으로 병렬 선언을 강제하지 않는 원칙을 적용했다. 3회 목표·5회 상한은 2~3인 실제 대기 시간과 장면 몰입을 보고 조정한다.
5. **Supabase·수첩의 신규 필드 호환:** 이 세션에는 해당 커넥터가 없어 실제 RPC·검증기·UI가 삭제된 필드를 요구하는지 확인하지 못했다. 운영 어댑터 검증/변경은 별도 작업이다.

수치와 판정 절차의 문서 대조는 REVIEW_CASES.md를 참고한다. 실제 장시간 AI 플레이를 통과했다는 의미는 아니다.
