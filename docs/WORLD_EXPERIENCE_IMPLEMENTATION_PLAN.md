## 1. 목표와 이번 작업의 경계

목표는 선택한 원작의 세계에서 새로운 인물이 평범한 목적을 수행하다 중대한 사건에 휘말리고, 발견·생존·돌파를 통해 더 깊은 진실과 강한 위협에 접근하며 의미 있는 해결·탈출에 도전하는 경험이다. 원작 요소는 실제 만남·행동·선택·결과를 만들고 다음 상황의 조건으로 남아야 한다.

사용자 문제 보고:

- 원작을 선택했어도 실제 체험은 비슷한 문서 조사·수리·행정 절차로 수렴한다.
- 파헤친 사건의 실체와 해결 난관이 작아, 발견할수록 긴장이 빠진다.
- 세밀한 묘사와 사소한 절차가 주요 발견·사건 발생·위기·돌파보다 길어진다.
- 플레이어가 일부러 위험을 찾아가기 전에는 세계와 적이 대기하는 느낌이 있다.
- 세계 정본에 원인과 설정은 있지만 실제로 겪을 사건 연결·적의 행동·결정적 해결이 빈약하다.

이 문서는 최초 계획과 구현 범위를 기록한다. 2026-11-08 사용자 적용 승인으로 실행 본문·지침·상태 의미 계약·검증에 반영했다. 최신 담당 규칙은 FINAL_THREAT_DESIGN / SCENARIO_BLUEPRINT / WORLD_INITIATIVE_EXECUTION / EXTREME_HAZARDS / STATE_SCHEMA다. 일반 사건은 분 단위 시한보다 조건 성립을 사용하며 시험의 40분 마감·괴물 수치를 기본값으로 채택하지 않았다. 구현 대조는 [WORLD_EXPERIENCE_REVIEW.md](WORLD_EXPERIENCE_REVIEW.md)를 참고한다. 구현 범위는 원작 분석 → 세계 생성 → 비공개 정본 → 플레이 중 사건 실행/장면 편집 → 진행 상태/세이브 → 검증 계약의 연결이다. 판정·피해·행운 수치, 입력 UI, 서버/앱 개발, 운영 저장 서비스 변경은 이 설계에 포함하지 않는다. 롤백으로 취소한 파일 세이브·작업 JSON·두 파일 전달·상태 효과 패치를 자동 재적용하지 않는다. 저장 **내용**을 강화하는 일과 저장 **수단**을 바꾸는 일은 구분한다.

### 전 항목에 적용할 원칙: 예시를 조건에 따라 작동하는 설계로 구현

이 계획의 A~G는 예시 장면을 반복 배치하는 목록이 아니다. 구현은 **원작의 허용 범위 + 확정된 세계 인과 + 현재 PC/파티 상태 + 플레이어의 실제 선택 + 지금까지의 결과**에서 이번에 적격인 접촉·위기·발견·돌파·환기를 도출하는 절차로 만든다. 예시를 본문에 더 많이 적는 것만으로 구현 완료라 하지 않는다.

| 판단 근거 | 적용에 반영할 것 | 반복 패턴 방지 |
|---|---|---|
| 원작/장르 | 존재론·기술·사회·위협·대응·정서의 실제 문법 | 모든 작품을 감염 생존극·기업 음모·문서 추리로 바꾸지 않음 |
| 확정된 세계/사건 | 현재 작동하는 원인·장소·NPC 목표·시간·수단·접근·차단 조건 | 예정 장면을 성립시키려고 진실·능력·증거를 뒤늦게 바꾸지 않음 |
| PC와 파티 상태 | 인원·직업/실제 기능·위치·부상/자원·지식·관계·선언한 목적 | 평범한 배송원·필수 직업·같은 개인적 위기를 모두에게 강요하지 않음 |
| 실제 선택과 방법 | 탐구·우회·선제 대응·협상·구조·도주·교류와 미선택 범위 | 준비한 사건을 건너뛰었다고 되돌리거나 성공을 무효화하지 않음 |
| 누적 결과 | 실제 획득/소모·처치/예방·막힌/열린 경로·위협 실행/취소 | 다음 장면을 위해 현재 상태를 초기화하거나 같은 적·위험을 반복 생성하지 않음 |
| 현재 장면의 필요 | 중요한 판단·긴급성·이미 확보한 안전·관계 교류의 가치 | 고정 순서/비율로 공격·반전·농담·잔씬을 할당하지 않음 |

향후 담당 본문은 각 요소마다 다음을 명시한다: **적용 조건 → 실제 작동 방식 → 가능한 대응/우회 → 결과와 다음 조건 → 적용하지 않는 경우 → 보존할 상태/ref**. ‘위험을 강화한다’ 같은 선언과 예시만 추가하지 않는다. 가능한 사건은 기존 세계에서 적격성을 확인한 뒤 구체화하고, 같은 역할을 하는 사건도 원작과 인물·선택에 따라 다른 방식으로 성립하게 한다.

- 물림·감염·배송물의 치료 가치, 허세 있는 조력자, 적이 더 커지는 순서, 피신처의 함정은 모두 예시다. 자동 등장 항목·캠페인 공통 단계·유일한 목표 변화/반전으로 등록하지 않는다.
- 선택한 원작의 핵심 체험을 접촉 가능하게 준비하되 특정 장면 관람을 강제하지 않는다. 예측·준비·회피로 위험을 막은 경우에도 원작 법칙을 이해하고 활용한 실제 경험과 성취로 인정한다.
- 기승전결은 의미 있는 상황 변화와 해결 방향의 연결이다. 같은 순서의 고정 장면이나 끝없는 위험 증가가 아니다. 개입으로 국면이 단축·결합되거나 위협이 감소하는 경우를 수용한다.
- 진행성 위해는 원작과 실제 노출이 적격할 때만 적용한다. 코미디/환기는 인물·상황·안전·사용자의 실제 반응과 호흡에 맞춘다. 적용하지 않는 판단도 정상 결과이며 빈자리를 다른 피해/농담으로 강제 충당하지 않는다.
- 생성에서 가능한 조건/관계를 확정하고, 플레이에서는 현재 결과를 갱신한다. 조건에 따라 장면을 다르게 만든다는 이유로 확정된 과거·진실·원작 법칙을 재설계하지 않는다.
- 저장에는 적용 중인 원인·조건과 실제 결과/ref를 보존한다. 미래에 반드시 실행할 예시 대본·강제 선택·PC 감정·모델 내부 추론을 저장하지 않는다.

완료 기준은 예시와 다른 원작/상황에서도 절차가 작동하는 것이다. 다양한 합성 사례뿐 아니라 **같은 세계에서 다른 PC 상태·선택을 주었을 때 결과가 달라지고, 같은 확정 사실은 유지되는지** 비교한다. 새로운 예시의 수를 늘리는 것으로 이 검증을 대신하지 않는다.

## 4. 1차 구현 요소와 설계 방법

### A. 원작 세계의 작동 방식과 실제 체험

현행 특징 기록을 다음 연결이 확인되는 내용으로 보완한다. 새 점수판이나 사용자에게 채우게 할 입력 양식은 만들지 않는다.

`원작 근거/허용·금지 범위 → 세계의 인물·장소·위협 → 자연스러운 접촉 조건 → 실제 선택과 대응 → 남는 결과 → 후속 국면`

- 원작의 확인된 설정, 이번 캠페인에서 만든 사건/인물, 각색 범위를 구분한다. 알려지지 않은 설정을 원작 사실로 채우지 않는다.
- 익숙한 원작의 새 이야기에서는 해당 작품의 존재론·시대·기술·조직·위협 원리를 기반으로 새 인물·사건을 만든다. 사용자가 별도 세계 각색을 지정하면 무엇을 계승하고 바꾸는지 먼저 명확히 한다.
- 비밀인 핵심 요소라도 플레이어가 접근할 수 있는 경로를 준비한다. 단 하나의 필수 장소/판정 성공에만 주요 체험을 묶지 않는다.
- 실제 체험은 피해 강제만 뜻하지 않는다. 관측·회피·협상·보호·추격·싸움·도구 활용·세계 법칙의 역이용도 포함한다. 유효한 선제 예방으로 정면 조우가 사라지면 그 차단 성취를 인정한다.
- 생성 검사는 ‘이름을 지워도 이 원작의 선택·위협·대응을 알아볼 수 있는가’, ‘주요 요소와 PC가 실제로 맞닿는가’를 본다.

### B. 중심 사건의 깊이와 해결의 무게

표면 문제, 실제 원인, 더 깊은 관계/규모, 현재 작동 중인 중심 위협, 막지 못할 때의 중대한 손실, 해결·탈출 조건을 함께 설계한다.

- 장치 수리·서류 확인·열쇠 획득 등의 국소 성공이 담당하는 기능을 명시한다. 그 기능은 안전 확보·새 경로·대응 수단·위협 차단처럼 실제 성취여야 한다.
- 중심 사건은 처음부터 그 국소 문제만으로 설명·종결되지 않는 깊이와 난관을 가진다. 단, 플레이어가 핵심 원인을 조기에 정확히 차단하면 유효한 조기 해결로 인정하고 분량용 새 음모를 붙이지 않는다.
- 위협은 목적/확산 원리·자원·능력·한계·전조·개입 가능한 약점/조건·현재 행동을 가진다. 체력만 높은 적, 만능 적, 무조건 실패를 만드는 메타 제약은 통과시키지 않는다.
- 클라이맥스는 실제 정보·관계·접근·도구·준비를 활용할 수 있는 큰 난관으로 준비한다. 설명을 들은 뒤 버튼 하나만 누르면 끝나는 중심 사건은 재검토한다. 압도적 위협에도 회피·차단·탈출·협상 등 원작과 인과에 맞는 대응 여지를 둔다.

### B-1. 최종 보스·최종 위험과 해결 난관의 생성축 보강

현행 SCENARIO_DNA의 Threat Behavior는 행동 성향, Climax Structure는 절정의 진행 방식, Ending Cost는 결과의 대가를 제안한다. 이 셋만으로 최종 보스/최종 위험의 정체·고유 능력·위협 범위·구체적인 대응 난관이 자동으로 정해지지는 않는다. 현재 절차의 단독 시험에서도 절정 축은 ‘두 목표 중 선택’이었지만 이것만으로 무엇과 맞서 어떤 위험을 돌파하는지는 나오지 않았다. 시험 초안의 변이체는 GPT가 추가로 구체화한 것으로, 완성된 최종 위협/전투 수치가 생성된 결과는 아니었다.

신규 생성은 **중심 사건의 최종 위협을 먼저 구체적으로 구성**하고, 그 원인·작동·접점·대응을 초중반 사건에 연결한다. 흑막/재난의 원인, 실제로 PC를 위협하는 존재/과정, 마지막에 극복할 문제는 각각 구분하되 인과적으로 묶는다. 하나의 인물/현상이 여러 역할을 맡을 수 있고 최종 국면도 사전 대응에 따라 바뀔 수 있다.

추가할 설계축 후보 8개:

| 축 | 확정할 내용 | 원작/조건에 따른 범위 |
|---|---|---|
| 1. 최종 위협의 실체 | 누가/무엇이 중심 위험이고 어디에 어떤 상태로 존재하는가 | 단일 적·적 집단/조직·생물학적 확산·작동 중인 현상·환경 붕괴·상호 연결된 복합 위험 등 적격 범위 |
| 2. 위협의 목표/진행 | 무엇을 달성/확산/파괴하며 왜 지금 개입이 필요한가 | 지능적 목적과 비인격적 진행 원리를 구분; 기존 Motive/Driver와 일치 |
| 3. 고유 능력과 한계 | 직접 접촉에서 어떤 위협을 경험하고, 무엇은 할 수 없는가 | 실제 공격/행동·사거리/범위·감각·내구/불사 여부·세계 법칙/기관 권한과 한계; 확정 수치가 필요하면 담당 판정/전투 규칙과 연결 |
| 4. 격화·전환 조건 | 어떤 실제 조건에서 더 위험해지거나 행동/영향 범위가 바뀌는가 | 생물학적 변화·자원/경로 확보·인물의 행동·시간/환경 등. 단일 상태가 적합하면 불필요한 변신/페이즈 생략 |
| 5. 결정적 국면의 압박 | 대응을 어렵게 만드는 실제 공간·시간·추적·동시 사건/대상이 무엇인가 | 위협의 실체와 현재 세계에서 파생. 기존 Climax Structure를 이 조건 안에서 해석 |
| 6. 개입·제압·탈출 조건 | 무엇을 실제로 바꾸면 위험을 끝내거나 벗어날 수 있는가 | 처치·차단·무력화·폭로/권력 해체·구조·봉쇄·탈출 등. 접근/실행 중 방해도 구체적으로 명시 |
| 7. 필요한 이해/준비와 획득 | 어떤 정보·기술·도구·접근·협력이 실제 대응 차이를 만드는가 | 복수 발견/확보 경로와 대체 수단. 해당 위협에 유효한 조기 해결도 인정 |
| 8. 실패/방치의 구체적 결과 | 누구/무엇이 어떤 범위로 손상되고 무엇을 예방할 수 있는가 | 실제 생명·신체·공동체·자유/거처·환경/정상성 등 중대한 손실; 기존 CAUSAL_ENDGAME_PRECOMMIT/Ending Cost와 연결 |

8개는 우선 **생성해야 할 내용의 축**이다. 전부 독립 d100 표로 굴려 모순된 능력/약점/목표를 조합하겠다는 뜻은 아니다. 구현 시 ① 원작과 직접 지정이 정하는 범위 ② 기존 축에서 파생할 내용 ③ 새 named stream/표가 필요한 변동 항목 ④ 반드시 구체화·검증할 필수 항목을 나눈다. 새 항목표·가중치·분포는 아직 미확정이며 실행 패치 때 설계/검증한다. 기존 Motive/Threat Behavior/Climax Structure/Ending Cost와 같은 사실을 별도로 재굴리지 않는다.

원작에 없는 초자연 능력·불사성·약점을 난수로 붙이지 않는다. 원작의 적격 후보 범위에서 실체와 작동을 먼저 정하고, 그 결과에 따라 이후 축의 조건을 좁힌다. 이미 확정한 항목과 충돌하면 미확정 부분의 적격성/재해석/허용된 국소 재생성 근거를 남긴다. 불리한 결과 회피와 구분한다.

세계 확정 시에는 최소한 `실체 ref / 원인·목표/진행 / 실제 능력·한계 / 현재 상태 / 격화 조건 / 플레이어에게 닿는 경로 / 유효한 개입·탈출 / 실패 결과`가 연결돼야 한다. 중요한 항목이 ‘나중에 정함’, ‘아주 강한 괴물’, ‘두 목표 중 하나 선택’ 같은 추상 문구로만 남으면 확정하지 않는다. 보스형 시나리오는 대면 전에 실제 행동·방어/피해·특수 조건 등 판정 가능한 명세를 갖추고, 재난형은 발동·진행·영향 범위·차단/탈출 조건을 명세한다.

작은 장치나 특정 증거 하나가 이 조건에서 맡는 역할도 정한다. 실제 핵심 원인 하나를 정확히 차단해서 조기 해결하는 창의적 성취는 인정한다. 그러나 정면에서 대응할 때도 위협의 방해·접근·실행 난관이 전혀 없고 사소한 고장 복구만으로 중심 사건 전체가 끝나는 설계는 생성 시 재검토한다. 최종 위협을 준비했다는 이유로 필수 보스전·등장 순서·희생·패배·강제 페이즈를 예약하지 않는다.

### B-2. 사건 스케일과 영향의 확대

사용자는 단독 생성 시험의 작은 통제/시설 문제보다 더 큰 사건과 위협을 원한다. 신규 세계 생성은 **초반에 마주한 표면 문제보다 더 큰 중심 원인·적/세력·위협의 영향과 결정적 난관**을 준비한다. 규모 확대는 중요 인물 수·장소 수·플레이 시간·보스 HP만 늘리는 작업이 아니다. 플레이어가 접촉하며 이해하는 사건의 범위, 위협의 실제 작동, 지켜야 할 것과 개입의 무게가 질적으로 달라져야 한다.

- 원인/세력의 스케일: 배후의 조직·권력·과정 또는 원작의 근본 위험이 현재 사건을 어떻게 만들고 유지하는가. 모든 원작에 거대 기업·비밀 결사·단일 흑막을 강제하지 않는다.
- 영향의 스케일: 개인의 불편을 넘어 어떤 생명·공동체·지역·기관·사회 기능·정상성이 실제로 위험해지는가. 이미 도달한 피해와 조건부 확산/미래 손실을 구분한다.
- 플레이의 스케일: 원작다운 서로 다른 공간·상대·접근·위험이 하나의 사건에서 어떻게 이어지는가. 주인공은 평범해도 큰 사태의 직접적인 위험/돌파를 경험할 수 있다. 모든 문제를 혼자 해결할 권한·능력을 지급하지 않는다.
- 해결의 스케일: 국소 수리/발견이 어떤 발판을 만들고, 최종 위협의 실질적인 개입·해결·탈출까지 어떤 큰 난관이 남는가. 전체 재난이 큰 경우에도 이번 사건에서 가능한 성취와 종료 범위를 명확히 한다.

STORY_SCALE의 플레이어 선택을 보존하면서 기본 생성의 내용과 무게를 강화한다. 사건은 응축된 생활권 안에서도 원작다운 중대한 위협과 깊은 원인/해결을 갖춘다. 대사건은 여러 장소·기관·세력의 움직임과 후속 결과가 실제로 충돌한다. 연대기는 지속 세계와 현재 챕터를 충분히 만들되 미래 챕터의 사건/결말을 선결정하지 않는다. 작은 규모 선택을 사소한 고장/행정 착오만 있는 이야기로 해석하지 않고, 큰 규모 선택을 의미 없는 이동·문서·잠금 단계를 늘릴 근거로 삼지 않는다.

처음부터 모든 정보를 설명하지 않는다. 실제 접촉·발견·대응의 결과로 더 넓은 사태가 드러나고, 그것이 현재 접근/목적/위험을 바꾸게 한다. ‘밖에서 엄청난 재난이 있다’는 설명만 있고 PC가 겪는 일은 계속 작은 심부름이면 규모 구현 실패다. 반대로 성공적인 선제 개입으로 위험이 줄어들면 그 성취를 보존하며 스케일을 유지하려고 새 재난을 덧붙이지 않는다.

### C. 인과로 연결된 주요 국면

기승전결을 PC의 대사/경로가 정해진 각본이 아니라, 기존 원인들이 바꿀 수 있는 세계 상태로 준비한다.

| 국면 | 생성 시 준비 | 플레이 중 확인할 변화 |
|---|---|---|
| 기 | 원작다운 정상 세계·PC의 실제 목적·첫 직접 충돌 | 평범한 목적만으로 처리하기 어려운 실제 문제와 대응 필요 |
| 승 | 발견/생존/돌파를 통해 접촉하는 인물·공간·위협과 후속 원인 | 이해·관계·접근·자원·위험이 달라짐 |
| 전 | 앞선 사실의 의미를 넓히는 깊은 진실·큰 위협·목표 변화 가능성 | 사실을 소급 무효화하지 않고 현재 판단과 해결 방향을 바꿈 |
| 결 | 조건이 충돌하는 결정적 개입·해결·탈출과 여파 | 실제 성취/실패·예방·잔존 손실로 결과가 정해짐 |

각 주요 전환에는 실제 원인/ref, 시작 조건, 관측/전달 경로, PC가 개입 가능한 범위, 차단/우회 시 대체되는 결과, 이후 남는 상태를 둔다. 순서 번호나 턴 수만으로 발동하지 않는다. 현행 첫 큰 사건 30턴 이내 기준과 연결하되 고정 장면 수·필수 희생·괴물 할당량은 만들지 않는다.

### C-1. 세계 생성의 산출물: 실제 진행을 준비한 시나리오 설계도

세계 생성 완료물은 설정집과 난수 결과표만이 아니라 **어떤 사건이 어떤 원인으로 이어져 플레이가 진행될지 준비한 대략적인 시나리오 설계도**여야 한다. 열린 세계/인과라는 이유로 첫 장면 이후의 발견·위기·대면·돌파·최종 국면을 전부 플레이 중 즉흥 작성으로 남겨두지 않는다.

고정 세계의 진실/법칙과 함께, 이를 플레이로 전달하는 **예상 주요 진행안 1개와 주요 분기/대체 접근**을 작성한다. 예상 진행안은 PC의 대사·선택·실패/감염/사망을 예약한 대본이 아니다. 현재 원인과 통상적인 접촉이 이어졌을 때 어떤 상황 변화로 어느 난관에 닿는지 구체적으로 보여주는 경로다. 우회·예방·다른 목표·협상·동료의 개입으로 달라질 부분과 이미 확정된 사실을 구분한다.

| 설계도 항목 | 반드시 준비할 내용 |
|---|---|
| 사건의 전체 구조 | 표면 사건·중심 원인·큰 위협·영향권·현재 사태·이번 사건의 해결/종료 범위 |
| 첫 진입/충돌 | PC가 무엇을 하던 중 어떤 실제 원인과 만나고 어떤 대응이 열리는가 |
| 주요 진행안 | 초반 이해/대응 → 접근/관여 확대 → 깊은 진실/강한 위협 → 결정적 개입/탈출 → 결과로 이어지는 구체적 인과 |
| 주요 국면별 경험 | 각 단계에서 원작 요소와 직접 만나는 상황, 새 정보/획득·손실·위험·관계/경로 변화 |
| 전환의 원인 | 이전 선택/발견/세계 행동이 왜 다음 상황을 여는지, 실제 시간/위치/조건·방지/취소 가능성 |
| 적과 세계의 병행 움직임 | PC와 별개로 누가 무엇을 하며 어느 조건에서 주 진행과 충돌하는지 |
| 큰 장면/난관 | 대면·추격·탐색·구조·전투·협상·환경 돌파 중 원작에 적격한 상황과 실제 지형/수단/제약 |
| 접근/분기/선제 해결 | 서로 다른 발견/진입 경로, 실패·지체·조기 발견·예방·철수·독창적 행동이 만드는 다른 결과 |
| 전조와 후속 활용 | 뒤의 위협/원리/해법을 공정하게 알 수 있는 앞선 흔적과, 준비/획득을 실제로 쓸 기회 |
| 절정과 여파 | 최종 위험의 현재 작동·큰 난관·유효 수단·성공/부분 성공/실패/탈출·남는 변화 |

각 큰 장면/전환은 기존 ID/ref에 `목적/역할, 발생/접근 조건, 현재 상황, 가능한 상호작용, 실제 위험/대응, 주요 결과, 다음 연결, 우회/차단 시 상태`를 연결한다. 예시는 인과 그래프 또는 연결표로 작성할 수 있으나 그래프의 화살표만 있고 실제 장소/인물/위험/조건이 비어 있으면 완료가 아니다. 의미 단위를 기존 scenario_progress_model·Driver·Route·Evidence·NPC 기록에 배치해 같은 사실을 여러 정본으로 중복 계산하지 않는다.

주요 진행안은 다음 반례까지 대조한다: 단서를 일찍 알아냄, 준비된 장소를 방문하지 않음, 판정 실패/지체, NPC/동료를 먼저 설득함, 핵심 위험을 예방함, 다른 출구/목표를 선택함. 순서가 달라져도 실제로 남은 인과로 이어지게 하고, 유효한 해결로 끝났으면 예정 장면을 강제 재현하지 않는다. 구체적인 진행 준비와 플레이어의 선택권을 함께 갖춘 상태를 생성 완료로 본다.

### D. 세계와 적의 선제 행동

PC가 조사 선언을 할 때만 움직이는 구조를 제거한다. 위협/기관/NPC가 목적과 실제 극중 경과에 따라 행동하고, 그 결과가 직업·숙소·교통·상거래·관계·탐색에 닿는 접점을 설계한다.

행동마다 목적, 실행 가능한 수단/위치, 조건·시간, 도달할 결과, 관측 가능 범위, 차단/취소 조건을 기존 Driver/NPC/Route에 연결한다. 예상 밖 사건은 이 독립적 움직임과 PC 선택이 만나는 데서 발생한다. 매 응답 돌발 사건을 난수로 생성하거나 성공한 안전을 무효화하지 않는다. 죽은 NPC·취소한 Driver를 재사용하지 않는다.

### D-1. 상황이 먼저 찾아오고 플레이어가 대응하는 진행

플레이어가 ‘사건을 조사할지’를 선택하거나 특정 NPC에게 말을 걸 때까지 중심 사건을 정지시키지 않는다. **사건은 세계의 인과로 발생하고, 플레이어는 도달한 상황에 어떻게 대응할지 선택한다.** 조사/의뢰 수락 메뉴를 사건 발생의 필수 스위치로 삼지 않는다. 일상 목적을 수행하는 동안에도 실제 인물·위협·시간·환경의 움직임이 접근·발견·관계·생존/돌파의 문제를 가져오게 한다.

세계 생성의 진행 설계도에는 초기 충돌 이후에도 사건의 움직임이 이어지는 접점을 준비한다. PC의 직업·이동·숙소·거래·관계와 중심 사건의 여러 원인이 실제로 만날 수 있어야 한다. 중요한 선택을 한 뒤에는 그 결과가 다음 상황의 조건으로 남고, 다른 행위자도 자신의 목표에 따라 행동한다. 주인공이 목표를 향해 움직일 때 세계의 진행과 맞물려 예상하지 못한 방향의 만남·변화·난관·기회가 생기는 구조다. 같은 적의 반복 공격이나 매 턴 무작위 이벤트 추첨으로 대신하지 않는다.

실제 응답 처리의 설계:

1. 현재 입력과 열린 절차를 처리하고 실제 행동/극중 경과에 도달한 결과를 정산한다.
2. 이번 상태·시간·위치에 연결된 적/기관/NPC/환경의 행동과 이미 발생한 여파 중 도달한 것을 실행한다. 모든 세계를 매 응답 다시 생성/검색하지 않고 확인된 관련 조건/ref를 재사용한다.
3. 실제 관측/전달/물리 영향이 PC에게 닿는 순간 장면으로 제시한다. 화면 밖 기록만 갱신하고 플레이어에게는 아무 상황 변화도 주지 않는 것으로 주요 진행을 대신하지 않는다.
4. 위험·새 정보·관계/접근 변화·선택할 기회처럼 지금 판단해야 할 상황에서 행동권을 반환한다. 이미 선언한 직접 결과는 충분히 처리하되 새 대응/동의/판정·자원 사용은 플레이어에게 남긴다.
5. 선택/예방/실패/우회가 바꾼 현재값과 다음 조건을 보존한다. 준비한 장면을 건너뛰어도 남은 세계 인과에서 이어가고, 종결됐다면 새 사건으로 억지 연장하지 않는다.

이 원칙의 속도감은 사건의 실제 움직임과 대응의 연속성에서 나온다. 환기·유머·치료·관계 교류도 진행 중인 사건의 인간적인 호흡으로 사용할 수 있다. 실제 확보한 안전을 무효화하거나 매 응답 공격·반전·큰 피해를 강제하지 않는다. 플레이어가 선택한 의미 있는 활동은 처리하면서 같은 극중 시간의 세계도 움직이게 한다.

일시 정지가 필요한 입력 경계는 존중한다. 메타 질문·주사위 입력 대기·인계/시각화 선택·현실 응답 지연 때문에 임의로 극중 시간을 늘리거나 다음 선택을 대신 실행하지 않는다. 극중에서 기다리거나 가만히 있는 행동을 실제 선언했다면 그 시간의 인과와 도달한 위험을 정산한다. 선택지를 주지 않겠다는 의미가 아니라, **선택할 가치가 있는 상황을 세계가 먼저 가져오는 것**이 구현 목표다.

### E. 중요한 장면 집중과 연속된 결과

장면을 선택할 때 발견·접근 변화·중대한 대면·실제 위험·돌파·의미 있는 인물 교류/선택을 우선한다. 종속된 이동·접수·반복 확인은 선언의 허용 범위에서 묶고 다음 의미 있는 판단에서 멈춘다. 필요한 세부 묘사는 이 주요 장면을 선명하게 만드는 데 사용한다.

위협의 종류뿐 아니라 플레이 방식도 달라져야 한다. 관찰·탐색·도주·협상·전투·구조·환경 활용 중 원작과 현재 인과에 맞는 경험을 준비한다. 억지로 모든 방식을 한 번씩 배치하지 않는다. 큰 위기 뒤 실제 안전과 중요한 대화·치료·재정비의 여유를 인정한다. 플레이어가 선택한 의미 있는 교류를 ‘잔씬’으로 삭제하지 않는다.

장면 종료마다 모든 규칙/정본을 다시 검토하지 않고, 실제 바뀐 위험·획득·지식·경로·목적·후속 조건만 기존 진행 상태에 반영한다. 다음 국면은 그 누적 결과에서 이어진다.

### F. 누적 피해·진행성 위험과 목적의 자연스러운 결합

실제 도달한 공격·물림·유해 노출은 담당 규칙의 판정/피해를 적용하고, 그 결과가 이후 행동과 사건에 남도록 설계한다. HP 감소와 부상은 묘사 뒤 사라지는 장식이 아니며, 진행성 위험이 있는 원작에서는 실제 극중 경과와 처치에 따라 변할 수 있다. 피해를 매 장면 할당하거나 이야기 진행을 위해 명중·물림·감염을 예약하지 않는다.

참고 영화의 유효한 연결은 `사투 중 물림 → 이후 악화 → 치료 관련 물건/인물과의 접촉 → 원래 배송과 개인 생존의 연결 → 결정적 해결을 향한 행동`이다. 게임에는 이 인과를 준비하되, 플레이어가 물리지 않거나 초기에 처치한 분기도 충분히 진행 가능해야 한다. 운반물의 정확한 역할은 치료에 필요한 물질로 표현하고, 모든 캠페인에서 배송물/치료제 반전을 반복하지 않는다.

진행성 위험을 사용하는 세계는 확정 전에 다음을 정한다.

- 실제 발생 조건과 판정: 무엇에 어떻게 노출돼야 하고 어떤 기존 규칙이 적용되는지. 모든 상처/물림을 자동 감염으로 취급하지 않는다.
- 진행 원리: 실제 극중 경과·행동·추가 노출·처치에 따라 무엇이 변하는지. 현실 대기시간·메시지 수로 임의 악화시키지 않는다.
- 관측과 이해: 외관·감각·기능 변화 중 플레이어가 알 수 있는 전조, 진단/증언/실험으로 알 수 있는 정보와 아직 비공개인 원인.
- 현재 영향: 실제 적용 중인 상태와 조건부 위험을 구분한다. 수치·피해·기능 영향이 필요하면 HP_AND_DEATH/HEALING/EXTREME_HAZARDS 및 해당 원작 법칙과 맞추고, 구현 단계에서 담당 본문/예외를 함께 검토한다. 본 계획으로 새 페널티·SAN 감소·감염 수치를 즉석 추가하지 않는다.
- 대응: 처치·억제·치료·격리·도주 등 원작과 세계에 맞는 접근 조건·한계·대가·차단 가능성. 치료의 존재만 적지 말고 플레이어가 알아내고 실제로 접근/사용할 경로를 준비한다.
- 사건 연결: 기존 물품·장소·세력·인물과 개인 위험이 만나는 근거. 사건을 경험해 알게 된 사실이 현재 목적과 선택을 바꾸도록 한다. 치료를 원한다는 PC의 감정/결심/약속을 대신 선언하지 않는다.

감염 외에도 해당 원작에 실제 존재하는 중독·저주·오염·추적 표식·기한부 신체 변화 등에 이 설계 원리를 적용할 수 있다. 모든 원작에 감염·저주·카운트다운을 추가하지 않는다. NPC 역시 실제 위해와 처치의 결과를 받으며 극적 역할 때문에 무적이 되지 않는다.

극적 긴장은 악화만 계속 누적하는 것으로 만들지 않는다. 처치·예방·안전 확보가 성공하면 실제 이점을 주고, 재발은 남아 있는 원인과 실제 조건이 있을 때만 발생한다. 마지막까지 유효한 대응 가능성을 검토하며 영화의 고정된 비극을 게임의 예정 결말로 쓰지 않는다. 기존 주요 위협을 조기에 막았거나 감염되지 않았다는 이유로 새 위험을 추가해 같은 결말로 되돌리지 않는다.

### G. 공포와 코미디·개성 있는 인물의 호흡

공포를 중심으로 하되 상황과 인물에서 자연스럽게 생기는 웃음·뜻밖의 인간미·기묘한 일상을 경험하게 한다. 사용자가 인상적으로 본 전반부 코미디와 환기 효과를 창작 방향으로 반영한다. ‘공포와 코미디가 가까울 수 있다’는 관점은 기대와 실제 반응의 차이·인물의 진지함·당황·타이밍을 활용하는 연출 원리로 다루며 모든 공포 장면에 농담을 붙이라는 지시로 만들지 않는다.

- 재미있는 NPC는 실제 목적·생활·능력·약점·말투·관계가 있는 인물로 만든다. 예를 들어 큰소리를 치지만 막상 겁은 많고 길눈은 밝은 인물의 허세와 실용성이 같은 상황에서 드러날 수 있다. 이 예시는 공통 필수 NPC가 아니며 기존 인물을 전부 같은 개그 인물로 바꾸지 않는다.
- 상황의 어긋남은 실제 인물과 사물의 인과에서 만든다. 허세와 행동의 차이, 엉뚱하지만 유용한 문제 해결, 익숙한 생활 습관이 낯선 상황에서 드러나는 순간 등을 활용한다. 설명형 펀치라인이나 별도 ‘개그 장면’을 의무적으로 생성하지 않는다.
- 웃음이 나도 NPC의 선택·협력·갈등과 실제 세계 반응이 이어지게 한다. 재미있는 인물과의 짧은 교류가 정보·신뢰·도움·애착을 만들 수 있지만, PC가 웃었다거나 좋아한다는 감정과 대사를 대필하지 않는다.
- 초반 일상/첫 접촉은 인물성과 상황 유머를 넣기 좋은 자리다. 중후반에도 실제 안전·재정비·여파에서 짧은 환기를 허용한다. 도달한 즉시 위험을 농담 때문에 멈추지 않으며 농담 횟수·전반/후반 비율·긴장감 배분 수치를 신설하지 않는다.
- 희생·사망·상처를 무해한 장난으로 되돌리거나 유능한 위협을 계속 바보로 만들어 공포를 중화하지 않는다. 인물의 피해를 조롱하는 유머를 기본값으로 삼지 않고 플레이어가 장면을 진지하게 받아들이면 그 호흡을 존중한다. 웃음 뒤 반드시 공격이나 희생을 붙여 환기를 처벌하지 않는다.
- 환기는 안전한 침묵·돌봄·동료의 능숙함·작은 성취로도 만들 수 있다. 코미디를 체력/SAN 자동 회복·생활 버프·선택을 넘기는 장치로 쓰지 않는다. 무의미한 잔씬을 늘리지 않되 의미 있는 교류는 충분히 경험하게 한다.

생성 시 개성 있는 인물과 자연스러운 상황의 가능성을 준비하고, 진행 시 실제 접점에 맞춰 짧고 살아 있는 대화/행동으로 구현한다. 대사 문구와 타이밍까지 모든 캠페인의 고정 패턴으로 저장하지 않는다. 실제 확립된 인물의 말투·관계·중요한 교류는 기존 NPC 연속성 기록으로 이어간다.

## 5. 세계 생성 내부 순서의 재조립

사용자의 시작 설정·원작 선택·전원 PC 생성 순서는 현행을 기준으로 유지한다. 아래는 **전원 PC 확정 후 세계를 만드는 내부 순서**의 제안이다.

1. 선택된 정확한 작품과 원작 세계의 작동 원리·핵심 체험·각색 경계를 확정한다.
2. 중심 사건의 원인·깊은 진실·최종 보스/최종 위험의 실체와 고유 작동·한계·개입하지 않았을 때의 결과와 해결/탈출 조건을 먼저 구성한다. B-1의 생성축과 명세를 초중반 접점·적의 행동·획득/준비에 연결한다.
3. 적·기관·NPC의 독립적 행동과 공간·경로·자원 제약을 연결한다.
4. 확정된 PC의 평범한 목적·직업·관계가 이 사건과 만나는 첫 충돌과 이후의 연속적인 상황 접점을 만든다. 사건 수락/조사 선택을 기다리지 않아도 실제 세계 행동이 닿을 경로를 준비한다. 미선언 과거·감정·충성을 추가하지 않는다.
5. 발견·획득·손실·세계 변화가 이어지는 주요 국면과 독립적인 접근/예방/우회 경로를 구성하고, C-1의 예상 주요 진행안과 큰 장면/전환 연결을 실제 인물·장소·조건으로 작성한다. 원작에 진행성 위해가 있으면 발생·진행·관측·대응과 중심 사건의 연결을 함께 준비하고, 실제 노출 결과만 적용한다. 개성 있는 인물·상황 유머·실제 안전의 환기 가능성도 주요 장면 사이에 연결한다.
6. 원작 체험별 실제 접촉과 행동 차이를 대조한다. 이름만 원작인 범용 조사/수리 사건이면 다시 설계한다.
7. 기존 생성축을 위 구조 안에서 해석한다. 원작과 맞지 않는 축은 담당 본문에 명시할 적격성/재해석 절차로 처리한다. 불리한 결과가 나왔다는 이유의 임의 재굴림과 혼동하지 않으며 난수 분포/표 변경은 별도 검토한다.
8. 아래 합성 사례와 생성 거부 조건으로 검토하고 비공개 정본을 확정한다. 부족한 부분은 확정 전에 고친다.

PRIVATE_CANON_DOCUMENT의 현행 필수 절을 중심으로 먼저 배치한다. WORLD_BASELINE은 원작다운 정상 세계와 영향 범위, HIDDEN_TRUTH는 중심 인과/깊이와 예상 주요 진행안의 근거, WORLD_RULES는 실제 체험할 원리, NPC/LOCATION/EVIDENCE/DRIVER_BASELINES는 접촉·행동·후속 연결, ENDING_CONDITIONS는 결정적 해결을 담당한다. 필요한 구조가 기존 절에 들어가지 않을 때만 새 절/규칙 ID를 검토하고 색인·참조·검증을 함께 바꾼다.

진행성 위해는 마지막으로 정산한 극중 시점·현재 단계/증상·다음 발동 조건·처치 효과/잔여 범위·처리 event를 기존 상태/시간/진행 기록과 결합한다. 아직 알려지지 않은 원인과 플레이어가 실제 관측한 증상을 구분한다. 로드 때문에 노출/물림·피해를 다시 적용하거나 진행을 초기화/완료하지 않는다. 치료 정보/수단을 알아낸 상태와 사용·효과가 발생한 상태도 구분한다.

저장/로드의 목표는 같은 장면 완료 목록을 재연하는 것이 아니라, **왜 다음 상황이 생기고 지금 무엇이 가능하며 무엇이 이미 바뀌었는지** 복원하는 것이다. 이미 실행된 사건·피해·난수·소모를 재실행하지 않는다. 취소한 위험을 되살리거나 과거 기준선으로 현재 상태를 덮지 않는다. 미발견 진실을 HUD/수첩/공개 지도에 노출하지 않는다.

현재 저장은 Supabase Checkpoint/DOCUMENT_BOUND 계약과 비공개 프로젝트 정본 결합 방식이다. 본 계획의 저장 개선은 그 상태에 필요한 의미 범위를 정하는 것이다. 향후 구현 전 실제 허용 schema/namespace가 새 의미 범위를 보존할 수 있는지 점검한다. 원격 연결이나 스키마가 없으면 검증 불가를 명시하고 동작을 만들어내지 않는다. 운영 변경이 필요해지면 구체 범위·영향을 별도 확인한다. 이전에 취소한 저장 수단은 이 계획으로 부활시키지 않는다.

레지던트 이블 계열의 생존/탐색 예시와 괴물 없는 정치/전쟁 계열 예시를 최소 한 쌍으로 검토한다. 동일한 합성 세계에 대해 PC 상태·자원·지식과 실제 선택을 바꾼 비교 사례도 수행한다. 달라져야 할 접근/결과와 유지돼야 할 원인/진실을 대조한다. A~G별 적용/미적용·우회·선제 해결을 함께 검토한다. 합성 데이터는 실제 사용자 캠페인에서 가져오지 않는다. 생성한 원작 특징을 각 접점/결과에 연결해 ‘존재’와 ‘실제 체험’을 구분한다. 플레이어가 우회·선제 차단하는 반례도 함께 대조한다.

## 9. 권장 구현 순서와 완료 조건

| 단계 | 수행 | 완료 조건 |
|---|---|---|
| P0 — 계획 | 이 문서 작성·기준/범위/자료 확정 | 본문·상태·예시·검증의 변경 위치와 미확정 사항 식별 |
| P1 — 생성/정본 설계 | A/B/B-1/B-2/C/C-1 및 F/G의 사전 조건·인물 설계와 내부 생성 순서, 원작 체험·중심 난관·정본 구조를 함께 수정 | 다른 성격의 합성 원작 사례가 통과하고 예시 재탕/빈약한 수리 사건이 거부되며 적용/미적용 조건과 실제 최종 위협/대응 명세·사건 규모·구체적인 주요 진행안/분기 설계도가 갖춰짐 |
| P2 — 실제 진행 | D/D-1/E/F/G와 담당 피해/치료·세계/진행 본문을 연결 | 첫 충돌 뒤 위협·발견·돌파가 실제 후속 상황을 만들고 우회/예방 반례도 정상 처리하고 실제 위해·처치·환기가 자연스럽게 이어지고 같은 세계의 상태/선택 변경 비교와 조사 수락 없이도 도달하는 연속 상황·입력 대기 정지 사례도 통과 |
| P3 — 상태/세이브 | 위 고정/동적 범위를 현행 소유 namespace/ref와 결합 | 같은 중간 지점 복원 시 위험/획득/질문/후속 조건이 이어지고 중복 적용 없음 |
| P4 — 지침/검증/배포 | PI/START·색인/카탈로그·계약/사례·README/DEVLOG·ZIP 정리 | 문서 검사와 관련 합성 검토 통과, 소스/ZIP 일치·재현성, main 반영 확인 |

P1~P3은 의존 관계 순서이며, 서로 상충하는 중간 룰북을 배포하지 않는다. 실행 패치를 시작할 때 해당 범위의 생성·진행·상태·검증을 일관된 묶음으로 완성한 뒤 배포한다. P0는 이후 구현 승인이나 실제 게임 동작 변경을 뜻하지 않는다.

## 10. 검증과 실제 플레이 평가

구현 시 기본 명령: `python3 scripts/rulebook.py check`, `python3 scripts/rulebook.py stats`, `python3 scripts/rulebook.py export`, `git diff --check`. ZIP은 CRC/manifest SHA-256/원본 바이트 일치와 동일 소스 재생성의 동일 바이트를 확인한다. 관련 기존 난수/규칙 검사는 변경 범위에 맞춰 유지한다.

자동 의미 계약에는 원작 요소의 접촉/선택/후속 연결, 국소 성공 유지, 실제 적 행동, 장면 압축의 주도권 경계, 고정 정본/동적 변화 보존·중복 event 금지를 연결한다. 검사 항목은 문자열 수집으로 품질을 주장하는 대신 위 합성 통과/거부 사례와 함께 검토한다.

실플레이에서는 실제로 경험한 원작 고유 상호작용, 사건/위협의 질적 변화, 준비/획득이 쓰인 돌파, 사소한 종속 절차의 왕복, 강제 선택/성공 무효화·상태 누락을 기록한다. 실제 위해가 이후 목표/선택에 영향을 주는지, 치료/예방이 유효한지, 인물/상황 유머가 자연스러운 환기를 주는지와 피해 희화화·반복 개그·PC 감정 대필 여부도 검토한다. 단순 전투/공격/반전 횟수는 성과 지표로 삼지 않는다. 응답 시간도 실제 로그가 있을 때만 보고하며 매 턴 전체 세계 검수/재생성으로 계획을 실행하지 않는다.

현재 미검증: 실플레이 재미/긴장/속도·장기 원작 체험·운영 저장 호환성. 본문 구현과 합성 검토만으로 실제 게임 경험이 검증됐다고 보고하지 않는다. 실제 캠페인 비공개 정본·세이브·인증은 공개 저장소/배포 ZIP에 포함하지 않는다.
