## HUD 맨 마지막 실제 판정 내역

아래는 전부 합성 표시 예시다. 실제 캠페인·Python 실행 기록이 아니다. 설명형 한 줄 대신 같은 판정의 요구·플레이어·실제 내부값·비교·결과·자원을 구분한다. 기존 HUD/필요 Context 뒤, 씬 연출 의도 바로 앞에 둔다.

### 고정 목표치와 보너스 자리수

이 예시는 **상대 굴림 없이 보통 목표치60으로 처리했다고 확인된 경우**다. 실제 판정 방식/기록이 없으면 이 조건을 추측하지 않는다.

🎲 **판정 내역**

- 요구: 고정 목표치 · 보통 ≤60(설득60).
- 플레이어: 기본99 / 추가98 · 보너스1 · 공통 1의 자리9 + 10의 자리9/9 → 후보99/99 → 최종99 · 실패.
- 내부/Python: 미실시(고정 목표치 판정).
- 비교: 최종99 > 요구60 · 보통 성공 미충족.
- 결과: 설득 실패 · 요청한 공개는 성립하지 않음.
- 자원: 행운 사용 안 함 · 소모0.

🎬 **씬 연출 의도** · 요청과 응답의 차이를 명료하게 보여주는 장면.

### 실제 공개 대항

🎲 **판정 내역**

- 요구: 일반 대항 · 양측 성공 단계 비교.
- 플레이어: PC A · 설득60 · 보통≤60/어려움≤30/극단≤12 · 원값32 → 최종32 · 보통 성공.
- 내부/Python: 상대 B · POW50 · 보통≤50/어려움≤25/극단≤10 · 실제 원값41 → 최종41 · 보통 성공.
- 비교: 보통 성공 동점 → 원래 수치60 > 50.
- 결과: PC A 승리 · 이번 설득 목적 달성.
- 자원: 행운 사용 안 함 · 소모0.

🎬 **씬 연출 의도** · 발언과 상대의 실제 반응을 이어 보여주는 장면.

여기서 승패는 32와41의 단순 대소가 아니라 담당 일반 대항의 성공 단계/동점 규칙이다. 근접 회피/반격은 별도 전투 규칙을 따른다. 전체 NPC 시트나 비밀 의도는 출력하지 않는다.

### 내부 수치 굴림과 기록 누락

피해라면 `내부/Python: 2d6+1 · 원값2/5 → 합계8`처럼 실제 식·각 주사위·합계를 표시한다. 이 값은 예시이며 게임에서는 실제 실행 결과가 있어야 한다. 플레이어 d100을 추가 생성하지 않는다.

굴림 전에는 `플레이어: 입력 대기`/`내부/Python: 실행 대기` 및 `결과: 미확정`을 쓴다. 실제 상대 굴림이 필요한데 기록이 없으면 `내부/Python: 확인 불가`이며 확인 전 승패를 확정하지 않는다. 기록이 없다는 이유로 미실시를 단정하거나 상대값을 새로 뽑지 않는다. 판정이 없으면 블록을 생략하고 과거 결과를 매 턴 반복하지 않는다.
