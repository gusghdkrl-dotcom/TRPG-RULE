# 통합판 검증 계약의 변경 근거

기존129개 의미계약을 현행154개 담당규칙에 맞게 재작성했다. 단순 문구 삭제로 통과시키는 방식 대신, 유지한 수치/예외와 승인한 새 의미를 각 담당 절의 contains/excludes 및 상시 instruction_contains로 명시한다. 현재 스크립트는 필수ID·최초403개원문/직전361개ID대응·카탈로그·은퇴ID라우팅·링크·문자수도 검사한다.

2026-11-09 인스트럭션 재구성에서는 기존 instruction_contains를 모두 보존하고 우선순위·생성 범위·진행/압축·조회 실패의 명시 조건을 추가했다. instruction_order는 지정한 절이 각각 한 번 존재하며 지정 순서로 배치되는지 검사한다. 파일별 라우팅 검사와 함께 개발 시 실행하며 매 게임 응답의 전수 검수 단계를 만드는 기능은 아니다. 새 회귀 사례는 내용이 남아 있어도 최우선 기준을 문서 맨 아래로 이동한 경우를 거부한다.

같은 날 UI 누락 지적에 따라 GUIDED_ACTION_RETURN의 실제 지원 버튼 우선/정직한 Markdown 대체와 BOTTOM_HUD_CONTRACT의 패널 위계·자원 아이콘·메인/파우치 별도 영역을 검사한다. ‘표/아이콘/문단 수의 고정 규격은 없다’는 완화 문구의 재유입을 거부하며 기존 상태·슬롯·물품 위치/수량 보존도 확인한다. 문서 검사로 실제 클라이언트의 버튼 클릭/카드 렌더링 성공을 확인했다고 주장하지 않는다.

검사 약화 회귀 방지: test_rulebook_contract.py는 임시복사에서 성장범위/상한·SAN누적/회복·질식단위·유불리00·인벤토리·후일담·장면맥락·상시스케일/NPC말투 훼손, 은퇴ID/수첩복원, 길이/중복/카탈로그/대응표 손실을 고의로 주입해 거부되는지 실행한다. 원본작업트리/서비스는 바꾸지 않는다.

이 검사는 문서 의미의 최소 요구를 보호한다. LLM이 문장을 실제로 준수하는지·생성한 이야기가 재미있는지·서비스가 저장을 수용하는지는 별도다. 구판오프라인검토를 실제플레이통과로 간주하지 않는다.
