# 외부 게임 저장 연동을 없앤 뒤의 대안

현재 운영은 전체 세이브 JSON(보관·새 방 첨부)과 최신 비공개 MD(프로젝트 소스 교체)를 같은 저장에서 제공한다. 비공개 변화는 임시 Python 작업 파일에만 기록하며 외부 쓰기를 재도입하지 않는다. 상세는 [STATE_PRIVATE_WORK](../rules/07-state.md#state_private_work)를 따른다.

조사일: 2026-11-07(한국 시간). 공식 문서의 지원 설명과 이 저장소의 실제 검증을 구분한다. 사용자 계정의 화면/파일 보관을 직접 시험한 결과가 아니다.

## 권장: FILE_SAVE_V1 + ChatGPT Library의 실제 보관 파일

파일 형식은 그대로 두고 보관·재첨부 수고를 줄이는 방법이다. OpenAI의 [Library 안내](https://help.openai.com/en/articles/20001052-using-library-to-manage-files-in-chatgpt)는 업로드/생성 파일의 보관과 새 채팅의 `Add from library` 선택을 설명한다. 해당 계정/UI에서 파일이 실제 보이면 새 채팅에 선택해 제공하고, 키퍼가 전체 파일을 읽어 동일 해시/상태 검증을 수행한다. 파일 생성 링크만으로 Library 등록이나 다른 채팅의 접근 성공을 단정하지 않는다. 중요 저장본은 기기에도 내려받아 둔다.

계정에 따라 Library 대신 [Space](https://help.openai.com/en/articles/20001549-getting-started-with-space-in-chatgpt)가 표시될 수 있다. 공식 안내상 Space는 페이지/파일을 관리하며 Projects와 별개다. 지원 플랜·화면·권한이 다르므로 사용자 화면에 실제 있는 파일 제공 방법을 따른다. Space 페이지를 작성했다는 사실만으로 JSON 전체 원문·해시·현재 상태가 무손실 보존됐다고 보장할 수 없다.

이 조합은 외부 DB/저장소 커넥터를 사용하지 않는다. 그러나 ChatGPT 자체의 파일 생성/접근 실패·보관 한도·보존 정책·도구 차단까지 없어진다고 보장하는 설계는 아니다. 전용 자동 저장 버튼·상주 서버·Library 조작 API를 룰북이 만들어 내지는 않는다.

## 비교

| 방법 | 가능한 흐름 | 한계/판단 |
|---|---|---|
| Library의 보관 파일 | 생성한 세이브를 실제 보관 목록에서 새 채팅에 선택 | 가장 적합. 동일 파일 완전성 검증은 계속 필요하며 계정에서 실제 지원 확인 |
| 직접 다운로드·재첨부 | 기기에 파일 보관 후 새 채팅에 첨부 | 계정 보관 UI가 없어도 사용할 수 있는 기본 전달 방법; 수동 보관 필요 |
| 프로젝트 소스로 응답/텍스트 저장 | 응답 메뉴에서 소스에 추가하거나 전체 텍스트 직접 등록 | 긴 본문 잘림·선별 검색·비공개 원문 노출 위험; 요약을 정상 세이브로 오인하면 안 됨 |
| Space의 편집 문서 | 계정이 지원하면 페이지에 현재 기록을 관리 | 편집 편의는 있으나 정확한 원문/버전·완전성 검증은 별도; 이번 패치로 자동 연동하지 않음 |
| 다른 연결 앱 | 지원되는 앱에서 파일/문서 생성·조회 | 권한·승인·지원 범위 문제가 다시 생길 수 있어 이번 목표의 기본 해법으로 채택하지 않음 |

[Projects 공식 안내](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)는 응답 메뉴의 `Add to project sources`와 파일/텍스트 등록을 설명한다. 이는 사용자가 실제 제공한 내용을 다음 채팅의 자료로 삼는 기능이다. 모델의 숨은 작업 상태 자동 저장이나 모든 세부 정보의 정확한 복원을 보장하는 게임 세이브 API는 아니다. 비공개 전체 텍스트 노출을 선택한 경우에만 복사형 복구 자료를 제공한다.

[Connected apps 공식 안내](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt)는 앱별 기능·계정/플랜/지역/권한 차이와 읽기/작업 전 승인이 필요할 수 있음을 설명한다. 따라서 다른 서비스 이름으로 바꾸면 안전 검사 문제가 반드시 해결된다고 말할 근거는 없다. 실제 최근 세션의 차단 문구는 확보하지 못해 원인 자체는 미확정이다.

## 이번 변경과 검증 경계

현행 실행 소스에서 외부 저장/로드/백업/동기화 절차와 엔드포인트를 제거했다. 룰북 개발용 GitHub 저장소·ZIP 배포는 유지한다. 운영 데이터/권한/스키마·다른 앱은 변경하지 않는다. 기존 파일의 원문/해시/분기, NPC 목소리/관계, 상태 효과, 이미 해결한 판정과 열린 대기는 그대로 보존한다.

문서 검사와 로컬 합성 파일 왕복/손상 검증은 Library 보관·Space 편집·프로젝트 소스 재사용·실제 ChatGPT 플레이 검증이 아니다. 사용 가능한 실제 UI/전체 파일을 확인하기 전에는 해당 경로 성공을 주장하지 않는다.
