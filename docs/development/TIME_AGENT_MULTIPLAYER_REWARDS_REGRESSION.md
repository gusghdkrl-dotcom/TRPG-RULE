## 실행 경로

1. 가상 신규 계정 2인 또는 3인, 실제 카드 캠페인 등록·합성 훈련 자격 부여. 현지 비공개 테스트 정본과 두 챕터의 `trpg_v2_commit`/`verify`를 생성하여 원래 `confirm_segment_terminal` → `return_segment` → `evaluate_segment` 처리.
2. `approve_chronicle_completion`으로 각 요원 **첫 정식 인증 1회 + 연대기별 훈장 1개 및 특별 선택권 1개**를 독립 지급.
3. **요원별 가상 선택**: 1번은 A(미보유 중립 카드 `NE-A-4` 직접 선택), 2번은 B(`POW` Lv.0 → 1 확정), 3인에서는 3번도 A(동일 `NE-A-4` 선택, 단 **다른 UUID의 개별 소유**). 같은 플레이어에게 카드 2개를 주거나, 다른 요원의 보유카드 원장을 수정하지 않음.
4. **각자 별도 일반 `chapter:02` 보상**을 마틴이 승인한 후 `trpg_cards.draft_pool`의 현재 적격 후보에서 4개 슬롯을 구성. 도미닉 `offer_general_reward` → `resolve_general_reward`을 원래 카드 DB와 함께 실행. 1번: 현재 클래스 카드 1장, 2번: 신규 성장 `STR` 확정 Lv.1, 3번: 중립 카드 1장. 특별 B의 `POW`와 일반 성장 `STR`는 **서로 다른 종류**로 저장.
5. 일반 드래프트 발행·해결과 특별 선택을 각각 동일 요청으로 재시도해 `applied:false` 및 중복 소유·중복 성장 없음 확인. `hq_reward_grants` ↔ `trpg_cards.drafts` 일치, `load_team_rewards` 및 `load_chronicle_honors` 불일치 0건.
6. 팀별 **개인 보상 사건 4종**(`reward_approved`, `reward_offered`, `reward_resolved`, `chronicle_special_resolved`)의 `audience` 배열은 자기 요원 UUID **딱 1개**에만 대응. 보상 RPC가 클라라 등 `hq_npc_agent_relations`나 개별 `hq_clara_releases`를 근거 없이 생성하지 않음.
7. 각자의 수령이 모두 완료된 뒤 같은 팀으로 새로운 별도 연대기 합성 미션을 생성해 **verified 최종 실패**. 새 완주 훈장/특별 보상 생성은 0건, 앞선 특별 A/B·기존 일반 수령 `resolved` 원장 및 첫 정식 인증은 그대로 유지.
8. 모든 테스트 변경은 성공 후 **서브트랜잭션 롤백**. 운영·개발의 실제 기존 요원 소유/성장·이전 캠페인을 건드리지 않음.

## 추첨·게임 주도권 경계

- 이번 SQL은 4개 후보를 **실제 적격 `draft_pool`에서 고정된 순서로 뽑는 검증용 값**으로 구성했다. 후보 선택과 사용자의 선택(1/3/4 슬롯)은 합성 입력이며, **원래 하우스룰의 Python SystemRandom 희귀도 가중 추첨을 구현·증명한 테스트가 아니다**. 실제 게임 키퍼는 규칙 `09-cards`의 후보 구성/희귀도 및 실제 플레이어가 정한 선택을 따라야 한다.
- 특별 A/B 또한 원래 개발 도구의 임의 테스트 입력이다. 실제 플레이어의 의사에 따른 선택이 아니며, 키퍼가 임의로 특별 보상을 확정하면 안 된다.
- 후속 실패는 합성 verified 종료이며 실제 HP·사망 직전 특성/전설 카드의 우선순위까지 검증한 것이 아니다.
- 실제 개별 NPC 감정·관계는 요원이 실제 듣고 말한 사건에 근거할 때만 `record_npc_interaction`으로 변화한다. 보상 원장 일치가 NPC의 친밀함/신뢰 자동 상승을 뜻하지 않는다.

## 추가 확인 — 열린 드래프트 카드의 별도 획득 충돌

원래 카드 DB만을 사용한 별도 롤백형 검사에서, 네 슬롯의 일반 드래프트를 `offered`한 뒤 **첫 후보 카드가 별도 경로로 이미 소유**된 상태를 가정했다. 그 슬롯을 수령하려는 호출은 `card_already_owned_before_selection`으로 거부되고 원래 드래프트는 계속 `offered`. **다른 유효 슬롯을 선택하면 정상 지급되고 원래 별도 카드도 1장만 소유**한다. 자동 재추첨·원래 보상 삭제 없음.

이는 `trpg_cards` **기본 카드 엔진에 대한 시험**이며 `trpg_hq.resolve_chronicle_special`를 이용해 실제 열린 일반 드래프트 도중 특별 보상을 요청한 통합 순서 시험과는 다르다. 실사용 UI에서는 이미 소유한 슬롯을 선택할 수 없다는 사실을 최신 소유 원장으로 다시 표시할 필요가 있다. 확정되지 않은 자동 재추첨·보상 대체 정책을 발명하지 않는다.
