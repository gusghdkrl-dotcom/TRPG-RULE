# 시간요원 프레임워크 — 장기 개발 설계 초안

> 상태: **개발 논의 중 / 게임 미적용**  
> 버전: **DRAFT v0.3 (2026-11-12)**  
> 적용 범위: 향후 신규 게임에서 선택적으로 적용할 수 있는 영구 요원 메타서사 및 본부 시스템 구상  
> 참조 규칙: `rules/00-index.md`, `04-setup.md`, `06-play.md`, `07-state.md`, `09-cards.md`의 **이식 시점 GitHub 최신본**  
> **중요:** 이 문서는 현행 실행 규칙·시작 프롬프트·정본·DB 스키마·배포 ZIP을 변경하지 않는다. 합의된 설계라도 별도 이식 승인 전에는 게임에 적용하지 않는다.

## 0. 설계의 목적과 비범위

기존의 '원작/세계 선택 → 현지 PC 생성 → 생존 공포 플레이 → 엔딩'에, 여러 임무를 관통하는 **영구 요원 정체성·본부 관계·개별 작전 기록·상관 평가**를 부여한다. 원작 안에서 살아가는 현지 인물과, 세계를 넘어 경험을 축적하는 플레이어의 장기 서사를 분리하되 연결한다.

- 참고하는 것은 보드게임 《T.I.M.E Stories》의 **요원·기관·브리핑이라는 도입 프레임의 아이디어**이며, 해당 게임의 시간 반복·턴·행동 포인트·사건/게임 시스템을 이식하지 않는다. 본 프로젝트만의 기관·동기화/세계 법칙·평가를 추후 설계한다.
- 주력 장르는 여전히 **원작 체험형 생존 공포 TRPG**다. 현지 세계의 삶·관계·실재 위험·선택·피해 완화·실제 성과가 본부의 점수에 종속되어 무효화되지 않는다.
- **이 문서의 '확정'은 사용자와의 설계 합의를 뜻하며 실행 규칙 적용을 뜻하지 않는다.** '논의 중'과 '제안'을 사실처럼 승격하지 않는다.

## 1. 확정된 세계관

### 1.1 본부의 정체성 [확정]
- 본부는 **여러 세계를 보호하고 탐구하는 조직**이다.
- 본부는 요원을 다양한 세계에 투입하며, 실제 사건이 일어났을 때 어떤 상황에도 대비할 수 있도록 훈련한다.
- 상관의 브리핑·작전 기록·실적에 따른 대우 변화는 장기 플레이어 서사의 핵심 방향이다.
- **본부의 내부 갈등·숨겨진 역사·비밀**도 장기 요소로 다룰 예정이나, **내용·인물·반전은 전부 추후 아이디어 회의로 보류**한다. 본부가 악의적이라는 결론, 배신이나 특정 반전을 미리 확정하지 않는다.

### 1.2 평행세계와 '훈련 시나리오' [확정]
- 세계들은 **과거·미래를 포함하는 실제 평행세계**다. 원래 요원의 세계에서는 실존하지 않는 영화·게임·이야기 형태의 '시나리오 세계'도 **독립적으로 실재하는 평행세계**다.
- **본부가 세계를 만들어 낸 가상 시뮬레이션이 아니다.** '훈련 시나리오'는 본부의 작전/교육 목적을 가리키는 명칭이다.
- 우리가 주로 플레이할 세계는 이런 **실제로 존재하는 훈련 대상 시나리오 세계**다. 본부의 장기 목적은 실제 재앙 대응 역량의 축적과 세계 보호·탐구다.
- 개입한 세계의 사망·생존·재난·피해·구조·관계·물적 변화·인과와 여파는 **실제로 발생하고 계속 남는다**. 임무 종료/요원 귀환을 이유로 되감거나 지우지 않는다.
- 요원이 떠난 뒤에도 해당 세계와 그곳 주민들은 **자기 역사를 지속**한다. 이후 재방문 여부·규칙은 별도 결정한다.

## 2. 영구 요원과 현지 인물

### 2.1 이중 정체성 [확정]
- **요원:** 세계를 넘어 지속되는 플레이어의 영구 정체성, 훈련·평가·영구 소유/성장의 주체.
- **현지 인물(PC):** 해당 세계에 본래 존재하며 이름·삶·기억·신체·직업·인간관계·능력을 가진 독립 인물.
- 요원은 현지 인물과 **완전히 동기화**된다. 현지 인물의 배경·기억·능력·관계를 가진 상태로 그 인물의 삶을 체험한다.
- 임무 중에는 **요원의 임무 목적성과 의지가 유지**된다. 현지 인물의 행동·발언·판단은 해당 PC를 맡은 **플레이어가 결정**한다. 키퍼가 요원의 결심·대사·감정·동의를 대필하지 않는다.

### 2.2 귀환 이후 [확정]
- 임무가 끝나면 요원은 본부로 돌아가며 동기화가 해제된다.
- 현지 인물은 **임무 동안 자신이 겪은 사건과 행동에 관한 기억**을 가진 채 자신의 삶을 계속 살아간다. 본부 요원의 별도 임무·경력·타 세계 경험을 현지 인물의 기억으로 자동 이식하지 않는다.
- 그 인물과 주변 사람들이 실제 경험한 변화와 관계가 계속 작동해야 한다.
- **현지 인물의 동기화 이후 삶은 엔딩 후일담에서 반드시 다룬다.** 이는 실제 확정된 생존·부상·관계·세계 상태와 양립해야 하며, 플레이어가 선언하지 않은 장기적 감정·결심을 임무 중 PC에게 소급 부여하지 않는다.
- 동기화 중 현지인이 요원의 존재를 인식하는지, 본부 정보 유출/기억 경계가 세부적으로 어떻게 작동하는지는 **추후 정밀화**한다. 확정된 '사건 기억 계승'을 부정해서는 안 된다.

## 3. 요원 활성화 ON/OFF [합의된 이식 방향, 미구현]

- 신규 시작 첫 설정의 현행 표시 **'영구 카드·성장 시스템 ON/OFF'를 '요원 활성화 ON/OFF'로 변경**할 계획이다.
- **ON:** 본부·영구 요원 프로필·임무 브리핑/평가·요원 이력에 더해 **현재 영구 카드/성장 시스템 전체**를 사용한다.
- **OFF:** 본부·시간요원 프레임도 사용하지 않고, 영구 카드/성장 전체도 건너뛴 **기존 일반 TRPG 흐름**을 유지한다.
- 현행 내부 설정값 `permanent_cards_enabled`·`permanent_growth_enabled`/Supabase UUID·보유 카드/성장은 **이 단계에서 변경하지 않는다**. 향후 이식 때 명칭·옵션의 실제 매핑/기존 캠페인 호환성을 설계한다.
- 기존 소유 기록은 OFF로 지우지 않으며, 기존 캠페인/검증 저장/확정 사실은 소급 수정하지 않는다.

## 4. 임무 프레임 [방향 합의, 세부 미정]

- 세계 생성 초반부터 요원이 신입 또는 경력 요원으로 **본부 상관과 대화하고 임무 브리핑**을 받게 한다. 세계 선택이 단순 설정 메뉴가 아니라 작전 준비가 되는 방향이다.
- **팀 공동 목표:** 사건의 진실을 최대한 파악하고 재앙을 막거나 피해·확산을 억제하는 것. 단, 현행 세계 생성 규칙상 주요 재난·습격의 **발생 자체는 필연적**이므로, 실제 대응은 발생 이후 구조·피해 완화·후속 차단·생존·철수·국지적 해결에 중점을 둔다.
- **요원별 공개 개인 임무:** 각 요원에게 서로 다른 목표가 주어질 수 있다. 모든 플레이어에게 공개되고, 각 인물의 구체적인 상황·접근/수단/선택을 고려해야 한다.
- 개인 임무가 현지 PC의 행동·약속·희생을 강제하지 않는다. 공동 임무/개인 임무가 충돌할 때의 구체적인 평가 로직과 임무 유형은 미정이다.
- 임무 도중 실제 세계에서 일어난 사람·장소·상황·성과를 중심으로 플레이하고, 진상 입증만으로 모든 진행을 환원하지 않는다.
- 신입/경력에 따라 본부 인물의 반응이 달라지는 흐름을 목표로 하지만, 임무 입장에 반복적인 서류·대기·확인 단계를 늘리지 않는다.

## 5. 사망·재투입·전멸 [본부 배정·사전 적격 후보·리타이어·현재 세계 계승 확정, 기술 예외 미정]

### 확정된 설계 방향
- 현지 PC의 **사망은 실제 사망**이다. 임무 실패/재투입이 현지 생명·손실·세계의 피해를 되감거나 부활시키지 않는다.
- 최초의 '파티 공용 1회' 안은 폐기하고 **요원 각자 재투입 기회 1회**로 변경한다.
- 재투입은 그 세계에 **이미 실제로 존재하는 NPC**를 대상으로 한다. 재투입을 위해 새 NPC나 새 출구를 사후 생성하지 않는다. **후보 명단과 NPC별 배경·목적·능력·관계·초기 위치·독립 동선·적격 정보를 게임 시작 전 비공개 정본에 확정**한다.
- 새로 동기화하는 인물은 **그 NPC 본래의 자아·기억·삶·관계·능력의 연속성**을 보존한다. 재투입이라고 해서 빈 몸이나 복제 신체가 되지 않는다. 동기화 상태의 행동 주도권은 플레이어에게 있다.
- 사망/재투입에 따른 개인 요원의 성적 불이익을 둔다는 원래 방향은 유지한다. 다만 **희생의 공적은 개인 공적 점수로 별도 가산하는 대신 팀 전체의 기여/평가에 반영**한다.
- 전원 사망하고 추가 가능한 재투입도 없으면 **전체 임무 실패**, 팀 임무 평가 하락 및 **해당 임무 보상 미지급** 방향이다. 이미 현지에서 확보한 구조·국지적 성공·완화 결과는 지우지 않는다.

### 사망 이후 본부 연결·재투입·다인 교대 절차 [확정]
1. **현지 인물 사망의 실제 처리와 사망 장면을 먼저 완료**한다. 이 단계의 죽음·피해·NPC 반응·위치/물건·세계 결과는 확정되어 계속 남는다. 사망 뒤 재투입으로 해당 사망을 취소하지 않는다.
2. 사망 장면이 끝나면 **해당 요원의 의식이 본부와 연결**된다. 요원은 본부와 대화하고 사망 후 재투입 절차를 진행한다. 이것은 합의된 '의식 연결'이며, 요원 육체의 물리적 귀환 방법까지 자동 확정한 것은 아니다.
3. **본부가 현재 동기화 가능한 기존 현지 NPC 리스트 가운데 재투입 대상을 선정**한다. 이는 본부의 배정이며 **플레이어가 후보 목록에서 고르는 방식이 아니다**.
4. 본부는 요원에게 **어느 NPC로 재투입되는지 통보하고, 선정된 NPC에 대한 정보**를 제공한다. 정보는 본부가 실제 확보/제공할 수 있는 범위여야 하며, 아직 발견되지 않은 세계의 모든 비밀이나 모든 NPC 정보를 자동으로 폭로하지 않는다.
5. **재투입 절차가 완료되어도 신규 NPC에게 즉시 행동권을 주지 않는다.** 먼저 **대기하고 있던 다른 플레이어의 턴을 마저 진행하여 끝낸 뒤**, 그다음 **재투입된 NPC를 맡은 요원의 턴**을 시작한다.
6. 재투입된 NPC는 이전부터 실제로 그 세계에 있던 **본래 위치·신체·자아·기억·관계·상태·소지품과 진행 중 사건**을 이어받는다. 구체적인 시점/연결 가능 범위·상태 인계·기억 경계 등 예외는 아래 미정 항목에서 결정한다. 재투입이 사망 장소로 순간 이동하거나 같은 물건을 자동 지급하는 근거는 아니다.
7. 이 절차는 **플레이어 행동권의 순서**에 관한 합의다. 본부와의 대화/입력 대기만으로 현지 극중 시간을 임의로 진행시키거나 전투·적·환경·병렬 행동의 이미 확정된 결과를 건너뛰지 않는다. 기존 담당 전투/다인 규칙과 어떻게 맞물리는지는 이식 전에 검토한다.

### 재투입 후보의 적격성·비공개 정본·리타이어 [확정]
- 적격 인물은 **시나리오 시작부터 해당 세계에 존재**하고, 재난에 휘말린 **비적대적 인물**로서 배신을 목적으로 참여하거나 기존에 숨겨 둔 배신 이유가 없어야 한다. 이는 무조건 순종·복종한다는 뜻은 아니다. 인물의 책임·기존 관계·성격·거절과 실제 이견은 유지한다.
- **재투입 후보 리스트와 후보별 인적 사항·능력/기억·관계·원래 소지품/위치·행동 목적/동선·현재 상황을 판별할 근거**를 해당 캠페인의 **비공개 정본에 사전 배치**한다. 실제 NPC를 재투입 용도로 빈 인형처럼 취급하지 않는다.
- 현지 NPC는 원래 목적과 실제로 흐른 시간, 재난/타인의 행동에 따라 독립적으로 움직인다. 재투입 시에는 **그 시각에 실제로 하던 일을 이어받아**, 그때의 **위치, 진행 중 행동/목표, HP·SAN·부상·위험, 고유 능력과 기억, 소지품, 인간관계**를 보존한다. 기존 PC의 소지품/무기는 재투입 NPC에게 자동 이전하지 않는다.
- **파티와의 합류 여부·방법·시점은 플레이어가 판단하고 선언한다.** 사망한 기존 PC 근처로 NPC를 순간 이동시키거나 자동 합류/연락을 실행하지 않는다.
- 사전 후보도 죽거나 연락 불능·동기화 불가 상태가 될 수 있으며 **후보라는 이유로 사망 보호를 받지 않는다.** 플레이어의 실제 구조/보호/방치는 후보 생존에 영향을 준다. 시도가 실패했거나 접근할 수 없었던 죽음도 실제 인과로 처리하며 구조를 의무 선택지로 강제하지 않는다.
- **요원별 재투입 기회가 남았더라도 현재 적격·생존 후보가 0명이면 해당 요원은 이 임무에서 리타이어한다.** 즉석 신규 NPC 생성·사망 후보 부활·편의상 보장된 기회를 만들지 않는다. 재투입 1회 소진 시에도 후보 생존과 무관하게 추가 재투입 없이 리타이어한다.
- 사망 장면 완료 → 본부 의식 연결 → 본부의 적격 NPC 선정/통보 및 그 NPC 정보 제공 → 진행 중인 대기 플레이어의 턴 마무리 → 새 NPC의 실제 현장/상태에서 재투입 요원 턴 시작이라는 위 순서를 지킨다.

## 6. 본부의 영구 콘텐츠 [성격·시설·핵심 NPC 구성·팀 동행 확정]

- **상관 및 주요 본부 NPC:** 최초 신입에게는 안내·교육·훈련을, 경력자에게는 이전 임무 기록과 성적에 따른 신뢰·비판·다른 대우를 보여준다. 상관은 단순 점수 안내자가 아니라 자기 가치관과 관계를 가진 살아 있는 인물이어야 한다.
- **본부 공간:** 브리핑·동기화·기록 열람·교류와 영구 성장 체험을 위한 실재 생활/업무 공간. **초기 시설 5개 구역과 핵심 NPC 8명 구성을 확정**한다. 본부 전체 인원/위치/건축·세계사·세부 동선은 추후 설계한다.
- **영구 요원 기록:** 이전 임무, 진실 접근 정도, 구조·생존·재투입·실패, 인상적인 행동, 평가, 칭호·계급 및 상관과의 관계 등 의미 있는 이력을 누적한다. 실제 플레이에서 성립하지 않은 업적이나 심리 성향을 판정으로 꾸미지 않는다.
- **귀환 및 평가:** 사건의 현지 결말과 후일담을 보존하고, 본부에서는 상관이 임무 보고서·공적·실패·희생·구체적 인상 장면을 언급하는 평가를 제공한다. 팀 평가·개인 평가·등급·특별 칭호의 정확한 수치/조건은 미정이다.
- **계급·칭호:** 후보 기능. 실제 대우/대사/역할과 연결하되 기존 카드·성장과 중복되는 능력 보너스 도입 여부는 별도 심의한다.


### 6.1 본부의 지향점과 팀 전원 동행 [확정]

- 본부 핵심 NPC 역시 플레이어 부재 시 근무·교류·자신의 임무/생활·관계 변화를 겪는다. 변화는 실제 경과와 인과로 성립하며 매 방문마다 강제 사건이나 승진을 만들지 않는다.

## 13. 최초 플레이·기존 게임 접속/진입의 실제 절차 [첫 체험 순서 확정, 기술 구조 제안]

### 13.1 신입의 첫 본부 체험 [확정]
- **판별 기준:** 사용자 표현은 "**클리어 기록이 없는 첫 플레이 인물**". 클리어 기록이 없는 첫 요원은 본부에서 **입단식 → 상관 면담·임무 브리핑 → 주요 시설 둘러보기 → 시설 인물들과 직접 대화 → 트레이닝에 대한 설명 → 실제 평행세계로 투입**되는 체험을 제공한다.
- 이때 **플레이어들은 본부 내에서 항상 팀원들과 함께 다닌다**. 개별 발언·질문·반응은 각 플레이어의 주도권을 지킨다. 시설의 인물/교류를 단순 안내 텍스트나 자동 완료 목록으로 치환하지 않는다.
- 마틴이 입단/면담/작전 브리핑, 제이든이 동기화, 클라라가 분석, 도미닉이 카드·영구 성장·훈련 내용을 담당하는 역할은 확정. 다른 시간요원들과도 실제 관계/상호작용이 가능해야 한다.
- 클리어 횟수/경험 여부를 단지 카드 개수, 카드 계정 생성일, 높은 성장 레벨만으로 추정하지 않는다.
- **아직 확정하지 않은 것:** 실패 경험은 있으나 클리어 0회인 요원의 재입단식 여부, 신입/경력 혼합 파티의 구체 순서, 실제 입단식 대사·선서/동의 단계·소개 분량, 첫 본부 방문의 세부 이동과 건축.

### 13.2 현행 게임과 연결할 기술적 접점 [검토/제안, 아직 최종 승인 아님]
기존 시작 절차는 대략 첫 설정 ON/OFF·인원·닉네임 확정 → 카드 UUID 확인/클래스·장착 → 세계/현지 PC/비공개 정본 생성 → 현지 플레이 → 종료·보상이다. **본부로 들어가는 것과 실제 현지 PC를 만드는 순서를 이식 때 명시적으로 다시 배치**해야 한다.
- 기존 첫 화면의 '요원 활성화 ON/OFF' 변경 방향은 확정(§3); **닉네임→기존 영구 UUID를 재사용**해 요원 이력과 연결하는 방안은 기술적 추천이다. 별도 계정 강제 생성은 하지 않는 방향이 합리적이지만 신규 DB 계약/요원 키의 최종 구조는 미정.
- **권장 진입 흐름:** 초기 설정 → UUID/요원 이력 조회 → 본부 입단/귀환 장면 → 세계 선택·브리핑/시설 교류·도미닉 카드 장착/성장 설명 → 현지 PC와 세계 정본 확정 → 동기화 → 기존 생존 공포 게임 실행 → 현지 후일담·본부 귀환/평가/보상 → 본부 장기 상태. **이 배치 자체는 기술적 설계 제안**이고, 실제 기존 04-setup/06-play/07-state/09-cards의 조건에 맞춘 확정 순서·저장 경계는 구현 전에 검증한다.
- **권장 데이터 분리:** (A) 영구 요원/현재 카드 UUID·소유·성장·경력, (B) 본부 NPC/시설/관계/팀 공동 경험/입단·클리어 이력, (C) 개별 캠페인의 현지 PC/세계/정본/검증 저장, 그리고 영구 요원과 캠페인/동기화된 현지 인물을 연결하는 임무 ID. 이것들은 현재 새 테이블이 존재한다는 주장이 아닌 **저장 설계 후보**다.
- 신규 상태 단계 예시: `CONFIG → AGENT_LOOKUP → HQ_ADMISSION 또는 HQ_RETURN → HQ_BRIEFING → HQ_TOUR → HQ_SOCIAL → HQ_TRAINING → WORLD_SETUP → DEPLOY_READY → WORLD_PLAY → WORLD_TERMINAL → HQ_DEBRIEF → HQ_FREE_PLAY`. **내부 상태 후보**일 뿐 강제 장면 수/실제 적용 enum 확정이 아니다.
- **핵심 이식 검증 대상:** 본부 방문 중 아직 세계 정본/PC 미생성 상태의 저장·새 채팅 복원, 세계별·본부별 시간 분리, 카드 장착·영구 성장의 정확한 1회 적용, 이미 완료한 입단/출격/보상 이벤트 중복 방지, 기존 계정/캠페인/세이브 보존.
- **규칙 충돌 후보:** 현재 사망·종결 카드 보상 자격과 이번 시간요원 모드의 전원 리타이어 시 임무 실패/보상 없음 방향 간의 정확한 연결 및 호환. 보상 지급 코드와 현재 09-cards/06-play의 실제 원문을 확인한 뒤 명시적으로 확정.
- 지금은 실제 `rules/*`, `START_GAME.md`, `PROJECT_INSTRUCTIONS.md`, `dist/*`, Supabase 스키마·데이터, 기존 저장을 건드리지 않는다.

## 14. 합의와 GitHub 업데이트의 실행 경계
- **일상 회의에서 GitHub를 매번 자동 수정하지 않는다.** 설계는 대화에서 확정/제안/미정을 구분해 정리하고, **사용자가 명시적으로 "GitHub 업데이트"를 요청할 때만** 그때까지 확정한 내용을 개발 문서에 누적 반영한다.
- GitHub의 이 초안은 실행 정본/현지 비공개 정본이 아니며 **개발 준비 자료**다. 실제 게임 이식은 설계 논의 완료 후 **별도의 명시적 사용자 승인**과 최신 정본 검토/검증을 필요로 한다.
