# 시간요원 본부 실제 START_GAME 통합 — 12차 DEV (2026-11-12)

## 목적 및 사용자 명시 정정

**기존 게임을 보존한다는 말은 START_GAME이나 시작 규칙을 수정하지 말라는 뜻이 아니다.** 기존 프로젝트 지침·기존 원작 게임의 모든 실행/판정/전투/SAN/이미지/HUD/저장·후일담 시스템을 기반으로, **필요한 진입 지점만 수정하여 시간요원 본부를 연결**한다. 별도 HQ 전용 게임 엔진/강제 START_HQ_TEST.md/대체 프로젝트 인스트럭션 방식은 철회한다.

## 실제 변경한 원본 개발 브랜치

- `START_GAME.md`: **가장 최신 운영 main 파일을 기준으로** 기존 장문 원작/PC/카드/위험/시나리오 지침을 보존한 채, `게임 시작` 명령의 첫 항목을 **요원 활성화 ON/OFF(기본 ON)**로 교체하고 `## 게임 시작 — 요원 활성화 분기`를 삽입했다.
- `rules/04-setup.md`: 최신 운영 main 판본의 `START_SETTINGS_GATE`를 두 경로로 분기, `HQ_ON_CAMPAIGN_ROUTER`를 추가, `CAMPAIGN_SETUP_PIPELINE`의 시작 위치만 분기. 현지 PC/성장·카드 4슬롯/기존 원작 설계/저장/판정의 실제 상세 절은 기존 main 그대로.
- `PROJECT_INSTRUCTIONS.md` 및 `rules/00-index.md`, `01-core.md`, `02-checks.md`, `03-danger.md`, `05-world.md`, `06-play.md`, `07-state.md`, `08-visual.md`, `09-cards.md`: **실제 현재 운영 main과 텍스트 완전 동일**하게 DEV 브랜치 재동기화. 특히 2026-11-12의 최신 SAN 산식·원작 체험 중심 사고·주요 사건 도달 규칙/기존 세이브 호환을 이 테스트에서 누락시키지 않는다.

## 실제 사용자 시작 화면

### 게임 시작 → ON (첫 질문)
- 요원 활성화: ON
- 참가 인원: 1~3명
- P1 영구 닉네임(2~24자)
- 필요하면 P2/P3 닉네임
- **이때 원작 인지도/대사건·연대기/원작·시대/PC 생성은 아직 묻지 않는다.**
- 입력 확정→기존 영구 카드 UUID/본부 이력→최초 신입 입구 또는 기존 요원 동기화실 → 제이든 인사·마틴 실제 입단/면담·본부 교류 → 작전실에서 **기존 인지도·규모·기피/지정 원작·시대**를 입력받음.
- 그 뒤 **기존 04-setup 원작 A~D/PC 생성·카드/성장/4슬롯·정본/V2 검증** → 마틴 실제 임무 브리핑 → 플레이어가 출격을 선택하면 제이든 동기화 → **기존 00~09 원작 생존 공포 게임을 그대로 진행**.
- 실제 끝난 임무만 V2 확인→귀환 +3일 1회→마틴 평가/적격 보상 승인→클라라 실제 관측 후속→도미닉 각 요원별 순차 직접 선택/지급→휴게실/후속 챕터/다음 임무.

### 게임 시작 → OFF
- 본부·닉네임/영구 카드·성장 모두 생략.
- **기존 일반 게임**의 원작 인지도, 규모, 배제/직접 지정 원작/시대, 전원 PC 생성·시나리오·판정·SAN/HP·세이브/HUD/후일담 전부 그대로.
- 기존 ON 현지 게임/확정 플레이/저장 기록에 소급 적용하지 않는다.

### 현지 진행 중 새 채팅에서 로드
- 게임 시작 절차를 다시 실행하는 것이 아니라 **07-state STATE_RESUME**, 현지의 실제 장소·시각·열린 입력부터. 미선택/이미 해결된 보상과 +3일 반복 없음.

## 실제 검증 범위

- **정적 파일 대조 통과**: `PROJECT_INSTRUCTIONS.md`와 `rules/00–03,05–09` 총 10개 파일이 최신 운영 main과 완전 동일함을 GitHub에서 각각 fetch하여 문자열 대조. `START_GAME.md`에는 ON/OFF 경로와 2026-11-12 최신 SAN/주요 사건 경험 규칙 보존, `04-setup.md`에는 세 START_SETTINGS_GATE/HQ_ON_CAMPAIGN_ROUTER/CAMPAIGN_SETUP_PIPELINE 및 기존 PC/시나리오 담당 절 보존.
- DEV Supabase의 본부 26개 마이그레이션·11차 DB 계층 루프 회귀는 이전 단계에서 이미 성공. **이번 12차는 게임 텍스트/라우팅 파일을 실제 수정했지만 ChatGPT의 첫 화면 출력·전체 1회 실전 플레이나 게임 세션에서의 DEV DB 인증 연결을 아직 실행 검증한 것은 아니다.**
- 운영 `main`, 운영 Supabase에 **쓰기 없음**. GitHub 개발 브랜치의 게임 설정 파일만 통합.
- **이전 v1/v2 테스트 ZIP 폐기 권고:** v1의 프로젝트 지침 대체/별도 시작 파일, v2의 변경 0바이트 START_GAME에 HQ_ON_ENTRY만 추가하는 방식은 사용자가 명시한 통합 목표와 다르다. 지금부터 실제 `START_GAME.md` DEV판이 유일한 신규 게임 시작점이다.
