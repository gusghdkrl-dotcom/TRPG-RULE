## 1. 최우선 기준과 역할 배치

**룰을 최대한 경량화하고 조회·처리를 최적화하면서 정확성을 유지한다.** 단순히 글자 수를 줄이거나 AI에게 전부 맡기는 것이 목적이 아니다. 판정·피해·비용·정보·상태·재개의 실제 결과를 결정하는 필수 내용은 정확히 보존하고, 중복 설명·고정 개수·세부 작성 절차·불필요한 확인과 검수를 줄인다.

- 인스트럭션: 생존 호러의 스토리를 만들고 이끄는 키퍼의 작가적 판단·연출·진행에 최대한 집중한다. 탄탄한 세계·시나리오·중요 소재·숨은 진실·강력한 적/환경·명확한 행동 경로·실제 위해·속도/환기·축적된 결과와 결말을 상시 유지한다. 상황별 룰북의 짧은 참조 경로를 둔다.
- **NPC의 서사 운영도 인스트럭션에 포함한다.** 목적·책임·욕망·두려움·관계·지식에 따라 먼저 행동하고, 협력/거절/거래/갈등으로 사건과 선택을 만든다. 말투와 실제 교류는 지속되며 위험과 손실을 겪는다. 명령 대기·자동 찬성/반대·정답 전달자로 고정하지 않는다.
- 룰북: 특정 상황의 수치·계산·조건·절차·예외. 동일 기능은 담당 본문 한곳에 두고 조회 조건으로 연결한다.
- 캠페인 정본/현재 상태: 그 세계·인물의 실제 사실과 누적 변화. 원문 보존과 정확한 재개를 경량화 명목으로 제거하지 않는다.
- AI 자율: 위 기반 안의 장면 구성·표현·대화 호흡·상황에 맞는 창작. 필수 소재의 인과와 의미까지 미정으로 방치하지 않는다.

배치는18절을 따르며, 진행/위협/페이싱을 앞세우고 구체적인 묘사/장면 작성법을 결합한 최종 지침은 PROJECT_INSTRUCTIONS.md다. [과거 교체 초안](PROJECT_INSTRUCTIONS_REORGANIZATION_DRAFT.md)은 개발 검토 이력으로만 보존한다.

## 3. 시작 설정 — 확정

### 입력과 생성

- **핵심 시드 입력 삭제.** 장르 탐색 기능까지 없애는 것은 아니다.
- **시작 시드는 실제 Python으로 자동 생성하고 기록한다.** 플레이어의 필수 숫자 입력은 없앤다. 별도 범위/알고리즘 변경 합의는 없으므로 현행 생성 체계를 기반으로 구현한다.
- 원작/장르 직접 지정은 우선한다. 미지정이면 시작 시드의 독립 장르 탐색 난수로 장르를 정하고 인지도·배제 조건을 반영해 원작 후보를 만든다.
- **인지도 유지.** 참가 인원 1~3명과 실제 슬롯 연결 유지.
- **작은 ‘사건’ 선택 삭제, 대사건·연대기만 유지.** 신규 선택 번호와 구판 저장 enum의 대응은 구현 때 명시하며 구판의 숫자를 조용히 재해석하지 않는다.
- **PC 사전 관계의 별도 시작 입력 삭제.** 플레이에서 실제로 생긴 관계·약속은 보존한다. 다른 프로필/관계 기능을 전부 삭제하라는 뜻은 아니다.
- 원작/장르/시대 직접 지정, 배제 조건 등 나머지 시작 선택 기능 유지.

### 처리 경량화

받은 값 보존, 누락/오류만 질문, 선택 입력의 빈칸 처리, 모호한 숫자의 대상 확인, 명시적 자동 선택 요청, 충돌 조건 확인, 완성된 입력의 재승인 생략을 하나의 짧은 입력 규칙으로 통합한다.

‘설정 완료 전 모든 검색·도구 금지’는 제거하고 **미확정 조건에 의존하는 생성만 대기**한다. 설정을 돕는 검색·도구와 시작 시드 생성은 허용한다. 설정 입력을 게임 시간/턴 진행으로 세지 않는다. 확정 이후 수정은 영향 범위만 처리한다. 로드는 신규 설정과 분리한다.

실제 UI가 없을 때 일반 채팅 전환을 승인받는 기본 절차는 제거한다. 지원되는 방식으로 실제 입력을 받되 도구/UI를 가장하지 않는다. 특정 UI를 사용자가 별도로 요구한 경우의 처리와 새 표시 방식은 UI 검토에서 정한다.

## 4. 원작 후보 선정 — 확정

- **드래프트 A~D 4개.** 대표작 A/B·자유형 나머지라는 고정 슬롯 구분 삭제. 인지도와 실제 체험 차이를 네 후보 전체에 적용한다.
- **최근 완료 작품 최대 10개 제외 삭제.** 크툴루의 별도 전체 완료 이력 차단도 함께 제거한다. 현재 드래프트 내 동일 작품/공식 단위 중복만 검사한다.
- 후보 선정의 별도 ‘이력이 없으면 과거 기록을 추측하지 않음’ 규칙 삭제. 이력 검색/추적 절차를 남기기 위한 우회 규칙도 만들지 않는다.
- 내부 후보 18~30개, 탐색 Lane 강제, HIGH/MEDIUM/LOW 등급, 고정 두 줄 카드·키워드 개수·선택 문구 삭제.
- 분위기·플레이 성향·공간 규모 표는 필수 추첨 대신 탐색 참고로 간소화한다. 다양성 때문에 원작 구현 가능성을 낮추지 않는다.
- 실제 존재하고 세계를 구현할 만큼 확인 가능한 작품을 선정한다. 불확실한 정보만 필요한 범위로 검색한다. 후보 추첨이 실제 필요하면 공통 Python 생성 규칙을 사용한다.
- 표시: 작품명·필요한 판본/공식 시나리오 구분·매체·짧은 체험 차이. 연도/문화권은 구분에 필요할 때 표시. 반전과 캠페인 비밀 비공개.
- 직접 원작 지정 우선, 정확한 공식 Source Unit 구분 유지. **기존 SF 자동 후보 제외 정책은 유지**하며 사용자 직접 지정은 허용한다. 팬/홈브루 직접 지정 등 기존 콘텐츠 선호를 임의 확대하지 않는다.

- 이름마다 최소6후보·다단계 추첨은 간소화. 현재 인물 혼동 방지는 짧게 유지. **최근 자동 이름24명 중복 회피 삭제.**

- 직업 기능 수치/업무를 선택 전 반드시 숨기는 제한 제거. 실제 표시 방식은 UI 개편에서 정한다.
- **배우 레퍼런스 필수 유지**(기존 한 명의 시각 참고). 배우 자동 선정의 별도 난수축·고정 설명 문장 수는 제거/간소화한다.
- **APP 구간별 상세 외형 묘사표 삭제.** APP 반영과 사용자 외형 보존·후속 이미지의 인물 일관성은 유지한다.
- 과거 사건/현재 목적은 유지하되 필수 ‘상처’와 별도 민감 자극 생성은 제거. 자연스러운 경력·생활·관계·성취도 배경이 될 수 있다.
- **정확히3개 캐릭터 태그·120개 카탈로그 삭제.** 실제 직업·신분·관계·경험에 따른 반응은 유지한다.
- **PC별 과거/사건 공명 후보2~3개 생성 삭제.** 자연스러운 연결은 서사 운영에 맡긴다.
- 파티 중복의 수치 기준과 재생성 검사는 다양성 원칙으로 압축하고 플레이어가 원하는 유사 인물은 허용한다.
- **0칸 직업 소지품1개 지급 삭제.** 필요한 직업 도구는 일반 시작 장비로 확정한다. 키템 등 다른 인벤토리 규칙까지 삭제한 것은 아니다.
- 최종 프로필 고정 코드 블록·항목 순서·문장 수는 UI 검토로 이동한다. 성장/숙련 표현/연대기 전문성 발전은 해당 플레이 영역으로 이동한다.

## 6. 세계·시나리오 생성 — 제안 수용 확정

**필수 산출물은 탄탄하게, 작성 방식은 AI 자율로.** 원인·깊은 진실·주요 소재의 목적/중요성/활용·인물/세력·공간/경로·증거·능동적 접촉·개입/해결/탈출·중대한 실패 영향은 반드시 갖춘다.

- 원작 교차 분석은 실제 체험에 쓰일 핵심으로 압축. 특징5~7개·세계 법칙최소2개 같은 고정 개수 제거. 법칙의 조건·효과·전조·한계·대응 명세는 유지.
- 연출 문법10종, 시나리오11축, 최종 위험5축의 필수 독립 추첨 절차 제거. 표는 필요한 경우 다양성 참고로 사용한다. 실제 난수를 쓰면 Python과 공통 생성 기록 규칙을 따른다.
- **최종 위험8개 설계 내용 유지:** 실체·목적/진행·능력/한계·격화 조건·결정적 난관·개입/제압/생존/탈출·준비/획득·실패 영향. 괴물만을 뜻하지 않는다.
- 원작·인과에 맞는 중심 이야기와 가능한 반전/대가는 준비하되 실제 중반 반전·결말 손실을 추첨으로 예약하지 않는다. 과거 시그니처 비교 후 축 재생성 삭제.
- 적의 판정 수치·피해식·방어·이동·접근, 환경 위해/진행성 상태의 효과·처치·해제는 사용 전에 확정. 같은 위해 설계의 반복 절 통합.
- 주요 NPC의 목적/지식/우선순위/경계/목소리, 장소의 용도/접근/운영, 단서의 내용/의미/발견/활용, 지도의 상대 위치/연결 유지. 모든 방/직원 사전 작성은 요구하지 않는다.
- 정확한 좌표·분 단위 이동표는 실제 필요할 때만. 생활 기반2~4개·미개입 진행축2~5개·접촉 경로 최소 개수 등 제거. 실제로 사건이 이어지는 인과는 유지.
- PC 참여 이유·첫 충돌·전문 활약과 주요 진행/우회/예방/실패 후 상황은 유지하되 중복 연결 표와 미래 장면 전체 작성은 축소한다.
- 생성 검수를 **원작/인과/진행/생존/실행 5개 기준**으로 통합. 회차·턴 수에 맞춘 생성 목표 제거. 플레이 중 속도 조절과 초반30턴 마감 삭제는 후속12절을 따른다.
- 핵심 진실/성과 보존과 미확정 세부의 구체화 구분. 연대기는 세계 기반+첫 챕터 준비, 다음 챕터는 실제 결과로 생성.
- 정본은 유지하고 파일/판본/저장 절차는 상태 문서로, 브리핑은 공개 상식/현재 이유/문제를 제공하고 형식은 UI로 배치한다.

## 7. 장면 진입·탐구 — 사용자 수정 포함 확정

### 유지

행동에 필요한 맥락·공간·상황, 소진된 조사 명확화, 실제 거리/장애물/위협에 따른 청취·안전 판단, 올바른 기능 선정, 실제 암호/외국어/손상 난관, 중요한 단서의 이해·접근·선택 변화, 복수 발견 경로, 사실/가설/확인된 결론, 실제 가설 시험과 유효한 위협 지식, 실패 후에도 가능한 진행을 유지한다.

### 삭제·통합

- 첫 장면 설명의 고정 순서, 핵심대상1개/선택대상0~2개, 사물마다 과거 비극 툴팁 삭제.
- **발견과 해석을 별도 단계로 구분하는 규칙 삭제**(사용자 수정). 명백한 의미·전문상식은 한 흐름으로 제공한다. ‘분석을 선언한 뒤에만 해석’ 제한도 제거한다. 사실/가설의 확실성 구분까지 없애는 것은 아니다.
- 단서 찾기→읽기→역사/분석을 자동 연속 판정하지 않는다. 같은 목적의 색인/번호/장부/파일 절차는 압축. 자연어 읽기 범위는 공통 행동 해석으로 통합한다.
- 자료의 실제 본문·핵심 숫자/날짜/문구·읽는 범위·작성자 지식·손상/접근·재열람 일관성 유지. 소개 순서/인용 서식 강제와 ‘한 문서가 전말을 다 설명하면 안 됨’ 일괄 금지 제거.
- 모순·시간 재구성·부재 단서·질문 심화·오도·복선·정보 재맥락화·환시/공간/퍼즐은 개별 의무/개수 없이 AI 참고 기법으로 통합. 실제 원인·관찰 사실은 사후 변경하지 않는다.
- 핵심 정보가 있는 올바른 접근에서 한 번의 실패로 전체 진행을 영구 차단하지 않는다. 실패의 실제 대가와 선택적 심층 보상의 비보장은 유지한다. 완료 확인을 반복하지 않는다.
- 증거 그래프/관계/시각/가설의 저장 구조는 상태 문서로, 고정 행동 메뉴/매 응답 요약은 UI로 이동한다. 메타 토의와 극중 조사 시간은 구분한다.

## 8. NPC·인물 상호작용 — 제안 수용 확정

- 목적·책임·지식·수단·관계에 따른 판단, 명령 없는 선제 행동, NPC끼리의 실제 교류, 상황 변화에 따른 재고 유지. ‘상충 가치 최소2개’와 요청별 단계적 검사 절차 제거.
- ‘정보는 Give & Take 뒤에만’, ‘결정적 물증 전 자백 금지’, ‘정체 시 환경/증거부터 처리한 뒤 NPC 힌트’ 일괄 제한 삭제. 실제 아는 것과 말할 이유가 있으면 먼저 정보/도움을 제공할 수 있다.
- 심리학/사회 판정 성공은 정상 판정의 사전 범위를 따른다. 자동 진실 탐지/자백으로 만들지 않는다. 성공한 설득·합의는 실제 반영한다.
- 새 결심·비용·위험·계약·약속·물건 사용은 PC 응답을 기다린다. 사소한 인사/확인마다 중단하는 적용과 응답마다 PC 발언 근거를 전수 검수하는 절차 제거. 이미 선언한 목적 안의 자연스러운 대화와 반복 문의는 처리/압축한다.
- PC의 미선언 결심/감정/약속은 대신 쓰지 않는다. 직접화법 의무는 완화하되 입력 대사의 의미·말투 보존. 표현은 장면에 맞게 한다.
- 인물별/상대별 말투·호칭·실제 관계와 중요한 기억·합의·이해 방향/표현 능력 유지. 매 발언의 상세 수신자 점검은 현재 지식과 중요한 근거 유지로 압축. 전원 이력 재조회는 하지 않는다.
- 맡은 역할·손에 든 물건·실제 인계·전투 행동 기회와 정상 수치/피해/SAN 유지. 무료 추가 행동·동시 수행은 허용하지 않는다.
- 동행 수/합류/이탈은 실제 이야기 인과로 처리. 고정 소개 절차/순서 제거. 필요한 공개 정보만 전달한다.
- 능동적 치료/구조는 일반 NPC 행동+의료 규칙으로 통합. 기관 접근6단계 고정 분류는 제거하고 실제 권한·범위·합의·제한을 기록한다.
- 관계/약속/말투의 저장 구조와 지식 오류의 정정 절차는 상태/복구 문서로 이동. 호감도 수치 대신 실제 경험 사용. NPC 서사 원칙은 인스트럭션에 포함한다.

## 9. 행동·결과 판정 — 제안 수용 확정

- 불확실성과 의미 있는 결과 차이가 있을 때 판정. 통상 행동·명백한 정보·불확실성 제거는 직접 처리. 같은 목적의 종속 공정 분할/같은 조건 무한 재굴림 금지. 실제 불가능과 창의적 수단으로 가능해진 시도 구분 유지.
- 순차 체크리스트 대신 현재 가능성/불확실성만 판단한다. 특성 의미·기능 선정·조사 기능·대체 경계를 한곳에 압축. 높은 값 때문에 전문 기능을 INT/EDU/STR/DEX로 무차별 대체하지 않는다.
- **계산 유지:** Critical01, Extreme원래값/5 내림, Hard/2 내림, Regular원래값. Fumble원래값50미만96~100/50이상100. 요구 수준 미충족은 실패. 굴림 전 난이도·유불리·성공 범위·실패 위험 고정.
- 난이도(작업)와 유불리(조건), 위험의 치명성과 성공확률 구별. 같은 원인 중복 보정 금지. 긴 사례/반복 경고 축소.
- **유불리 유지:** 1:1상쇄·남은 최대2·기본 일의 자리 고정/복수 십의 자리·00=100·보너스최저/패널티최고. 계산 원문 한곳, PC/NPC 실행은 참조.
- **행운 유지:** 체크만 받고 Regular 최소 비용 자동 차감, 부족/금지이면0차감, Hard/Extreme 상승 불가. Fumble/SAN/Luck Roll/피해량 금지. 행운+강행은 행운 우선.

- PC d100은 플레이어, 나머지 실제 난수는 Python. 실제 입력/원값/비용/적용 이력 보존. UI/결과 표시·상태 기록·구판 호환은 담당 영역으로 이동. 회복/버프 후속 합의는11·17절.

## 10. 위기·생존 — 이번 제안 수용 확정

### 실행·전투

- 실제 도달한 공격·환경·정신 위해는 판정과 실제 결과까지 처리. 경고로 되돌리기/플롯 보호/피해 누락 방지. PC/NPC 동일 세계 원칙과 유효한 차단·회피·안전 보존. 긴 담당 문서 Cascade/반복 경고는 짧은 참조로 통합.

## 12. 세계 진행·시간·장면 전환·다인 진행 — 제안 수용

- 실제 원인·목적·정보·위치·자원·조건에 따른 NPC/적/환경의 선제·화면 밖 진행 유지. 바뀐 조건에 관련된 활성 원인만 처리하고 결과/취소를 한 번 반영한다. 인과 의존 순서는 보존하되 상세 저장 필드는07-state로 집중한다.
- **초반 큰 사건30턴 고정 마감 삭제.** 첫 일상 목적을 무한 연장하지 않고 초반 직접 충돌과 중대한 PC 영향/대응 문제를 실제로 발생시킨다는 서사 책임은 강화한다.
- 변화 없는 장면2개 정체 카운트, 규모별150/220/300 등의 후반 턴 기준과 WARNING/RETURN_PRESSURE/OVERRUN 편집 모드 삭제. 소진된 조사/반복 절차는 압축하고 실제 중심 인과·성과·남은 난관으로 수렴/종결을 판단한다.

- 활동에 맞는 자율 시간 경과, 정확한 기존 일정/거리 우선, 중복 시간 정산 방지 유지. 인사·협의·문서 작성별 시간 범위표는 의무 규칙에서 제거. 실제 전투·질식·마감·동시 행동 충돌에 필요할 때만 세분한다. 일반 사건은 조건 성립 중심.
- 알려진 이동은 실제 위험/비용/갈림길이 없으면 출발~도착을 한 번에 처리. 장기 행동 완료 전에 실제 도달하는 기존 사건은 가장 이른 대응 지점에서 중단한다. 미선언 후속 행동을 자동 실행하지 않는다.
- Scene Turn은 의미 있는 행동 결과의 진행 번호로 유지하고 메타/입력/재표시/로드에서 중복 증가시키지 않는다. 고정3회 목표/5회 상한의 Spotlight 교대 예산 삭제. 자연스러운 직접 결과 경계·긴급 대응·명시적 넘김·오래 기다린 PC를 기준으로 교대한다. 도착만으로 상호작용 전에 자르지 않는다.

## 13. 성취·성장·결말·연대기 — 사용자 수정 포함 확정

- **게임 내 영구 스탯 성장은 연대기에서만 가능. 대사건에서는 없음.** 일반 기능 외 신화 기능 등 별도 상승도 이 제한과 대조한다. 학습으로 얻은 사실/대응 지식·물건·협력자·권한·경로는 대사건에서도 실제 성과로 유지. 피해·소모·현재치 치료/회복은 성장과 구분한다. 새 특성/최대HP 성장 시스템은 추가하지 않는다.
- 연대기 기능 성장: 실제 의미 있는 사용·학습 근거, 중요한 결과가 일단락된 첫 안전 경계, PC별최대2개, 후보1~2개 자동/3개 이상 선택. 직전 영구 기능80미만+2/80이상+1·상한95, 별도 성장 주사위 없음 유지. 기존 획득치·열린 판정 보존. 성장 대기/적용/중복 방지는 상태 문서에 집중한다.
- 연대기 전문성은 실제 충분한 훈련/경험으로 챕터 사이 기존 범위 심화 또는 새 전문성1개, 시작 포함 동시상한3개 유지. 일반 기능 성장 경계와 혼동하지 않는다.
- Seed→Echo→Payoff 형식 의무와 나비효과3~6개 참고 개수 삭제. 실제 중요한 선택·준비·환경·관계의 후속 인과는 보존. 막판 회수표·마지막 풍경·콜백은 자율 작법으로 축약한다. 실제 인물 인계1회·대상 없으면 관전 유지.
- 종결은 실제 중심 갈등 해결/차단·실제 철수·불가역 실패·가능한 인계 뒤 행동 주체 소멸 등으로 판단. 결과를 바꿀 유효한 대응은 먼저 처리하되 모든 단서·관계·목표 완결을 요구하지 않는다. 종료 중복 방지/실제 손실 정산 유지.
- 고유 엔딩 제목+결말 장면+후일담 유지. 결과6개 축은 점수/정형 보고서가 아닌 빠짐 방지 참고로 축약. 이미지 선택 대기로 엔딩을 멈추지 않고 변화 카드 등은 요청 시 제공.
- **OPTIONAL_POST_CREDITS_VIEWS 이름의 기존 기능은 선택 요청형으로 축소하지 않는다.** 핵심 결말 뒤 다음 다섯 항목을 **순서대로 한 출력씩 자세하고 몰입되게** 제공하고 `다음`으로 이어간다. 필수 글자 수는 없고 실제 기록에 근거하며 반복 분량 채우기는 하지 않는다.
  1. Highlight Reel: 실제 발생한 강렬한 장면을 감각·행동·결정적인 순간으로 재조명.
  2. The Silent Stage: 사건 뒤 장소·파괴·구조·잔존 위협·선택의 외부 흔적.
  3. Cast & Crew: 실제 인물의 활약/결과·생사·최종 공개 상태·확인 가능한 후일.
  4. The Hidden Truth: 놓친 확정 원인과 연결. 후속 캠페인/진행 세계 비밀 보호, 미정인 정답을 사후 창작하지 않음.
  5. Ultimate Butterfly: 결말에 큰 영향을 준 실제 앞선 선택 하나와 이어진 인과를 비춰 마무리.
- 후일담의 완료/현재 항목은 종료 상태와 함께 보존해 채팅 이동 때 처음부터 반복하거나 게임 플레이를 재개하지 않는다. 감정·교훈·새 비극/구원을 강제로 덧붙이지 않는다.

## 14. 상태·세이브·로드 — 연속성 우선 설계 확정

사용자는 **로드 실패·외부 저장 차단 자체는 이번 해결 범위에서 제쳐두고**, 플레이 경험과 세계/스토리 문제 개선에 집중하도록 지시했다. 서비스 차단을 해결했다고 주장하지 않는다. 현재 Supabase/GitHub 저장 경로를 임의로 새 서비스/서버로 교체하거나 운영 데이터·인증을 바꾸지 않는다.

기존 값/개별 사실 비교만으로 충분하다고 보지 않는다. 저장 내용은 다음 범위를 연결한다.

| 범위 | 필요한 내용 |
|---|---|
| 정확한 상태 | 전원 수치·자원·부상/광기·소지품/소지자·위치·세계 변화·난수/판정/행동 대기 |
| 이야기 연결 | 여기까지 온 주요 원인·발견·목표 변화·결정과 결과·미해결 문제·현재 흐름 |
| 인물 연속성 | 기본 성격/말투와 상대별 호칭·대화 관습·공동 경험·현재 태도 및 이유·지식·협력/거절·역할 |
| 현재 장면 | 직전 행동/반응·대화 주제·마지막 질문/제안·확인된 의미·거리/장애물/준비·누구의 어떤 응답 대기인지 |
| 잔존 인과 | 약속·준비 효력·후속 결과·진행성 위해·화면 밖 행동과 다음 발동/취소 조건·이미 처리한 event |

- 구조화된 현재값과 **그 사실들이 어떻게 연결되는지 보여주는 재개 문맥**을 함께 보존한다. 문맥은 확정 사실을 설명하며 수치/정본을 덮어쓰는 독립된 경쟁 정본이 아니다. 향후 계약에서 실제 저장 가능한 위치와 재구성 경로를 확인한다.
- 정본 기준선+누적 현재 변화+신규 사실+종결/취소+처리 event 유지. 마지막 저장 이후 변화만 남기는 불완전한 delta 체인으로 바꾸지 않는다. 모든 대화 전문/모든 몸짓을 저장하라는 뜻도 아니다.
- 실제 의미 있는 변화 시 관련 부분만 갱신. 장면 전환에서 완료/잔존 결과를 연결하되 과거 중요 경험을 현재 장면 요약으로 지우지 않는다. 현재 장면 밖의 중요한 상태도 저장에 포함한다.
- 주요 NPC 말투는 형용사만이 아니라 확립된 문장 길이·존대/호칭·어휘·상대별 관습·위험 때 반응 등 재현 가능한 특징을 보존한다. 필요하면 실제 짧은 발언을 참고로 남기며 모든 인물에 항목/인용 개수를 강제하지 않는다.
- 로드 첫 지문 전에 정확한 현재값+이야기 흐름+관련 인물+현재 장면/응답 대기를 함께 복원. 제안/수락·소유/소지·준비/실행·듣기/발화·확인/추정을 구분한다. 이미 통했던 의사소통을 미확인으로 되돌리지 않는다.
- 검증은 **기록 원문 보존 / 중요한 내용과 맥락 보존 / 실제 이어하기 적용**을 구분한다. 이전 대화 없이 정본과 저장본만으로 재개해 완료한 일을 다시 묻는지, 말투/태도/목표/다음 선택/준비/피해가 이어지는지 비교한다. 기존 check_resume_semantics.py는 지정한 값 비교용이며 이 경험 검증을 자동 대신하지 못한다.
- 현재 규정의 반복적인 저장 설명/수신자 경고/복구 절차는 담당 절 한곳으로 집중. 필요한 현재 상태/동일 원문은 재사용하고 변경 없는 전체 상태를 매번 재직렬화/재조회하지 않는다. 해시와 의미 보존은 별개, 서버 verified와 재개 품질도 별개다.
- 일반 저장30턴·수동 저장·전체 종료 저장의 기본은 유지. 앞서 제안했던 **20턴 전체 정본 재독 삭제 / 설정 완료+시작 직전 저장 통합 / 백업 파생 문서 생략**은 세이브 경량화 논의가 재개 품질 우선으로 다시 열린 항목이다. 내용 충분성과 복원 경로를 대조하기 전 확정 삭제로 간주하지 않는다. 운영 저장 계약 변경은 별도 범위다.
- 실제 저장/도구 유실과 확인 가능한 작업 상태를 구분하고 부분 복구를 완전 최신본이라고 하지 않는다. 기존 verified 원문·다른 분기·구판의 사실을 조용히 덮거나 추측으로 메우지 않는다.

## 15. 입력·출력·상시 HUD — 사용자 수정 포함 확정

- 실제 입력 UI 도구 우선, 없으면 별도 전환 승인 없이 동일 항목을 채팅으로 받는다. UI/도구 기능을 가장하지 않는다. 필수 정보/후보 대응/현재 입력의 의미는 보존하고 제목·순서·문장·행 배치의 과도한 고정은 제거.
- PC 굴림 원값+행운/강행 통합 입력 유지. 행운은 체크만 받고 Regular 최소 비용 자동 계산. 필요한 원값/동의/강행의 구체 방법과 더 큰 위험을 묶고 유효한 제출을 반복 요구하지 않는다. 삭제한 생활 버프 폼 제거.
- 자유 선언 항상 허용, 일반 행동 선택지 고정1~3+4번 안내 삭제. 실제 가능한 다른 접근만 번호로 제시하며 수를 채우려고 세계 사실을 만들지 않는다. 직접 답할 NPC 질문이 있으면 그 질문으로 행동권을 돌릴 수 있다.
- **매 응답 ‘이번 씬 요약·결과’ 전체 의무 삭제. ‘씬 연출 의도’ 표시 삭제.** 복잡한 결과 정산/명시적 요청의 요약까지 금지하지 않는다.
- 상시: 행동권자·이름/턴·위치/시각·HP/SAN/Luck, 실제 부상/상태와 효과, 필수 대응/판정 대기. 목표/위험/관련 물품·탄약 등은 현재 판단에 필요할 때. 현금은 거래/변경/요청 시. **인벤토리는 상시 생략 제안을 철회하고 기존처럼 매 일반 턴 물품 목록+메인/파우치 점유량 유지.** 알려진 구성품 상세는 현재 관련성/요청에 따라 펼칠 수 있다.
- 공개 판정 내역은 실제 요구값·PC 원값/최종값·성공 단계·상대 실제값/단계·최종 비교 결과를 합계1~2줄. 대항/NPC Python 사용 완료 값 포함, 비공개 사건/미발견 상대는 누설하지 않는다. 표·각주·긴 해설 없이 필요한 실제 행운/피해만 짧게 덧붙인다.
- 전체 시트/인벤토리 상세/공개 단서/인물/약속은 요청 시 제공. HUD 생략과 상태 삭제는 다르다. 아이콘·3열표·문단 수/정확한 순서의 반복 강제는 간결한 읽기 위계로 통합.
- 본문900~1,600자 참고와 매번 분량/형식 전수 점검 절차 삭제. 중요한 장면은 충분히, 단순 처리는 짧게. 수치/필수 사실은 서식 자율화로 바꾸지 않는다.

## 16. 지도·이미지·공개 수첩 — 사용자 수정 포함 확정

- 실제 지형/경로·연결 모델, 공개 지도와 비공개 공간 구분, 지도 보기 시간정지/이동은 실제 처리 유지. 이미지 픽셀은 거리·위치의 정본이 아님. 최초 기능형 지도 이미지 제공 유지, 실패 시 동일 공간의 텍스트/연결도로 진행하고 이미지 성공으로 가장하지 않는다. 발견/폐쇄 상태는 갱신하되 매번 이미지 재생성하지 않는다.
- APP·배우 참고·실제 외형/복장/부상/장비·장소의 공간 연속성 유지. 프로필 dossier 계열/제공 기준 이미지·시작/종료 변화 카드 유지. 정확한 블록 위치·보조 사진 수·문장 수·캐릭터 태그/물건 생활 흔적 의무는 제거/정합화한다.
- 장소A/B/C 등급/조건2개, 상호작용 요소2~4개, 3패널/면적 비율·3~4사진 등의 고정 개수 제거. 장면에 맞는 실사 영화적 구도는 AI가 선택한다. 프로필/장소마다 A/B 대기 삭제, 요청/정해진 제공 시점에 처리한다.
- 이미지의 임의 소품을 숨은 단서·통로·자원으로 자동 확정하지 않는다. 기존 세계에 맞는 평범한 세부를 실제 상호작용하며 확정할 수 있다. 실제 asset ref만 보존, 없으면 외형/공간 기준으로 재현하고 픽셀/파일의 영속 동일성은 주장하지 않는다.
- 웹 참고는 실제 설명에 유용할 때 출처와 참고 표시를 붙여 활용. 후보/첫 등장마다 검색 의무 제거. 정확한 캐릭터/지도/증거를 일반 사진으로 대체하지 않고 비공개 정보를 검색어로 보내지 않는다. 실패해도 텍스트 진행.
- **공개 수첩 기능 전체 삭제.** rules/09-notebook.md, 개설·조회·복구·binding, 변경 전송/이미지 보관, watcher/단일Writer/큐·충돌, 전용 상태·지침·색인·세이브/로드 참조 제거. 일반 게임에 필요한 공개 인물·증거·가설·약속·지도 사실 자체는 현재 상태와 세이브에 남긴다. 운영 앱/외부 수첩 데이터 삭제나 배포를 의미하지 않는다.

## 17. 남았던 계산 기준 — 후속 명시 승인

- **장기적 광기:** 극중 하루 시작 SAN을 고정 분모로 사용. 그날 SAN 손실의 합계가20% 이상(정수 최소치=ceil(시작SAN/5))이면 발생. 회복은 누적 손실 차감 없음. 시작SAN53이면11손실. 단일5+손실→INT는 별도 유지. 하루 기준/누적은 로드로 초기화하지 않는다.
- **질식/익사:** 실제 위험 지속 행동 구간마다 CON1회, 전투 중 라운드당1회, 실패1d6. 메시지/대사/입력마다 판정하지 않는다. 긴 행동은 필요한 생존 대응에서 멈추고 완료까지 피해를 몰아 자동 정산하지 않는다. 별도 산소 게이지 추가 없음.
- **일반SAN회복:** 안전한 환경에서 충분한 수면·휴식 시 극중 하루1회1d3. 최대SAN 초과/동일 휴식 중복 적용 없음. 단순 농담/식사/연기 채점으로 지급하지 않는다. 별도 확정 치료가 있으면 해당 규칙 적용, SAN 회복만으로 광기 자동 치료 없음. 대사건에서도 현재치 회복 가능. 사용 여부/위험 처리 단계는 상태에 보존한다.

## 19. 통합 패치의 대표 검토 사례

1. 평범한 직업/방문에서 시작해도 초반 직접 충돌·현재 문제·걸린 것·접근이 생기며 원작 요소를 실제 경험하는가. 기존 영화 사건을 복제하지 않는가.
2. 작은 이상을 따라가면 큰 원인·실행력 있는 위협·주요 소재의 의미·구체적인 해결/탈출로 연결되는가. 무한한 후속 적/무의미한 고장·문서 수집으로 끝나지 않는가.
3. 조사하지 않아도 인물/위협은 실제 조건으로 움직이고, 도달한 위해는 결과까지 적용되는가. 창의적 차단·조기 해결·확보한 안전은 인정되는가.
4. 중요한 장면의 몰입·자연스러운 행동/상황 유머는 살아 있고 반복 이동/회의/종속 조사는 줄었는가. 삭제한 분량/개수 검사를 새 이름으로 되살리지 않는가.
5. PC/NPC가 다치고 상태 효과·치료·소모·SAN 손실이 이어지는가. 일일SAN누적·회복1회·질식 진행 단위와 전투경제가 정확한가.
6. 대사건 영구 기능 성장은 없음/연대기 기존 성장 계산, 신화 기능 예외, 실제 지식/장비 성과·현재치 치료를 구별하는가.
7. 인벤토리 상시 목록은 유지되고 씬 요약/연출 의도·생활 버프·수첩은 신규 경로에서 제거됐는가. 판정 요구/양측 원값/결과는1~2줄에 정확한가.
8. 세이브의 원문·수치 대조 외에 **이전 대화 없는 재개 비교**로 NPC말투/태도·의사소통 방향·합의·이야기 연결·마지막 질문·준비/위험을 실제 이어가는가. 합성 검증과 실제 ChatGPT 검증을 구분하는가.
9. 조기 해결/철수/실패/사망·인물 인계·연대기 챕터가 실제 결과로 처리되고 다섯 후일담이 한 출력씩 이어지며 중복 종료/피해/성장 없는가.
10. 기존 세이브/원문·구판 메뉴·기존 성장/난수·원격 병행 변경을 보존하며 삭제된 새 기능을 가짜빈필드/검사 약화로 숨기지 않는가.

## 20. 실행 순서와 이번 기록의 범위

1. 최신 main/작업 상태와 이 통합 합의를 대조한다. 전체 기존 규칙ID별 유지/이동/통합/자율/삭제 대응을 확인해 영역 검토와 실제 전수 대응 완료를 혼동하지 않는다.
2. 인스트럭션·시작 입력·담당 본문을 함께 편집한다. 한 기능의 수치/예외 소유자는 하나로 유지하고, 삭제된 기능 뒤에 Override나 중복 금지 절을 쌓지 않는다.
3. 색인·카탈로그·검증 계약·관련 예시/개발 문서를 새 구조에 맞춘다. 승인된 의미 변경은 검사 요구도 명시적으로 갱신하되 검증 실패를 감추기 위해 약화하지 않는다. 운영 API/DB 변경은 별도 범위로 남긴다.
4. 대표/경계 사례, check/stats, PI≤7,800 Unicode 문자, export 두 번 ZIP동일/CRC/manifest/소스 일치, git diff --check. 필요한 실제 생성·이어하기 검증은 문서 검사와 구별해 수행/미수행을 기록한다.
5. 원격 변경을 보존·통합한 뒤 필요한 검사/export를 반복하고 룰북+ZIP+DEVLOG를 같은 커밋으로 main에 반영·재확인한다. 강제 푸시하지 않는다.

**통합 실행 적용:** PROJECT_INSTRUCTIONS·START_GAME·rules00~08·색인/카탈로그·검증 계약·관련 검토/예시·배포 ZIP을 함께 갱신한다. 공개 수첩 소스/유지보수 문서는 삭제한다. 기존 지침과 게임용 소스를 새 ZIP으로 함께 교체해야 적용된다. 실제 캠페인 정본/세이브는 별도 보존한다. 공개 저장소/ZIP에 실제 캠페인 비밀·세이브·인증 정보는 넣지 않는다.

세이브 경량화의 보류 항목은 이번에 임의 삭제하지 않고 기존20턴 전체 재독·두 초기 저장·백업 파생 문서를 유지했다. 새 재개 문맥은 실제 지원 계약에서 확인해야 하며 운영DB/외부앱/안전차단 해결은 수행하지 않는다.
