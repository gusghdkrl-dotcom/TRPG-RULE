# 외부 연결 없는 파일 세이브

실행 계약: [STATE_CANON_SAVE_BINDING](../rules/07-state.md#state_canon_save_binding), [STATE_COMMIT](../rules/07-state.md#state_commit), [STATE_RESUME](../rules/07-state.md#state_resume).

## 사용자 흐름

1. `저장`이라고 요청한다. 실제 파일 생성/읽기 도구가 있는 대화에서 키퍼가 현재 상태와 정본을 담은 JSON을 만들고 다시 읽어 검증한다.
2. `TRPG_SAVE_...json` 다운로드 링크를 받아 파일을 직접 보관한다. 링크가 나왔다는 사실은 사용자 기기에 보관됐다는 뜻이 아니다. 원격 접속·계정 연결·새 서버가 필수는 아니다.
3. 같은 룰북을 사용하는 새 채팅에 그 파일을 첨부하고 `이 파일에서 이어서 진행해 줘`라고 요청한다. 프로젝트 소스에 매 저장을 누적 업로드할 필요는 없다. 클라이언트가 첨부/읽기를 지원하지 않으면 해당 환경에서는 복원할 수 없다.

파일에는 미발견 진실도 담기며 소유자가 열면 볼 수 있다. 게임 지문에는 전문을 펼치지 않고 실제 캠페인 세이브·키는 공개 저장소/배포 ZIP에 넣지 않는다. 파일 크기에 관한 특정 ChatGPT 상한을 단정하지 않는다. 이 설계는 100KB 이상 프로젝트 소스 업로드 오류의 원인이나 해결을 입증하지 않는다.

## 무엇을 보존하는가

불변 정본 전문 + 전체 현재 state + 파일 식별/분기/해시를 한 파일에 넣는다. 이전 파일이 없어도 현재 파일 하나로 복원 가능해야 한다. NPC 목소리·관계·지식/약속·대화 대기, 상태의 적용/해제·극중 경과, 완료된 피해·난수·사건, 열린 굴림과 선택을 보존한다. 이미 없는 정보는 보장할 수 없으며 줄거리 요약을 완전한 세이브로 취급하지 않는다.

SHA-256은 payload를 UTF-8/키 정렬/공백 없는 JSON으로 직렬화해 계산하고 canon text의 정확한 UTF-8 해시도 검증한다. envelope 자체의 해시를 자기 안에 넣지 않는다. 해시는 서명·접근 제어·의미 완전성 증명이 아니다. 의미 검증은 실제 현재 상태/정본/필수 ref와 대조해야 한다.

FILE_SAVE_V1 번호는 원격 DB version과 독립이다. 구판으로 돌아가거나 다른 채팅에서 갈라지면 분기를 구분한다. 여러 파일 중 큰 번호/최근 파일명만으로 다른 분기를 덮지 않는다. 실제 원격 전체 상태가 있을 때만 새 파일로 전환하며 원본 history는 보존한다. 파일은 구판 RPC에 전송하지 않는다.

## 기능 부재·실패

실제 생성/해시/재읽기/전달에 실패하면 완료한 단계와 실패 범위를 짧게 알리고 현재 확인된 상태로 플레이한다. 일반 일시 오류 최대 1회 재시도, 다음 저장 경계·수동 요청·실제 기능 복구에서 재시도한다. 명시적 안전 차단은 우회하지 않는다. 도구가 없을 때 복사형 전체 텍스트는 비공개 내용이 보인다는 점을 사용자가 선택한 경우에만 제공하고, 검증되지 않은 복구 자료를 정상 세이브라고 하지 않는다.

## 개발 검증

`scripts/file_save.py`는 FILE_SAVE_V1의 구조/직렬화/실제 파일 재읽기를 확인하는 개발용 참조 구현이다. 게임용 ZIP에 설치되거나 일반 ChatGPT에 자동 추가되는 도구가 아니다. 키퍼는 실행 규칙에 적힌 계약과 실제 제공된 Python/파일 기능을 사용한다.

`python3 scripts/test_file_save.py`는 합성 상태의 저장/읽기, 원문과 해시 보존, 손상·중복 키·비정상 값·식별 충돌·누락·덮어쓰기 거부를 확인한다. 참조 구현은 서사적 사실의 누락을 판별할 수 없으며 STATE_INTEGRITY의 의미 대조가 별도로 필요하다. 실제 ChatGPT의 저장 생성·다운로드·재첨부·NPC 말투 재현·원격 연동은 이 테스트로 검증되지 않는다.
