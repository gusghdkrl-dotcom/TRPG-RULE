# 외부 연결 없는 파일 세이브

실행 계약: [STATE_CANON_SAVE_BINDING](../rules/07-state.md#state_canon_save_binding), [STATE_COMMIT](../rules/07-state.md#state_commit), [STATE_RESUME](../rules/07-state.md#state_resume).

## 사용자 흐름

1. `저장`이라고 요청한다. 실제 파일 생성/읽기 도구가 있는 대화에서 키퍼가 현재 상태와 정본을 담은 JSON을 만들고 다시 읽어 검증한다.
2. `TRPG_SAVE_...json` 다운로드 링크를 받아 파일을 직접 보관한다. 링크가 나왔다는 사실은 사용자 기기에 보관됐다는 뜻이 아니다. 원격 접속·계정 연결·새 서버가 필수는 아니다.
3. 같은 룰북을 사용하는 새 채팅에 파일을 직접 첨부하거나, 해당 UI와 실제 보관 파일이 있으면 `Add from library`로 선택하고 `이 파일에서 이어서 진행해 줘`라고 요청한다. 프로젝트 소스에 매 저장을 누적 업로드할 필요는 없다. 클라이언트가 첨부/읽기를 지원하지 않으면 해당 환경에서는 복원할 수 없다.

파일에는 미발견 진실도 담기며 소유자가 열면 볼 수 있다. 게임 지문에는 전문을 펼치지 않고 실제 캠페인 세이브·키는 공개 저장소/배포 ZIP에 넣지 않는다. 파일 크기에 관한 특정 ChatGPT 상한을 단정하지 않는다. 이 설계는 100KB 이상 프로젝트 소스 업로드 오류의 원인이나 해결을 입증하지 않는다.

Library/Space는 보관·파일 제공 경로이고 FILE_SAVE_V1은 내용/검증 형식이다. 실제 보관과 전체 재읽기 여부를 확인해야 한다. 계정에 그 UI가 없거나 파일이 보이지 않으면 직접 다운로드/첨부 경로를 쓴다. 자세한 대안과 공식 근거는 [SAVE_ALTERNATIVES](SAVE_ALTERNATIVES.md)를 참고한다.

## 무엇을 보존하는가

불변 정본 전문 + 전체 현재 state + 파일 식별/분기/해시를 한 파일에 넣는다. 이전 파일이 없어도 현재 파일 하나로 복원 가능해야 한다. NPC 목소리·관계·지식/약속·대화 대기, 상태의 적용/해제·극중 경과, 완료된 피해·난수·사건, 열린 굴림과 선택을 보존한다. 이미 없는 정보는 보장할 수 없으며 줄거리 요약을 완전한 세이브로 취급하지 않는다.

SHA-256은 payload를 UTF-8/키 정렬/공백 없는 JSON으로 직렬화해 계산하고 canon text의 정확한 UTF-8 해시도 검증한다. envelope 자체의 해시를 자기 안에 넣지 않는다. 해시는 서명·접근 제어·의미 완전성 증명이 아니다. 의미 검증은 실제 현재 상태/정본/필수 ref와 대조해야 한다.

구판으로 돌아가거나 다른 채팅에서 갈라지면 분기를 구분한다. 여러 파일 중 큰 번호/최근 파일명만으로 다른 분기를 덮지 않는다. 구판 변환은 사용자가 이미 보유한 전체 원문과 정본을 제공한 경우만 가능하며 원본은 보존한다. 외부 저장·불러오기·백업·재동기화 경로는 실행하지 않는다.

## 기능 부재·실패

실제 생성/해시/재읽기/전달에 실패하면 완료한 단계와 실패 범위를 짧게 알리고 현재 확인된 상태로 플레이한다. 일반 일시 오류 최대 1회 재시도, 다음 저장 경계·수동 요청·실제 기능 복구에서 재시도한다. 명시적 안전 차단은 우회하지 않는다. 도구가 없을 때 복사형 전체 텍스트는 비공개 내용이 보인다는 점을 사용자가 선택한 경우에만 제공하고, 검증되지 않은 복구 자료를 정상 세이브라고 하지 않는다.

## 비공개 기록과 두 파일 전달

[STATE_PRIVATE_WORK](../rules/07-state.md#state_private_work)에 따라 고정 정본은 프로젝트 소스에 두고, 확정된 비공개 변화만 실제 Python 작업 JSON에 일괄 기록·재읽기한다. 변화가 없으면 기록용 도구 호출을 하지 않는다. 공개 HP/SAN/Luck·행동 로그·전체 소지품을 매 턴 파일로 복사하지 않는다. 필요한 공개 판정의 Python 난수 호출은 그대로 수행한다.

정상 저장 시 같은 체크포인트의 전체 JSON과 비공개 MD를 함께 받는다. 전체 JSON에는 공개 진행과 누적 비공개 기록·정본 전문이 모두 들어간다. MD에는 고정 정본과 그 시점의 비공개 상태를 구별해 담고 JSON의 캠페인/분기/번호/해시를 연결한다. JSON은 보관/새 방 첨부, MD는 프로젝트 소스 교체용이다. 매 비공개 변화마다 기기에 다운로드하거나 소스를 교체할 필요는 없다. 프로젝트 소스를 자동 갱신했다고 주장하지 않는다.

비공개 필드가 공개 상태로 전환되면 release로 과거 비공개 덮어쓰기를 해제한다. 이력은 남기고 최신 공개 값은 그대로 따른다. 같은 event 중복·다른 분기·오래된 변경 번호는 덮어쓰지 않는다. 작업 파일 유실 시 빈 파일 재생성으로 숨기지 않으며 확인 가능한 원본/이후 변화만 복구한다. 실행 공간의 영구 보관은 보장되지 않는다.

## 새 방에서 한 번 로드하고 이어가기

최신 JSON을 첨부하거나 지원되는 Library에서 실제 파일을 선택한 뒤 `이 세이브 전체를 읽고 저장 당시 입력 대기부터 이어서 진행해 줘`라고 요청한다. 파일명/첨부 표시만 확인하는 것으로 끝내지 않는다. 최초 전체 읽기에 검증·복기·작업 상태 구성을 묶고 이후에는 확정된 변화를 갱신하며 진행한다. 같은 최신값을 기존 HUD에 표시하되 전체 시트/JSON/비공개 기억 요약을 추가 출력하지 않는다. 예를 들어 로드 당시 HP 8에서 피해 2가 확정되면 현재 HP와 HUD는 6이며, 과거 파일의 8을 다시 현재값으로 적용하지 않는다.

비공개 정본은 등록된 동일 판본 프로젝트 소스를 기본 조회 경로로 둔다. 파일 안의 정본 전문은 독립 복원과 소스 미등록/접근 불가 시의 동일 판본 사본으로 유지한다. 프로젝트 소스를 다시 읽어도 현재 생사/소모/이동/발견을 초기값으로 되돌리지 않는다. JSON에는 비공개 자료도 포함되므로 공개 상태만 담은 파일로 취급하지 않는다.

일반 턴마다 세이브 재읽기·전체 검증을 하지 않는다. 실제 유실/충돌이면 현재 문맥과 이후 확정 변경부터 확인하고 부족한 범위만 복구한다. 비공개 정본 20턴 재독·30턴 저장 검증 등 기존 경계는 유지한다. 긴 대화에서 무손실 기억이나 실제 도구 호출 횟수를 보장하지는 않는다.

## 복원 범위 대조

신규 FILE_SAVE_V1에는 [STATE_RESTORE_CONTRACT](../rules/07-state.md#state_restore_contract)의 `continuity.version=RESTORE_V1`이 포함된다. 실제 저장 전 원본과 파일을 비교하고 11영역·전체 경로/단일 값 해시·정본 목록·참조·장면/입력 담당/대기 절차/마지막 공개 출력을 검사한다. 신규 파일은 빠진 영역을 빈값으로 메워 통과시키지 않는다. 구판의 계약 부재는 곧 손상이 아니며 실제 원문과 누락 범위를 점검해 새 분기로 변환한다.

[복원 충실도 점검 결과](SAVE_FIDELITY.md)에 재현한 결함·합성 시험·실제 세션 확인 절차를 기록했다.

## 개발 검증

`scripts/file_save.py`는 FILE_SAVE_V1의 구조/직렬화/실제 파일 재읽기를 확인하는 개발용 참조 구현이다. 게임용 ZIP에 설치되거나 일반 ChatGPT에 자동 추가되는 도구가 아니다. 키퍼는 실행 규칙에 적힌 계약과 실제 제공된 Python/파일 기능을 사용한다.

`scripts/private_state.py`는 비공개 변화 일괄 기록·소스 투영의 개발 참조이며 게임 ZIP에 자동 설치되지 않는다. `test_private_state.py`는 무변화 I/O 없음·묶음 기록/재시도·파일 유실·공개 전환·두 파일 일치·다른 분기/시점 거부를 합성 데이터로 확인한다. `render_source`는 검증한 같은 payload에서 생성하므로 순환 해시가 없다.

`python3 scripts/test_file_save.py`는 합성 상태의 저장/읽기, 원문과 해시 보존, 손상·중복 키·비정상 값·식별 충돌·누락·덮어쓰기 거부를 확인한다. 저장 원본과의 불일치·등록된 경로의 누락·잘못된 재개 연결을 거부한다. `capture_continuity`와 `write_verified`에는 저장 전에 확보한 `source_state/source_canons`를 전달한다. 일반 `decode`는 RESTORE_V1을 요구하며 `inspect_legacy`는 구판의 구조 확인 전용이다. 참조 구현은 원본에서부터 누락된 서사적 사실을 판별할 수 없으며 STATE_INTEGRITY의 의미 대조가 별도로 필요하다. 실제 ChatGPT의 저장 생성·다운로드·재첨부·NPC 말투 재현·Library/Space 보관은 이 테스트로 검증되지 않는다.
