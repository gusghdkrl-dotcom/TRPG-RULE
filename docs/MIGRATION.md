## 블록 추적

rule-migration.json은 원본 주 룰북의 SYSTEM_LOCK/SYS_RULE/SYS_DIRECTIVE 403개 블록을 전부 분류한다. `original_line_normalized`는 원문의 잘못된 리터럴 줄바꿈 두 곳을 실제 줄바꿈으로 정규화한 뒤의 줄 번호다. `source_sha256`은 해당 블록에서 태그/구분선만 정리한 본문의 UTF-8 hash이며 원본 파일 전체 hash가 아니다.

- 정리·이동: 의미·수치 보존을 중심으로 태그·이력·참조와 삭제 기능에 종속된 표현을 정리했다.
- 재작성: 중복·충돌 또는 사용자 변경 범위를 현재 절차로 합쳤다.
- 통합: 다른 규칙/새 공통 절차로 옮겼다.
- 삭제: 명시적으로 제거한 기능 또는 그 기능에만 필요한 분기다.

비공개 저장의 별도 계약은 STATE_AUTHORITY/SCHEMA/IDENTITY/INTEGRITY/CADENCE/COMMIT/RECOVERY/RESUME/COMPATIBILITY로 통합했다. 공개 지도·시각 정체성·수첩 상태는 각 전문 문서와 STATE_SCHEMA에서 다룬다. 오래된 필드의 의미를 바꿔 재사용하지 않는다.

## 기존 세이브

2026-10-30의 저장 복기 패치는 기존 verified 전체 원문·registry를 사용하며 별도 서버나 비밀 메모리 필드를 추가하지 않는다. 이미 끝난 30턴 저장을 소급 반복하지 않고 다음 정상 경계에 복기를 연결한다. 기존 NPC 질문 대기·원래 선언·미저장 진행은 보존하고, 앞선 키퍼가 대신 말한 내용을 확인 없이 과거에서 지우거나 새 답변으로 덮어쓰지 않는다. 이후 장면부터 새 답변/수락은 플레이어에게 돌린다.

판정/비공개 작업 상태 분리 패치는 새 DB 스키마나 실시간 캐시 서버를 설치하지 않는다. 기존 exact 상태에서 STATE_WORKING_CONTEXT의 관련 범위를 구성하며 모르는 비밀·기능 값·예정 사건을 추측해 채우지 않는다. 현재 진행과 미저장 변경분이 있는 채로 최신 저장 전체를 다시 로드해 덮어쓰지 않는다. 이미 확정한 판정 결과를 자료조사/역사 구분 정정 때문에 소급 재굴림하지 않으며, 열린 판정은 실제 pending을 확인한 뒤 변경이 필요하면 플레이어에게 정정 이유를 알린다.

이번 문서 개편은 DB migration이나 데이터 삭제가 아니다. 기존 verified 저장의 필드·hash·version을 변경하지 않는다. 삭제된 모드·MP를 사용하는 구판 캠페인은 구판으로 이어가거나 별도로 합의한 변환을 거쳐야 한다.

새 문서판과 DB schema version을 혼동하지 않는다. 실제 서버가 새 상태를 허용하는지 확인해야 한다. 특히 MP 필수 여부, 영구 프로필 검사, 종료 처리의 보상 의존성, 공개 수첩 입력 검증기를 확인한다. 가짜 빈 값으로 기존 검증을 통과시키지 않는다.

## 실제 연동 검증 범위

이 작업에서 Supabase·Render·수첩 앱의 실행 도구가 제공되지 않았다. 문서의 함수·프로젝트 식별은 기존 계약에서 유지한 것이며 실시간 존재/권한/호환성 확인 결과가 아니다. 실제 새 캠페인 전체 payload의 pending → verify → 동일 version read-back → 새 채팅 복원은 별도의 연결 환경에서 검증해야 한다.

## 플레이 개선판 적용

최신 ZIP의 sources 10개와 PROJECT_INSTRUCTIONS를 함께 교체한다. 새 게임은 최신 START_GAME 양식에 필수 시드 두 개·인원·인지도·규모를 입력한다. 배제할 세계관·직접 지정·사전 관계는 비워 두면 자동 `없음`이다. 이미 시작한 캠페인은 새 게임 입력으로 재생성하지 않는다. 기존 규칙판·참가 슬롯·확정 세계·진행 대기를 먼저 확인한다.

프로필 표시를 간소화해도 이미 존재하는 사람·약속·관계나 PC가 정한 성향을 지우지 않는다. 기존 verified 프로필 원문/hash는 보존한다. 진행 중 캠페인의 연출·업무 압축 개선은 현재 사실을 보존하는 범위에서 적용할 수 있으나, 삭제한 모드/자원을 쓰는 세이브의 변환은 별도 호환 확인이 필요하다. 이번 피드백 로그에는 삭제 대상 자원이 남아 있어 최신 문서가 실제 세션에 적용됐다고 확인할 수 없다.

이미 30턴을 넘겼다면 과거 턴을 재연하거나 설정을 뒤집지 않는다. 현재 사실·NPC 목적·약속에서 다음 접촉과 가능한 선택을 복구한다. 실제 기존 인과가 없는 새 사건을 과거부터 있었던 일로 추가하지 않는다.

## 외형·시각 자료·직업 개선

신규 PC는 기본정보 뒤 특성을 먼저 선택하고, 확정 APP를 반영해 배우 참고와 외형을 완성한다. 기존 PC의 외형·배우·직업과 verified 저장 원문을 패치 때문에 자동 재작성하지 않는다. 외형 재설정을 사용자가 요청했다면 해당 범위만 명시적으로 갱신한다.

새 직업 후보는 A/B 기본, C/D 원작 테마 연결, E/F 자유형 조커로 생성한다. 특별 역할의 의무 배치와 추가 후보군 확장을 철회한다. 이미 공개된 후보의 문자·순서·직함이나 선택 완료 직업은 조용히 다시 뽑거나 바꾸지 않는다. 웹 참고 이미지는 출처와 참고 용도를 유지하며 기존 수첩 서버가 이를 구분할 수 없으면 실제 PC 초상·지도 슬롯에 대신 넣지 않는다.

## 공개 지식·조회·Spotlight 개선

현행 패치는 진행 중 캠페인의 다음 작업 상태부터 적용할 수 있다. verified 원문·hash·version을 고치지 않는다. 공개 사실만 stable ref와 출처를 보존해 합치고, PC별 발견 기록을 세계 비밀 전체의 공개로 확대하지 않는다. 과거 개인 Scene 표식은 새 열람 제한에 사용하지 않는다. NPC는 실제 인지한 지식만 유지한다.

진행 중 굴림·인계·병렬 시간 구간은 의미와 실제 경과분을 유지해 이어간다. 이전 로그에 명확한 Spotlight 선택·결과 기록이 있으면 횟수를 복원하고, 없는 과거 횟수는 추측하지 않는다. 짧은 이동과 3/5 교대 기준은 새 선언부터 적용하며 이미 확정한 이동·턴·시간을 되돌리거나 다시 계산하지 않는다.

라우팅을 위해 DB 테이블/필수 컬럼을 추가하지 않는다. 작업 상태·진행 예산·공개 사실은 실제 저장 계약이 허용하는 기존 의미 범위에 보존한다. 복원/저장 검증은 계속 필수이며 일반 지문마다 latest load를 반복하지 않는다. 수첩 앱에 파티 공통 정보가 실제 표시되는지는 해당 앱/단일 Writer 계약을 따로 검증한다.

## 서술·자료 본문·이동 연속성 개선

이번 개선은 진행 중 캠페인의 다음 출력부터 적용할 수 있다. 실제 읽는 자료의 이미 확정된 원문·숫자·핵심 의미는 유지한다. 기존 단서가 의미만 정해져 있었다면 그 범위 안에서 최초 본문을 구체화해 보존하며, 유실된 원문을 새로 만드는 방식으로 복구하지 않는다.

시간 분 수에 따른 병렬 선언 강제를 제거했다. 기존 pending에 실제로 받은 행동은 보존해 남은 구간만 처리하고, 받지 않은 다른 PC의 행동·대사를 보충하지 않는다. 문체와 UI 변경 때문에 Spotlight 횟수·시간·판정·저장 원문을 초기화하거나 과거 결과를 다시 실행하지 않는다.

## 채팅 HUD 서식

새 HUD는 기존 값과 공개 범위를 그대로 읽어 아이콘·표·목록으로 표시한다. 기존 세이브의 수치·소지품·턴·Focus/Gate를 서식 변경 때문에 갱신하지 않으며 새 상태 필드는 요구하지 않는다. 표가 지원되지 않으면 수치 세 줄로 대체한다. 외부 수첩 앱의 CSS나 화면을 배포한 변경은 아니다.

HUD 감시기를 사용하는 경우 `P[N]`, `Scene Turn`, `HP/SAN/Luck`와 실제 수치가 새 표/목록에서도 해당 슬롯에 정확히 연결되는지 실제 감시기에서 확인해야 한다. Markdown 변경만으로 파싱·ACK 성공을 주장하지 않으며 기존 단일 Writer 계약을 유지한다.
