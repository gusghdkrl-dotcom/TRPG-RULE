# 파일 세이브의 경험 연속성 점검

2026-11-07. 실제 캠페인 세이브는 제공되지 않았다. 최신 main의 문서와 참조 구현을 검토하고 가상 데이터로 저장/복원을 시험했다. 실제 사용자 세션을 복원했다는 보고가 아니다.

## 발견한 빈틈

이전 `scripts/file_save.py`는 식별·정본 전문/해시·전체 payload 해시와 기본 상태를 검사했지만 critical_state_registry의 이름에 대응하는 실제 데이터 존재를 검사하지 않았다. 기존 합성 fixture에서 `pcs`, `npcs`, `pending`, `rng`, `timeline`을 각각 지우고 외부 payload 해시를 다시 계산했을 때 5건 모두 정상으로 읽혔다. 파일이 손상되지 않았다는 것과 진행을 빠짐없이 담았다는 것은 달랐다.

기존 본문에는 NPC 말투/관계/기억·상태 효과·열린 절차 보존 지시가 이미 있었다. 이번에는 그 의무를 저장 직전 원본과 실제 파일의 대조, 명시적인 범위·경로·재개 지점 검사로 연결했다. 일반 턴의 규칙 라우팅이나 게임 수치를 변경하지 않았다.

## 보완한 계약

[STATE_RESTORE_CONTRACT](../rules/07-state.md#state_restore_contract)가 FILE_SAVE_V1의 `continuity.version=RESTORE_V1`을 정의한다. 11영역, 모든 state 최상위 namespace의 실제 JSON Pointer, 전체 경로의 타입/구조/값 해시, 정본 목록, entity 연결과 입력 대기 경계를 저장한다. 목록에는 긴 본문을 중복 저장하지 않는다. 이 정보는 검사 자료이며 새로운 게임 상태나 점수가 아니다.

개발 참조 구현의 순서:

1. 실제 최신 작업 상태와 미저장 변화를 합친 전체 원본을 먼저 동결한다. 실제 참조 정본 전문도 확보한다.
2. `capture_continuity(payload, source_state=..., source_canons=..., domains=..., resume=..., references=...)`로 원본과 payload를 대조하고 계약을 생성한다. source에 이미 요약한 payload를 다시 넣는 것으로 실제 원본 비교를 대신하지 않는다.
3. `write_verified(path, payload, source_state=..., source_canons=...)`가 원본과 다시 대조한 뒤 파일 생성·전체 재읽기를 검사한다. 같은 파일에 다른 상태를 덮지 않는다.
4. 새 프로세스의 `decode(raw)`도 계약을 요구한다. `inspect_legacy(raw)`는 구판의 구조 검사 전용이고 정상 복원 완료를 뜻하지 않는다. 원본 파일을 보존한 상태에서 실제 사실을 대조한 뒤 새 분기로 변환한다.

이 함수들은 개발 도구다. 프로젝트 ZIP에는 자동 설치되지 않으며 게임에서는 실제 제공되는 Python/파일 기능으로 실행 본문의 계약을 수행해야 한다.

## 실행한 합성 시험

`python3 scripts/test_file_save.py`의 12개 테스트 그룹에서 다음을 확인한다.

| 대상 | 확인 결과 |
|---|---|
| 원본에서 저장/재읽기 | 전체 state·정본·알려지지 않은 확장 필드 동일, 동일 파일 재전달 가능, 다른 내용 덮어쓰기 거부 |
| 5개 핵심 영역·NPC 말투/지식·소지품·효과 기한·세계 경로·마지막 공개 출력 삭제 | 바깥 해시를 다시 계산해도 동결 증거 불일치로 거부 |
| state 해시만 갱신 | 저장 전 경로별 inventory와 불일치하면 거부 |
| 필수 영역/경로·입력 담당·절차 상태·대상 ID 연결 불일치 | 새 state inventory를 만들었어도 계약 불일치로 거부 |
| 내부적으로 유효하지만 실제 source와 다른 상태 | 파일 생성 전에 거부 |
| 구판·정본 판본 변조·잘림·중복 키·NaN/Infinity·안전하지 않은 파일명 | 구판은 구조 검사만 허용, 나머지는 검사 실패 |
| 한글·100KB 초과 합성 본문·빈 배열·null·0·false·특수 키 경로 | 직렬화/재읽기에서 값과 타입 보존; 업로드 성공을 검증한 것은 아님 |
| setup/action/roll/choice/handoff/reaction/visual/resolve/ended | 동일 입력 경계의 상태 보존, 불명확 실행을 입력 대기로 바꾸지 않음 |
| 부모 파일 없는 새 Python 프로세스 | 사망 NPC·개별 지식/말투·소모품 0·해제한 젖음·남은 효과 12분·처리 난수·열린 원값·시각 43분 등 원본과 완전 일치 |

마지막 시험은 **기록이 보존됨**을 확인한다. 실제 ChatGPT가 난수를 재굴리지 않았거나 정확히 같은 말투로 다음 장면을 썼음을 시험한 것이 아니다. 해시/목록 자체까지 잘못 만든 파일, source부터 빠진 사실, 거짓 부재 선언은 해시로 판별할 수 없다. STATE_INTEGRITY의 실제 진행 대조는 계속 필요하다.

## 실제 세션에서 남은 확인

실제 세이브와 저장 직전 대화/상태가 확보되면 동일 체크포인트로 아래를 확인한다. 비공개 자료를 공개 저장소/룰북 ZIP에 올리지 않는다.

- PC 시트·HP/SAN/Luck·소모품·생사·위치·시각·목표가 저장 전과 같은가.
- NPC별로 확립된 호칭/말투·관계·기억·아는 사실/모르는 사실·마지막 질문이 유지되는가. 없던 말버릇·전지적 지식이 추가되지 않는가.
- 단서 본문과 이동, 세계 사건 취소, 닫힌 길, 이미 막아 낸 위험이 되돌아가지 않는가.
- 상태의 실제 영향·남은 경과·해제 여부, 적용한 피해/행운/성장/난수가 유지되고 재처리되지 않는가.
- 첫 재개에서 같은 PC에게 같은 입력을 기다리는가. 새 장면/선택/대사를 먼저 진행하지 않는가.
- 프로젝트 규칙판·표현 설정을 함께 확인했는가. 파일 전체 읽기·사용자 다운로드/재첨부·Library 보관이 실제로 되는가.

목표는 같은 사실·인물성·세계 인과·선택 상황에서 이어가는 것이다. 모델이 달라지거나 같은 모델을 다시 호출해도 미래 문장/대사/연출은 달라질 수 있다. 실제 이미지 원본이 없는 경우 동일 그림도 보장하지 않는다. 저장 뒤 미저장 진행과 원본에서 이미 유실된 사실은 파일만으로 복원할 수 없다.
