# 룰북·현재 작업 상태·Supabase의 역할

이 문서는 사용 방식과 구현 한계를 설명한다. 실제 캠페인의 비밀·저장 원문을 담지 않으며 게임용 ZIP에는 포함하지 않는다. 실행 규칙은 PROJECT_INSTRUCTIONS와 STATE_WORKING_CONTEXT / STATE_ACCESS_ROUTER / INVESTIGATION_SKILL_ROUTING에 있다.

## 무엇을 어디서 보는가

| 필요한 정보 | 첫 출처 | Supabase 접근 |
|---|---|---|
| 판정 필요 여부, 어떤 기능인지, 성공 단계, 교대 규칙 | 프로젝트의 해당 룰북 절 | 규칙 확인에는 사용하지 않음 |
| PC의 자료조사 수치·행운·현재 위치 | 현재 작업 상태의 PC 시트 | 필요한 값이 실제 유실/충돌한 경우만 복구 |
| NPC 목적·비밀, 증거의 배치·본문 | 생성/로드한 현재 세계 상태 | 이번 장면에 필요한 원본이 없을 때만 복구 |
| 다른 장소의 예정 사건·위협 진행 | 활성 원인들의 다음 발동 조건/시각과 관련 상태 | 필요한 색인/조건이 없을 때만 복구 |
| 새 채팅 재개, 저장/검증, 실패 복구, 명시적 저장 대조 | 실제 Supabase 저장 계약 | 해당 작업에 필요한 접근 수행 |

자료 찾기 선언의 정상 흐름은 다음과 같다.

1. 허락·접근 조건·현재 방법을 작업 상태에서 확인한다.
2. 판정 필요 여부는 FICTION_FIRST_ROLL_TRIGGER_GATE, 기능은 INVESTIGATION_SKILL_ROUTING을 적용한다. 문서에서 기록을 찾는 일은 자료조사, 시대적 의미의 전문 해석은 역사다.
3. 판정이 필요하면 현재 PC 시트의 해당 수치와 실제 실패 결과를 사용해 d100을 요청한다. 규칙 본문과 상태가 이미 있으면 규칙 검색도 DB 조회도 0회다. 아직 필요하지 않은 기사 전문이나 흑막 이력을 전부 불러오지 않는다.
4. 굴림 뒤 실제 시간·결과를 반영하고 읽을 수 있게 된 자료 원문을 제시한다. 원문이 이미 있으면 재사용하고, 없으면 필요한 ref를 복구한다. 읽는 행위만으로 저장을 추가하지 않는다.

권한이나 기능 수치가 없는데도 무조건 조회 0회로 밀어붙이지 않는다. 현재 필요한 정보와 없는 이유를 구분해 관련 범위만 복구한다. DB가 부분 조회를 지원하지 않으면 정확한 저장본 한 번에서 필요한 데이터를 가져와 재사용하며, 새 조회 API가 생긴 것처럼 지시하지 않는다.

## 비공개 상태를 AI가 알고 있는가

모델은 실제 생성했거나 도구로 읽어 현재 입력 문맥에 남아 있는 상태를 사용할 수 있다. Supabase에 있는 모든 행이 자동으로 모델의 기억이 되지는 않는다. 룰북에 GM_STATE라고 적는 것만으로 별도의 메모리 서버나 비밀 파일도 생기지 않는다.

현재 배포물은 Markdown 지침/룰북과 배포 검사 스크립트다. 모델 문맥은 독립적인 영구 저장소가 아니며, 대화 압축·새 채팅·문맥 한도로 상세 데이터가 빠질 수 있다. 비공개 추론도 게임 상태를 보존하는 저장 API가 아니다. 따라서 “한 번 로드하면 캠페인 내내 절대 잊지 않는다”는 보장은 하지 않는다.

키퍼가 계속 추적해야 할 범위는 출처/버전과 미저장 변경분, 각 PC의 정확한 수치/위치/진행 대기, 불변 세계의 핵심 제약, 관련 장소/NPC/단서, 다른 장소도 포함한 예정 사건의 발동 조건과 처리 여부다. 매 턴 전체를 다시 쓰지 않고 실제 결과의 변경분을 반영한다. 게임 시간이 경과할 때 예정 사건을 확인하므로 플레이어가 채팅을 보내지 않는 현실 시간에 별도 프로세스가 계속 돌고 있다는 뜻도 아니다.

공개된 지문에 비밀을 숨겨 적거나, 수첩/프로젝트 소스/GitHub에 비밀 요약을 올리는 방식은 사용하지 않는다. 현재 키퍼용 데이터가 있다고 해서 플레이어 화면으로 공개해도 된다는 뜻은 아니다. 이 규칙의 공개 범위는 게임 진행 규약이며, 클라이언트의 도구 결과 표시나 계정 접근권을 기술적으로 차단하는 보안 구현은 아니다.

## 현재 적용과 더 안정적인 구조

현재는 실제 로드된 문맥을 재사용하고, 필요한 값이 빠졌을 때만 복구하며, 기존 검증 Checkpoint 경계를 유지한다. 새 채팅에서는 검증된 저장본부터 재개한다. 마지막 저장 이후 변경분을 잃었다면 과거 저장과 현재 상태를 임의로 섞지 않고 복구 가능한 지점을 분명히 한다.

장기적으로 비공개 상태의 누락을 줄이려면 모델 밖의 **키퍼 전용 실행 서비스**가 더 안정적이다. 이 서비스가 권한 있는 작업 상태와 변경 기록을 보관하고, 실제 게임 시간에 도달한 사건 및 현재 장면에 필요한 정확한 상태를 응답마다 모델에 제공하며, 기존 Supabase commit/verify를 담당하는 구조다. 모델이 매 턴 DB 전체를 직접 검색할 필요를 줄일 수 있다. 다만 서비스/API/접근권/충돌 처리와 실제 성능 검증이 추가로 필요하며 현재 저장소에는 구현하지 않았다.

## 검증 범위

사용자가 보고한 합본 열람 응답은 약 64초였다. 제공된 텍스트에는 규칙 검토가 보이지만 실제 RPC명·횟수·시간은 없어 Supabase 호출 여부나 병목은 확정할 수 없다. 현재 변경은 조회 기준과 상태 유지 계약을 명확히 한 것이며, 실제 게임 모델의 기억·응답 시간 또는 운영 DB를 실행 검증한 결과가 아니다. 측정은 RESPONSE_TIME.md를 따른다.
