# TRPG-RULE

**2026-11-10 게임 규칙 통합 패치:** 장비 장착 4분류/상시 HUD, PC 선택지 대사 직접화법, 상점 실제 재고·구매/판매·고유 의뢰, 직업 A~F6개, 대표 원작 적+창작 적 비공개 실행 프로필, Hard/Extreme 자동 추가 버프 삭제 및 01 Critical/100 Fumble만 특별 처리. 난이도·대항·명시된 영구 강화 카드 효과 및 기존 상태를 유지한다.

일반 ChatGPT 프로젝트 채팅에서 사용하는 한국어 AI 키퍼용 생존 호러 룰북이다. 별도 게임 앱/서버를 만드는 프로젝트가 아니다.

현재 판은 **생존 호러 통합 경량판 2026-11-08**이다. 인스트럭션은 스토리 진행·실제 위협·선택·페이싱을 우선하고 공간·행동·대사·감각의 구체적인 서술 원칙을 상시 유지한다. 룰북은 상황별 수치/절차/예외를 담당한다. 원작 요소가 실제 접촉·생존·발견·목표 변화·큰 난관과 해결로 이어지도록 세계를 설계한다.

## 설치와 교체

**[최신 프로젝트 ZIP 다운로드](https://github.com/gusghdkrl-dotcom/TRPG-RULE/raw/refs/heads/main/dist/TRPG-RULE-project.zip)**

별도 신규 캠페인: **[SCREAM_survival_rebuild_project.zip 다운로드](https://github.com/gusghdkrl-dotcom/TRPG-RULE/raw/refs/heads/main/dist/SCREAM_survival_rebuild_project.zip)**. 사용자가 이 패키지만 예외로 공개 승인했다. 범인·숨은 설정을 포함하므로 플레이어는 먼저 PLAYER_BRIEFING.md를 확인한다. 공통 룰북 ZIP과 별도이며, 기존 캠페인 정본/진행을 교체하는 세이브가 아니다.

1. ZIP의 PROJECT_INSTRUCTIONS.md를 프로젝트 지침에 복사한다.
2. 기존 게임용 룰북 소스를 제거/교체하고 sources의 **9개 Markdown(00-index~08-visual)**을 등록한다. 구판·개발 문서·삭제된09-notebook을 함께 남겨 검색이 섞이지 않게 한다. 실제 캠페인 비공개 정본은 별도로 보존한다.
3. START_GAME.md로 새 게임을 준비한다. 필수는 인원1~3·인지도·대사건/연대기. 시작 시드는 실제 Python 자동 생성이다.
4. 기존 게임은 새 설정을 실행하지 말고 저장본이 지정한 정본과 누적 상태로 복원한다. 확정된 세계/PC/성과·구판 세이브를 소급 덮지 않는다. 규칙 전환은 STATE_COMPATIBILITY를 따른다.

ZIP에는 실행 지침·시작 입력·게임용 소스·업로드 안내·SHA256.json만 포함한다. 개발 일지/검토/과거 자료·실제 캠페인 비밀/세이브/인증 정보는 포함하지 않는다. 파일 업로드·프로젝트 도구 지원 여부는 실제 클라이언트 환경에 따른다.

## 이번 판의 주요 변경

- **2026-11-10 패치:** 신규 PC 시작 장비를 직업 관련 필수 물품 정확히1개로 제한하고, 추가 장비는 실제 세계의 발견·파밍·거래·수리·협력으로 얻는다. 별도 전문 분야 선택 및 연대기 전문성 성장 규칙은 신규 생성에서 제거했다(구판 확정 정보 보존). 판정 발동은 의미 있는 불확실성/실패 위험·실제 대립·규칙상 발동·제한적 극적 우연의 네 가지로 정리하고, 무관한 판정/임의 보상/강제 피해는 금지한다.

- 이후 신규 세계는 초반 귀가/우회·관여 축소와 의도적 탈출도 위협·대응·실패가 있는 생존 경로로 준비한다. 위험권/출구·경로별 추적/차단/노출·우회/준비·실패 결과·바깥 안전을 정본에 연결하고 실제 위해는 HP/SAN·부상/광기·소모·사망 가능성까지 처리한다. 떠나겠다는 선언/교통편 확보만으로 엔딩을 주지 않으며 실제 이탈 실패와 잔존 상태도 유지한다. 고정 피해·사후 봉쇄·확보한 안전 취소는 없고 기존 캠페인은 재설계하지 않는다.

- 이후 신규 캠페인은 공포의 형상/공간·행동과 원작의 의미를 실제 체험에 연결하고, 앞선 경험·관계·준비가 결정적 대응에서 하는 일을 구체화한다. 의식/장치 절차와 마지막 회상만으로 대체하지 않는다. 동기 복잡화·충격적 반전·모든 물품/인물 사용은 의무가 아니며 간단한 예방/해결도 인정한다. 기존 캠페인과 새 채팅 재개는 이 보강으로 재설계하지 않는다.

- 시나리오의 운용 조건과 서사 깊이를 함께 설계한다. 주요 진실이 겪은 현상/물건/인물의 의미·관계 선택·위험/대응/대가·결말을 바꾸게 하고, 준비·관계·선택을 절정에서 활용한다. 피해 대상 수·작업량·뒷설명만 늘리는 설계와 모든 원작에 같은 반전/배신/우주적 재앙을 붙이는 설계는 보완한다. 조기 이해/예방·실제 안전은 유지하며 새 보스로 연장하지 않는다.

- 새 캠페인과 주요 미확정 국면은 원작의 깊은 원인→직접 경험/난관→변화 조건·대응→준비/관계가 바꾸는 결과→실제 해결/안전/탈출이 정본 본문에 연결돼야 설계 완료로 판단한다. 가능성만 적힌 주요 빈 연결은 관련 부분만 보완한다. 매 턴 전수 검토·고정 보스전·강제 피해·전모 공개·구판 세계 초기화는 요구하지 않는다.

- [원작 체험형 공통 기반](docs/EXPERIENCE_FIRST_FOUNDATION.md)으로 생성·진행을 재구성했다. 살아 있는 세계와 당면 목적/상황망을 먼저 설계하고 행동·관계·수단 선택의 실제 결과로 다음 상황을 잇는다. 추리·미스터리는 대응/신뢰/목표를 바꾸는 요소이며 진상 입증·서류 대조를 일반 진행/종결의 필수 경로로 삼지 않는다.
- [승인된 UI 고정 서식](docs/HUD_PREVIEW.md)을 사용한다. 세로 알약형 선택 버튼·단일 상태 카드·HP/SAN/Luck3열·시각/위치/상시 현금·메인/파우치/실제 중요 물품 순서를 유지한다. 미지급 대금과 잔액을 구분하고 같은 물품을 재분류/중복 표시하지 않는다. 실제 UI 미지원 시 동일한 의미/순서의 Markdown으로 대체하며 선택지5개 고정·가짜 클릭·저장 알림을 위한 도구 호출은 없다.
- 인스트럭션은 최우선 기준→진행 순서/조회 조건→생성·플레이·압축·NPC·서술의 적용 상황→연속성/종결→라우팅→출력으로 정리했다. 세계 설계의 적용 범위, 장면을 펼칠 기준, 압축 중 입력받을 경계, 필요한 본문 조회/실패 처리 조건을 명시한다.
- 키퍼 원칙·숙지 문구의 매 응답 반복 출력을 제거했다. 원작 체험·능동적 세계 반응·장면의 호흡·필요 규칙 적용은 상시 인스트럭션 본문에 유지한다. 버튼/상태 패널·자원 아이콘·메인/파우치와 HUD 본문18px/자원24px·Markdown3/4단계 표시 규약은 유지한다.
- 네 원칙은 원작 체험·능동적 세계 반응·다양한 플레이와 호흡·전 과정의 규칙 적용으로 구분한다. 조사는 다음 행동을 바꾸는 핵심 정보에 집중하고 키퍼가 추가 검증을 계속 요구해 절차를 늘이지 않는다. 핵심 난관과 플레이어가 선택한 심층 탐구는 유지한다.
- 상시 인스트럭션에서 보조 업무의 목적 단위 처리와 중심 사건 복귀 기준을 구체화했다. 사소한 확인마다 입력 대기를 만들지 않으며 지문·NPC 대사·HUD의 추리 평가/검증 안내를 금지한다. 중요한 선택·교류·협상과 실제 새 비용/위험은 보존한다.
- 생존 국면은 초반·최종전 사이의 탐구/이동/대면/구조/탈출에도 이어진다. 원작·인과에 맞는 직접 위협과 적격 SAN 노출, 실제 피해/상태를 처리하며 필요한 규칙 본문이 없으면 결과 확정 전에 조회한다. 유효한 예방·안전·손실 회피는 인정한다.

## 도구·저장과 검증 범위

PC d100은 플레이어, 그 밖의 실제 무작위는 Python 실행을 사용한다. 실제 입력 폼이 없으면 채팅 입력으로 진행한다. 룰북은 클라이언트에 없는 입력/검색/파일 기능을 만들지 않는다.

저장 수단은 **비공개 프로젝트 정본 + 새 Supabase `trpg-state-v2` 검증 체크포인트(DOCUMENT_BOUND/DB1, `state_schema_version=TRPG_STATE_V2`) + 인증된 비공개 GitHub 백업/비상본**이다. 신규 Supabase project ref는 `taoaffdyssqtnjszumpq`이고, 서버 RPC와 정확한 호출/검증/복원 계약은 [07-state](rules/07-state.md)의 STATE_CANON_SAVE_BINDING·STATE_COMMIT에 있다. [DB V2 재구축 SQL](docs/sql/trpg-state-v2.sql)은 구형 DB를 복제하지 않고 독립 구축하기 위한 이력이다. 신규 DB에서 합성 2버전의 commit→verify→같은 version exact read-back/SHA, 부모충돌 차단, 중복attempt 재생, 필수문맥·coverage 거부와 권한 제한을 검증했으며 테스트 저장본은 제거했다. 실제 비공개 캠페인의 정본 결합·장기재개 및 인증된 private GitHub 백업 왕복은 별도 검증이 필요하다. 차단/실패는 완료라 하지 않고 현재 확인 가능한 플레이는 계속한다. 기존20턴 정본 재독·30턴 저장 경계는 유지하고 같은 원문/상태를 재사용한다.
