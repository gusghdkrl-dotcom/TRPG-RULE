# 판정·특성·자원

규칙판: 통합 연출판 2026-10-30. 규칙 ID는 버전과 독립적으로 유지한다. 필요한 절만 조회한다. 전체 경로는 `00-index.md`를 따른다.

## FICTION_FIRST_ROLL_TRIGGER_GATE

적용: 일반 행동의 판정 필요 여부를 정할 때. 전투·SAN의 고유 발생 조건은 전문 규칙을 따른다.
1. 현재 수단·위치·시간으로 불가능하면 굴리지 않는다. 가능한 새 수단을 얻으면 다시 판단한다.
2. 선언·정보·도구·권한·대가로 불확실성이 실제 제거되면 직접 해결한다.
3. 신체·감각·전문 수행의 성공 여부가 여전히 불확실하면 적절한 기능/특성 판정을 요구한다. 자세한 설명이나 충분한 시간만으로 수행 성공을 보장하지 않는다.
4. 판정 전에 실패의 결과를 정한다. 정보·시간·위치·소음·자원·접근·위험 또는 현재 방법의 실패가 실제로 달라져야 한다. 의미 있는 차이도 능력 검증 필요도 없으면 굴리지 않는다.
5. 능력은 기능/특성, 직접 저항은 대항, PC가 통제하지 못하는 외부 우연은 Luck으로 처리한다. 확정 비용을 실패 확률로 바꾸지 않는다.
- 같은 목적의 미세 행동을 쪼개 굴리지 않는다. 새로운 독립 난관이 생길 때 추가 판정한다.
- 같은 조건으로 성공할 때까지 반복 굴리지 않는다. 새 방법·지원·수단·실제 시간 투자·위험 등 조건 변화가 있어야 하며 Push가 적용되면 그 절차를 따른다.
- NPC가 제안을 수락할 이유가 충분하면 사회 판정 없이 반응한다. 실제 저항이 남을 때만 판정한다.
- 정확한 조사 방법으로 은폐가 제거되면 보이는 사실을 제공한다. 미세 감각·전문 분석의 불확실성은 판정한다.
- PC의 값이 없으면 굴림을 요청하고 대기한다. 결과를 먼저 만들지 않는다.

## PLAYER_D100

- PC의 능동 판정은 1d100이며 굴림값이 목표 특성/기능 이하이면 성공 단계에 들어간다.
- PC 굴림은 플레이어가 직접 제공한다. AI RNG 큐를 절대 사용하지 않는다.
- 값이 없으면 ROLL_INPUT_FORM_CONTRACT의 통합 폼으로 판정을 요구하고 결과를 선행 생성하지 않는다.

## ROLL_INPUT_FORM_CONTRACT

PC의 판정 요청은 **굴림 숫자 + 행운 사용 + 실패 시 강행**을 같은 입력 폼에서 한 번에 제출받는다. 신규 판정에서 숫자만 받은 뒤 별도의 행운/강행 선택 화면을 다시 여는 두 단계 질문을 기본 흐름으로 만들지 않는다. 판정 수치·허용 조건은 PLAYER_D100, BONUS_PENALTY_DICE, LUCK_SPENDING, PUSHED_ROLL 등 담당 규칙을 그대로 따른다.

[같은 폼의 필드]
- 기능/특성·공개 가능한 목표·현재 Luck·유불리 개수·필요 굴림 수와 통상 실패의 공개 가능한 결과를 먼저 표시한다. 기본 d100 및 필요한 추가 d100 원값을 각각 1~100 정수 입력칸으로 받는다. PC 굴림을 AI가 대신 생성하지 않는다.
- `☐ 행운 사용 — 가능하면 필요한 최소 점수로 성공 전환`과 `☐ 실패 시 강행 — 아래 방법과 위험으로 재시도` 체크를 같은 폼에 둔다. 둘 다 기본 해제이며 미선택은 사용하지 않음이다. 판정 종류상 금지된 옵션은 선택 불가와 짧은 이유를 표시하거나 숨기고 이유만 적는다. 실제 체크를 지원하는 입력 도구를 사용하고 표시용 체크박스를 작동하는 컨트롤로 가장하지 않는다.
- 행운 체크 옆에는 소비 상한 입력을 둔다. 초기 상한은 현재 Luck이며 사용자가 낮출 수 있다. `필요 최소 비용만, 표시 상한 이내 사용`이라는 동의 범위를 명시한다. 입력값에 따라 계산 가능한 UI라면 최종 판정값 기준 필요 비용과 사용 후 Luck을 같은 폼에서 미리 표시한다. 동적 계산이 불가능해도 상한 동의를 받아 제출 후 계산할 수 있으며 별도 행운 확인 화면을 요구하지 않는다. 숨은 상대 수치·난이도를 비용 미리보기로 노출하지 않는다.
- 강행 체크에는 구체적인 재시도 방법 입력/선택과 그 방법으로 실패했을 때의 더 큰 위험을 함께 둔다. 현재 상황에서 가능한 방법·위험을 미리 제시하고 그 방법을 선택하거나 사용자가 직접 적도록 한다. 체크만으로 미선언 행동을 만들어내지 않는다. 새로운 방법으로 위험이 달라져 사전 안내가 불충분하면 그 변경 부분만 확인하며, 이미 안내·동의한 방법과 위험을 다시 묻지 않는다.
- 두 옵션을 함께 체크할 수 있다. 폼에 **행운으로 성공 전환 우선 → 불가능하면 강행** 순서를 명시한다. 제출 버튼은 하나이며 원값·체크 상태·상한·강행 방법을 같은 현재 판정에 묶는다. 제출 전에 옵션만 바꾸는 것은 판정 확정이나 자원 소비가 아니다.

- LIFESTYLE_BUFFS의 적격 버프가 있으면 같은 폼에 단일 선택을 추가한다. 원래 기능과 버프 적용 목표치를 구분하고 굴리기 전 선택하도록 안내한다. 옵션 미선택은 사용 안 함이며 이 때문에 행운/강행을 별도 화면으로 나누지 않는다.

[제출 후 처리]
1. 현재 PC·열린 판정·입력 개수·범위·옵션 적격성과 동의를 확인하고 보너스/패널티 원값에서 최종 판정값을 계산한다. 잘못된 입력은 해당 필드만 수정받는다. 유효 원값을 다시 굴리게 하거나 수정 중 Luck을 차감하지 않는다.
2. LIFESTYLE_BUFFS의 유효한 사전 선택이 있으면 효과·소모를 반영한 뒤 판정한다. 이 결과가 해당 판정을 성공시키면 행운 차감·강행 없이 바로 결과를 묘사한다. 행운 체크는 성공 단계 올리기나 자동 최대 지출 동의가 아니다.
3. 실패하고 행운이 체크됐으면 LUCK_SPENDING이 허용하는 성공 전환의 최소 비용만 쓴다. 비용이 제출한 상한 또는 현재 Luck을 넘거나 금지 판정/Fumble이거나 Regular 전환으로 해당 요구를 충족하지 못하면 **Luck을 전혀 차감하지 않는다**. 부분 지출·임의 상한 초과·난이도 완화는 하지 않는다. 적용 가능하면 한 번만 차감하고 결과를 확정하며 `행운을 쓰시겠습니까?`를 다시 묻지 않는다.
4. 행운 미사용/적용 불가로 실패가 남고 강행 체크·방법·위험 동의와 실제 재시도 여지가 유효하면 강행으로 바로 이어간다. 첫 실패의 실제 결과·시간·비용은 유지하고 실패 때문에 재시도가 물리적으로 불가능해졌다면 강행하지 않는다. **강행 여부 재확인은 생략하되 새 강행 굴림값은 플레이어에게 받는다.** 최초 값을 재사용하거나 AI RNG로 대신하지 않는다. 강행 입력에서는 추가 강행을 비활성화하며, 기타 옵션은 해당 판정의 기존 허용 범위를 따른다. 이미 제출한 값·동의를 반복 요구하지 않는다.
5. 행운/강행 둘 다 미선택이거나 적용할 수 없으면 생활 버프까지 반영한 이번 굴림 결과를 즉시 처리한다. 후속 일반 행동·상황에 맞는 플레이어의 자발적 강행 제안은 기존 규칙으로 판단하지만, 키퍼가 매 실패마다 별도 사용 여부 질문을 붙이지 않는다. 적용되지 않은 체크는 필요한 이유만 짧게 알리고 선택을 강요하지 않는다.

[입력 도구·대기·복원]
- 현재 클라이언트에 실제 통합 입력 폼 도구가 있으면 그 도구로 만든다. 도구가 없으면 그 한계를 한 번 알리고 `기본 54 / 행운 사용, 상한 9 / 강행 안 함`처럼 동일 항목을 한 메시지로 받는다. 선택 항목을 안내한 신규 요청에 숫자만 오면 둘 다 미선택으로 처리하고 재질문하지 않는다. 코드 블록·HTML·이미지를 실제 입력 폼으로 가장하지 않는다.
- 구판의 이미 열린 Luck 선택은 자동 동의/거부로 바꾸지 않는다. 기존 원값을 보존하고 아직 받지 못한 선택만 한 번 받아 끝낸 뒤 신규 판정부터 통합 폼을 사용한다. 옵션 없는 구판 숫자 응답에 새 미선택 기본값을 소급 적용하지 않는다.
- 기존 진행 대기에 현재 판정 식별·PC·원값·선택·상한·방법/고지 위험·해결 단계를 compact하게 보존한다. 반복 제출·저장/로드가 같은 Luck 지출·첫 실패 결과·강행을 두 번 실행하지 않게 한다. 완료한 판정의 제출은 새 판정값으로 재사용하지 않는다. 별도 DB 호출·새 서버 스키마를 요구하지 않는다. 일반 행동 메뉴와 입력을 섞지 않는다.

## CHARACTERISTIC_VS_SKILL

- 육체적/직관적 한계 시험은 특성치: STR, DEX, CON, INT, POW, SIZ, APP, EDU 등 캐릭터 시트의 핵심 특성.
- EDU는 축적된 교육·학습·직업적 지식의 폭을 나타내며, 즉흥 추리(INT)나 전문 훈련 기능을 공짜로 대체하지 않는다.
- 훈련·전문지식이 필요한 행동은 기능: 의학, 기계수리, 역사, 관찰, 듣기, 잠행, 설득, 격투, 사격 등.
- 플레이어가 다른 기능으로 논리적 우회를 제안하면 물리적 본질이 맞을 때 허용한다.
- 유리한 수치만 쓰기 위한 억지 대체는 거부한다.

## INVESTIGATION_SKILL_ROUTING

조사는 장소나 자료의 연식이 아니라 **선언한 작업**으로 기능을 고른다. 판정 필요 여부는 FICTION_FIRST_ROLL_TRIGGER_GATE가 먼저 정한다.
- 신문 합본·색인·장부·문서 더미에서 원하는 기록을 찾고 대조하는 작업은 `자료조사`가 기본이다. 도서관 이용이라는 표현도 이 기능을 가리키며 새 기능을 만들지 않는다. 오래된 신문이라는 이유만으로 `역사`로 바꾸지 않는다.
- 발견한 기록의 시대 배경·과거 제도·사건의 역사적 의미를 전문 지식으로 해석하는 작업은 `역사`다. 문서 위조·언어·회계 등 다른 전문 수행이면 그 실제 작업에 맞는 기능을 고른다. 기능 수치가 높다는 이유로 대신 쓰지 않는다.
- 이미 찾은 읽을 수 있는 기사·공고의 본문을 읽거나 같은 자료를 재표시하는 데는 찾기 판정을 반복하지 않는다. 해독·손상·언어 등 실제 별도 난관이 있을 때만 추가 판단한다. 찾기에 성공했다고 반드시 역사 판정을 연달아 붙이지 않는다.
- 열람 허락은 접근 문제를 해결한다. 방대한 자료 속 탐색의 불확실성까지 자동 제거하지는 않으며, 반대로 오래된 자료/많은 분량이라는 말만으로 무조건 굴리지 않는다. 실제 찾기 난관과 실패 때 달라질 결과를 현재 상태에서 확인한다.
- 기능 선택·판정 절차의 근거는 룰북이고, PC의 해당 기능 수치·열람 권한·자료 배치·소요시간·실패 결과의 근거는 현재 GM_STATE다. 별도 저장/복구 조건이 없는 일반 판정은 둘 다 확인 가능하면 Supabase 조회는 0회다. 규칙이 없으면 해당 규칙만 읽고, 필요한 상태 값이 없을 때만 STATE_ACCESS_ROUTER로 복구한다. 역사 40만 보인다고 자료조사도 40으로 만들지 않는다.
- 굴림 전에는 그 판정에 필요한 조건만 확인한다. 발견할 기사의 전체 원문이나 흑막의 모든 이력을 판정 요청의 선행 조회로 요구하지 않는다. 다만 판정 조건·실패 결과를 결정할 핵심 상태가 없으면 해당 범위를 먼저 복구한다. 성공 뒤 실제 자료를 제시할 때 원문이 필요하다면 그때 작업 상태에서 찾고, 없을 때만 복구한다.

## STAT_BOUNDARY

- 저항하며 움직이는 생명체를 때림 = 격투. STR로 대체 금지.
- 공격 회피 = 회피. 이동하며 들키지 않기 = 잠행, 몸을 숨기기 = 숨기. DEX 하나로 대체 금지.
- 비생물 파괴/밀기/버티기 등에는 상황에 맞는 특성치를 사용한다.

## CORE_CHARACTERISTIC_REFERENCE

STR 힘, CON 체력·독/질병 저항, SIZ 체격, DEX 균형·손놀림·행동 순서, APP 외양·첫인상, INT 사고·아이디어, POW 의지·SAN, EDU 교육·축적 지식이다.
- 전문 훈련이 필요한 행동은 기능으로 판정한다. EDU/INT가 모든 전문 기능을 대신하지 않는다.
- 공통 표시 기능은 관찰·듣기·회피·격투·사격이다. 시작 수치는 [PC_SKILL_START_VALUES](04-setup.md#pc_skill_start_values) 한 곳에서 정한다. 회피의 기본은 floor(DEX/2)다.

## SUCCESS_LEVELS

LIFESTYLE_BUFFS를 선택한 비전투 기능 판정은 아래 원래 기준을 만든 뒤 그 절의 소규모 목표치 보정을 적용한다. Critical/Fumble은 보정하지 않는다.

01 = Critical.
기능/특성의 원래 수치의 1/5 이하 = Extreme.
기능/특성의 원래 수치의 1/2 이하 = Hard.
기능/특성의 원래 수치 이하 = Regular.
그 초과 = Failure.
Fumble:
- 기능/특성의 원래 수치가 50 미만이면 96~100.
- 기능/특성의 원래 수치가 50 이상이면 100.
- Hard/Extreme 난이도로 목표치가 줄어들어도 Fumble 범위는 줄어든 목표치가 아니라 원래 기능/특성 수치를 기준으로 한다.
- 단계가 높을수록 추가 정보, 무소음, 관통, 시간 절약 등 상황에 맞는 부가 이득을 줄 수 있다.
- 실패는 단순 '아무 일 없음'보다 시간·소음·위치·자원·관계 악화 같은 후속 결과로 변환한다.

## PLAYER_FACING_ROLL_RESULT_RENDER

- 플레이어가 굴림값을 제출한 뒤 Keeper는 성공 단계와 Fumble 여부를 내부적으로 판정하되, 일반 게임 지문에 `59는 20을 넘었으므로 실패`, `Hard 성공`, `Fumble 아님`, 목표치와 굴림값의 대소 비교 같은 계산·분류 로그를 쓰지 않는다.
- 플레이어 출력은 그 판정 단계가 만든 **세계의 직접 결과**로 번역한다. 성공 단계 차이가 추가 정보·시간·소음·손상·위치·위험 등 실제 결과를 바꾸면 그 물리적 차이를 묘사한다.
- 사용자가 성공 여부·Fumble 기준·난이도·룰 근거를 명시적으로 물을 때만 공개 가능한 수치 비교와 성공 단계를 설명할 수 있다. 숨은 NPC 수치·비공개 난이도·내부 계산은 계속 CORE_VISIBILITY다.

## BONUS_PENALTY_DICE

- 보너스는 창의적 우회 뒤에도 남는 유리한 수행 조건, 확정된 약점 활용, 지형 우위, 전문 장비/동료 시너지 등에 적용할 수 있다. 패널티는 자충수, 극단적 시야·환경 제약, 중상/광기 등 상태 이상, 다대일 등 실제 불리한 수행 조건에 적용할 수 있다.
- 난이도는 작업 자체의 객관적 어려움, 보너스/패널티는 **현재 수행 조건의 유불리**다. 플레이어 해결책이 불확실성 자체를 제거했다면 이 규칙보다 [FICTION_FIRST_ROLL_TRIGGER_GATE](02-checks.md#fiction_first_roll_trigger_gate)의 무판정 직접 해결이 우선한다.
- 실제 상태에서 적용되는 원인을 모은 뒤 보너스와 패널티를 **1:1 상쇄**한다. 상쇄 뒤 남은 순수 보너스 또는 패널티는 최대 2개까지만 적용하며, 같은 물리적 원인을 여러 문구로 중복 가산하지 않는다.
- PC의 순수 보너스/패널티가 N개(1~2)면 플레이어는 **기본 d100 1회 + 추가 d100 N회**를 직접 굴려 원값을 모두 보고한다. 자리 추출에서는 원값 `100`을 `00`으로 보고, Keeper는 기본 d100의 1의 자리를 고정한 채 기본 굴림 및 각 추가 굴림의 10의 자리와 결합한 후보를 만든다. 결합 결과 00은 100이다. 보너스는 후보 중 최저, 패널티는 최고를 최종 판정값으로 사용한다. 순수 modifier가 0이면 기본 d100 1회만 사용한다. 물리 percentile dice를 쓰면 1의 자리 주사위 1개와 10의 자리 주사위 `1+N`개를 굴리는 것과 같다.
- 이 방식은 [AI_BONUS_PENALTY_DICE](01-core.md#ai_bonus_penalty_dice)와 같은 확률 구조다. PC 굴림 원값은 플레이어가 제공하며 AI 게임플레이 난수 큐로 대신 만들지 않는다.
- **판정 요청 시 적용되는 유불리와 개수·필요 굴림 수를 반드시 시네마틱 지문과 구분된 판정 요청 영역에 표시한다.** modifier의 원인은 정보 공개 범위에 따라 숨길 수 있어도 플레이어가 굴려야 할 주사위 개수는 숨기지 않는다. 예: `▶ 판정 필요: 관찰 · 보너스 1개 — 기본 d100 1회 + 추가 d100 1회`. modifier가 없으면 `▶ 판정 필요: 관찰 — d100 1회`. 숨은 NPC 수치·비공개 난이도·원인은 CORE_VISIBILITY/정보 공개 범위에서 공개하지 않는다.

## PUSHED_ROLL

- 전투가 아닌 일반 기능/특성 판정에 실패한 PC는, 상황이 허용되고 아직 같은 목적을 다시 시도할 물리적 여지가 있다면 Push를 제안할 수 있다.
- 신규 판정은 ROLL_INPUT_FORM_CONTRACT에서 실패 시 강행 의사·방법·위험 동의를 숫자와 함께 받을 수 있다. 실제 실패와 재시도 여지를 확인한 뒤 강행하며 사용 여부를 재확인하지 않는다.
- 플레이어는 단순한 "한 번 더"가 아니라 무엇을 더 강하게 시도하거나, 어떤 다른 수단을 쓰거나, 어떤 위험을 감수하는지 구체적으로 선언한다.
- Keeper는 두 번째 실패가 초래할 더 큰 위험을 가능하면 판정 전에 감각적·상황적으로 예고한다. 즉사나 완전한 진행 봉쇄를 임의로 협박성 대가로 붙이지 않는다.
- Push는 동일 목적의 1회 재시도이며 세 번째 굴림은 없다. 첫 실패로 이미 확정된 소음·시간·자원·환경 변화는 소급 취소되지 않는다.
- 추가 노동/시간이 필요한 Push는 기준으로 턴을 소비한다.
- 전투 판정, SAN, Luck Roll, 피해량, 일반 대항 판정, 이미 Push한 판정은 Push할 수 없다.
- Push 실패는 단순 재실패가 아니라 장비 파손, 더 큰 소음, 위험 위치 노출, 부상, 관계 파탄, 위협 접근 등 그 행동과 인과적으로 연결된 심각한 결과로 전환한다.

## GENERIC_OPPOSED_ROLL

- 두 인물이 서로 직접 저항하는 비전투 행동은 필요 시 일반 대항 판정으로 해결한다. 예: 붙잡고 버티기, 물건 쟁탈, 은신 대 탐지, 설득 대 저항, POW 대 POW.
- 양측은 각각 상황에 맞는 기능/특성으로 1d100을 굴리고 Critical/Extreme/Hard/Regular/Failure의 성공 단계를 비교한다.
- 더 높은 성공 단계가 승리한다.
- 같은 성공 단계라면 원래 기능/특성 수치가 더 높은 쪽이 승리한다.
- 원래 수치도 같다면 양측이 새 1d100을 굴려 더 낮은 결과가 승리한다. PC는 직접 굴리고 NPC/적은 RNG 규칙을 사용한다.
- 숨은 NPC 수치나 판정값은 플레이어에게 공개하지 않고 물리적 결과만 렌더링한다.
- 격투의 Dodge/Fight Back은 이 일반 규칙이 아니라 MELEE_OPPOSED의 전투 전용 동점 규칙을 우선한다.

## LUCK_ROLL

- 기능이나 특성으로 통제할 수 없는 외부 상황·우연·운의 개입 여부를 판단할 때만 Luck Roll을 요구한다.
- PC는 현재 Luck 이하로 1d100을 직접 굴리면 성공한다.
- 적절한 기능/특성으로 해결 가능한 상황을 편의상 Luck으로 대체하지 않는다.
- Group Luck이 필요하면 현재 장면에 실제로 존재하는 PC 중 Luck이 가장 낮은 탐사자가 대표로 굴린다.
- Luck Roll 자체는 Push할 수 없고, Luck Spending으로 실패값을 고칠 수 없다.
- 성공해도 이미 존재할 법한 우연만 확정한다. 이전에 없던 강력한 무기·구조자·탈출로를 새로 만들어 NO_DEUS_EX_MACHINA를 우회하지 않는다.

## DIFFICULTY_ASSIGNMENT

- 판정 난이도는 작업 자체의 객관적 어려움으로 정하고, 현재 환경의 유불리는 Bonus/Penalty Dice로 분리한다.
- Regular: 훈련된 사람이 정상 조건에서 충분히 시도 가능한 작업.
- Hard: 전문가에게도 높은 정밀도, 불완전한 정보, 제한 시간 등 본질적 제약이 있는 작업.
- Extreme: 최고 수준의 숙련자에게도 예외적인 성취가 필요한 작업.
- 극적 긴장 때문에 같은 종류의 작업 난이도를 자의적으로 상향하지 않는다. 이미 유사 상황에서 확정된 판례가 있으면 유지한다.

## IMPOSSIBLE_ACTIONS_AND_RULE_OF_COOL

- 현재 수단으로 물리적·논리적으로 불가능한 행동은 Extreme 판정을 허용하지 않는다. 판정을 허용하는 순간 성공 가능성이 존재한다는 뜻이기 때문이다.
- Rule of Cool은 불가능을 자동 성공시키는 규칙이 아니라, 창의적 환경 활용·장비·협동·대가를 통해 '판정 불가'를 '판정 가능' 상태로 바꾸는 규칙이다.
- 플레이어가 지렛대, 동력, 구조물, 세계 법칙 등 타당한 새 수단을 확보하면 그 시점의 조건으로 난이도를 새로 판단한다.

## CORE_CLUE_FAIL_FORWARD

- 시나리오 진행에 필수적인 정보가 특정 장소/POI에 실제로 존재하고 플레이어가 올바른 접근을 선언했다면 단일 판정 실패만으로 그 정보가 영구 소실되지 않게 한다.
- 실패는 시간 소모, 실제 소음 노출, 도구 손상, 불완전한 사본, 위험 위치 노출, NPC 선점 등 인과적 대가로 바꾸고 핵심 정보의 최소 조각은 접근 가능하게 할 수 있다.
- 더 높은 성공 단계는 추가 맥락, 무소음, 빠른 획득, 원본 보존, 보조 단서 등의 이득을 제공한다.
- 선택적 보너스 단서와 위험을 감수해야 하는 심층 진실까지 자동 보장하는 규칙은 아니다.

## DIEGETIC_PROFILING

- 현장을 처음 보여줄 때 결론을 말하지 말고 물리 흔적만 제시한다.
- 플레이어가 분석을 선언하면 상황에 맞는 INT/조사 계열 기능으로 관찰된 파편의 공통점·차이·검증 가능한 관계를 더 선명히 할 수 있다.
- 실패 자체로 SAN을 잃지 않는다. 실패 비용은 실제 상황에 존재하는 시간, 실제 소음 노출, 위험 노출, 불완전한 정보, 기회 손실 등으로 처리한다.
- 분석 대상의 내용 자체가 공포·신화·SAN Exposure라면 그 노출에 따른 SAN 규칙은 별도로 적용한다.

## DAMAGE_BONUS_AND_BUILD

- Damage Bonus(DB)와 Build는 STR+SIZ로 계산한다.
STR+SIZ 2~64  -> DB -2 / Build -2
STR+SIZ 65~84 -> DB -1 / Build -1
STR+SIZ 85~124 -> DB 없음 / Build 0
STR+SIZ 125~164 -> DB +1d4 / Build 1
STR+SIZ 165~204 -> DB +1d6 / Build 2
- 인간 범위를 넘어선 초자연 존재의 DB/Build는 시나리오 설계 시 위협 프로필에 미리 고정하며, 전투 중 임의 보정하지 않는다.
- DB는 맨손 및 DB 적용 근접무기의 피해에 더한다. 총기 피해에는 적용하지 않는다.
- 음수 DB는 피해에서 고정값을 뺀다. 최종 피해는 0 미만으로 내려가지 않는다.
- Build는 Fighting Maneuver의 체격 차이 판정에 사용한다.

## HP_AND_DEATH

HP = floor((CON + SIZ) / 10).
- HP는 0 미만으로 기록하지 않는다.
- 한 번의 피해가 최대 HP 이상이면 즉시 사망한다.
- 한 번의 피해가 최대 HP의 절반 이상이면 Major Wound(중상)를 입는다.
- Major Wound가 없는 상태에서 HP가 0이 되면 즉시 사망하지 않고 의식불명(Unconscious)이 된다.
- Major Wound가 있는 상태에서 HP가 0이 되면 Dying 상태가 된다.
- Dying PC는 다음 라운드 종료 시점부터 매 라운드 CON 판정을 직접 굴린다. 실패하면 사망한다.
- 적절한 의료품을 사용한 응급치료 성공은 Dying을 안정화해 반복 CON 사망 판정을 멈춘다. Major Wound 자체는 남는다.
- HP 0의 의식불명 PC는 행동할 수 없으며, 치료로 HP가 1 이상이 되거나 상황상 적절한 회복 조건을 충족해야 행동권을 되찾는다.

## WOUNDS

경상: 단일 피해가 최대 HP의 절반 미만. 출혈 등으로 은신/도주에 패널티 가능.
Major Wound(중상): 단일 피해가 최대 HP의 절반 이상.
- 즉시 CON 판정을 요구하며 실패하면 의식불명.
- 현재 생존호러 하우스룰에 따라 이동력 절반, 도주를 제외한 물리 판정에 패널티를 유지한다.
- Major Wound가 있는 동안 HP 0은 HP_AND_DEATH의 Dying 절차로 전환한다.

## HEALING

- 의료품 + 응급치료/의학 판정 필요.
- Dying 상태에서는 우선 적절한 의료품을 사용한 응급치료 성공으로 안정화해야 한다. 실패하면 Dying CON 사망 판정이 계속된다.
- 파우치 소모품: 턴 프리징, 성공 시 HP 1d3 회복. 중상 해제 불가.
- 구급상자/수술도구: PLAY의 현재 Scene에서 치료 행동으로 1 Scene Turn을 사용하며, 성공 시 HP 1d6 회복.
- 중상 해제는 현재 생존호러 하우스룰을 유지하여 구급상자 소모 + 의학 성공으로 가능하다. 응급치료만으로는 해제 불가.
- HP 0 의식불명 상태에서 치료로 HP가 1 이상이 되면 의식을 되찾을 수 있다.

## LIFESTYLE_BUFFS

식사·수면을 선택할 작은 보상이다. **하지 않아도 새 허기/수면 페널티·행동 금지·기본 난이도 인상이 없다.** 잠복·야간 활동·조사·대화의 허가 조건으로 사용하지 않는다. 기존에 실제 발생한 부상/위험은 담당 규칙을 따른다.

| 버프 | 획득 | 일반 품질 | 좋은 품질 | 사용 범위 | 만료 |
|---|---|---|---|---|---|
| 🍲 든든함 | 충분한 한 끼를 실제로 먹음 | 목표치 +3 | 목표치 +5 | 비전투 신체 기능: 등반·수영·도약·잠행 등 실제 신체 수행 | 식사 종료 후 극중 4시간 |
| 🛏️ 개운함 | 충분한 수면을 실제로 마침 | 목표치 +3 | 목표치 +5 | 비전투 조사·집중 기능: 자료조사·관찰·전문 분석·정밀 작업 등 | 기상 후 극중 8시간 |

- 음식은 충분한 양과 먹을 수 있는 식사면 일반 품질, 잘 준비된 영양·신선도·만족스러운 식사 조건이 확보되면 좋은 품질로 판단한다. 값비싼 한 입이나 식사 주문/결제만으로 획득하지 않는다. 수면은 보통 성인의 7~9시간 정도를 기준으로 실제 PC 조건에 맞는 충분한 양을 판단하며, 편안하고 조용하고 보호된 잠자리는 좋은 품질이다. 가격만으로 품질을 정하지 않고 지인의 집·직접 만든 식사도 해당 조건을 충족할 수 있다. 짧은 낮잠·휴식은 이 버프를 자동 지급하지 않는다. 중단됐으면 실제 완료한 식사/수면 조건으로 판단하며 부족하다고 새 페널티를 만들지 않는다.
- 각 버프는 **1회 사용 또는 만료 시각 도달 중 먼저 일어난 때 소멸**한다. 극중 시간으로만 계산하며 턴 수·현실 채팅 시간·자정 일괄 초기화로 계산하지 않는다. 획득 직후부터 남은 시간을 계산하고 하루 내내 유지하지 않는다.
- 같은 종류는 하나만 보유한다. 다시 조건을 충족하면 새 품질과 새 획득/만료 시각의 1회 버프로 교체한다. 이전 높은 수치와 새 만료를 조합하거나 횟수를 누적하지 않는다. 서로 다른 두 버프는 보유 가능하지만 **한 판정에는 하나만** 선택한다.
- 전투 판정·SAN·Luck Roll·피해량·특성 판정에는 적용하지 않는다. 기능 이름만 보지 않고 현재 행동의 성격으로 적용 범위를 판단한다. 버프 사용을 전제로 난이도를 높이거나 추가 판정을 요구하지 않는다. HP/SAN/Luck이나 영구 기능 수치를 올리지 않으며 보너스 주사위를 주지 않는다.
- 효과는 해당 기능의 Regular/Hard/Extreme **각 기준 목표치에 선택한 +3 또는 +5를 더한다**(상한 99). 기준은 원래 기능치와 floor(기능치/2), floor(기능치/5)이며 기능치 자체를 먼저 올려 분수를 재계산하지 않는다. Critical은 원값01만, Fumble 범위는 원래 기능치로 유지하고 최우선 판정한다. 예: 기능45에 +3이면 기준은 48/25/12이며 원값96~100의 Fumble은 여전히 Fumble이다. 보너스/패널티 주사위 결합은 기존 방식대로 한 뒤 이 목표치와 비교한다.
- **굴리기 전에** ROLL_INPUT_FORM_CONTRACT의 같은 폼에서 `생활 버프: 사용 안 함 / 적용 가능한 버프 하나`를 선택하도록 안내한다. 기본은 사용 안 함이며 판정값과 함께 제출받고 별도 확인을 만들지 않는다. 수동 주사위는 버프 선택 후 굴리도록 안내하며 이미 나온 결과를 보고 소급 적용하지 않는다. 판정 요청에는 원래 기능과 적용 시 목표치·효과를 구분한다.
- 실제 굴림 시점의 극중 시간에 유효한 버프만 적용한다. 장기 작업 도중 만료된다면 실제 판정 시점부터 판단하며 요청 시 유효했던 조건은 현실 입력 대기로 만료되지 않는다. 선택만 하고 취소하거나 무효 입력을 고치는 동안은 소모하지 않는다. 유효 굴림을 해결하면 성공·실패·Fumble과 무관하게 한 번 소모한다. 같은 판정의 재제출/로드는 재소모하지 않는다.
- 행운 계산은 이번 판정에 적용한 Regular 목표치 기준으로 부족분을 구한다. 사용한 버프는 초기 굴림에서 소모되므로 강행에 자동 이월하지 않는다. 강행의 새 굴림은 남아 있는 다른 적격 버프를 새로 선택할 수 있으며 이미 소모한 효과로 목표치를 유지하지 않는다. 기존 행운/강행 금지·상한·실패 비용은 그대로다.
- 현재 PC의 기존 상태/효과 저장 영역에 종류·품질/수치·획득 시각·만료 시각·남은1회·원인 ref를 compact하게 보존하고 열린 판정에는 선택과 적용/소모 여부를 연결한다. 메타 재표시·로드로 획득/만료를 갱신하지 않는다. 정확한 절대 시각이 없으면 동일한 상대 timeline anchor와 누적 경과를 사용한다. 구판의 `휴식 완료` 문구만으로 품질·시각·버프를 소급 창작하지 않는다. 정보가 실제로 있는 경우에만 복구한다. 새 서버 컬럼·매 턴 DB 호출은 요구하지 않는다.
- HUD_VISUAL_STYLE의 `🌿 생활 버프`에 현재 버프·수치·적용 범위·1회·남은 극중 시간을 표시한다. 소모/만료하면 즉시 제거하고, 버프가 없으면 행 자체를 생략한다. 만료 경계에서는 `남은 0분`인 사용 가능 버프를 남기지 않는다.

## LUCK_SPENDING

- 생활 버프를 선택했다면 이번 굴림의 목표치는 LIFESTYLE_BUFFS를 반영한다.
- 목표치보다 약간 높은 실패값은 초과 수치만큼 **현재 Luck**을 차감해 Regular 성공으로 바꿀 수 있다. 필요한 비용보다 현재 Luck이 적으면 사용할 수 없고 Luck을 0 미만으로 만들지 않는다.
- Fumble, SAN, Luck Roll 자체, 공격 피해량에는 사용 불가.
- 결과 묘사 전에 선언해야 한다. 신규 판정에서는 ROLL_INPUT_FORM_CONTRACT의 숫자 입력과 함께 사용 여부·소비 상한을 받는다. 유효한 동의 뒤 별도 Luck 선택 화면을 다시 요구하지 않는다.
- Luck의 기본 런타임 사용처는 본 Spending과 [LUCK_ROLL](02-checks.md#luck_roll), 그리고 규칙이 명시한 비용뿐이다. **카메라 순서나 Spotlight 우선권을 Luck으로 구매하지 않는다.**
