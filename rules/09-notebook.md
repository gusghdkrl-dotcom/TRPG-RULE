# 공개 조사자 수첩

규칙판: 플레이 개선판 2026-10-29. 규칙 ID는 버전과 독립적으로 유지한다. 필요한 절만 조회한다. 전체 경로는 `00-index.md`를 따른다.

## NOTEBOOK_LITE_OPEN_GATE

공개 Setup 자료가 확정되면 실제 연결된 수첩 앱에서 각 P슬롯의 수첩을 한 번 연다.
1. 기존 binding을 확인한다. 이미 열렸으면 기존 수첩을 사용하며 새로 발급하지 않는다. 이전 호출의 성공 여부가 불명확하면 중복 생성 전에 복구 키/현재 binding을 확인한다.
2. 지원되는 `open_notebook(slot,campaignTitle)`을 실제 호출하고 응답의 recoveryKey/revision을 비공개로 기록한다. 제목은 확정한 캠페인 이름이다.
3. 공개 허용목록만 최초 동기화한다. 공개된 해당 PC 정보·HP/SAN/Luck·현금·소지품·지도·NPC·증거·플레이어 가설만 포함한다. 지도·NPC·증거·가설 등 파티 공통 지식은 모든 참가 슬롯에서 같은 공개 범위를 사용하고 HP/SAN/Luck·현금·소지품은 해당 PC 값만 쓴다. 미검증 checkpoint version은 null이며 아직 시작 전의 sceneTurn은 0이다.
4. 명백히 최초 열기를 누락한 경우에만 첫 장면 전 1회 보정한다. 앱이 없거나 실패하면 수첩 연결만 대기하고 Supabase 저장 성공 여부는 별도로 판정한다.
5. `수첩 열기`는 시간 정지다. 새 채팅의 load_notebook은 게임을 STATE_RESUME으로 복원한 뒤 실제 verifiedSceneTurn/verifiedCheckpointVersion으로만 요청한다.
연결 실패를 이유로 과거 산장·로그인·외부 캐릭터 생성 UI를 열지 않는다. 실제 서버의 접근 통제는 유지한다. 공개 변경의 이후 Writer는 NOTEBOOK_WATCHER_RUNTIME_SINGLE_WRITER를 따른다.

## NOTEBOOK_WATCHER_RUNTIME_SINGLE_WRITER

P슬롯별 공개 수첩 Writer는 한 명이다. 기본은 KEEPER_DIRECT이며 일반 공개 변경은 NOTEBOOK_PUBLIC_PATCH를 따른다.
- WHALE_WATCHER 전환은 실제 HUD·대상 슬롯 매칭·서버 ACK·재전송이 확인되고 사용자가 명시적으로 전환한 경우에만 한다. 설치나 체크박스만으로 성공을 추정하지 않는다.
- 전환된 슬롯에서 Keeper는 일반 Play 공개 변경을 sync_notebook/sync_notebook_delta로 중복 쓰지 않는다. HUD·게임 상태·비공개 Checkpoint는 계속 정상 처리한다.
- 감시기의 ACK·누락을 관찰할 수 없으면 성공으로 보고하지 않는다. 지원하지 않는 서사 기록이 자동 반영됐다고 말하지 않는다.
- 새로고침·채팅 이동·감시기 끊김만으로 Keeper 자동 쓰기로 돌아가지 않는다. 새 채팅은 감시기 재등록·같은 P수첩 복구 키 재연결·전송 승인 확인 후 기록한다. 이전 대기열을 새 수첩과 자동 병합하지 않는다.
- 감시기 소유 슬롯의 수첩 동기화 요청에는 감시기의 현재 HUD 저장/대기열 재시도를 안내한다. Keeper의 직접 수동 수정·이미지 전송은 해당 자동 쓰기를 멈추고 대기열/서버 revision 충돌을 해소한 뒤 명시된 범위에서 수행한다.
- 전환된 슬롯의 연결을 확인할 수 없으면 공개 수첩 쓰기만 대기한다. 같은 게임의 비공개 저장·진행을 수첩 오류로 재생성하지 않는다.

## NOTEBOOK_PUBLIC_PATCH

공개 변경 전송은 실제 연결된 서버 도구의 최신 계약을 확인한 뒤 수행한다.
- 직접 전송이 해당 슬롯의 Writer일 때, 지원되면 `sync_notebook_delta`로 변경된 공개 필드만 보낸다. `sync_notebook`은 실제 확인한 expectedRevision 계약을 따른다. 두 도구의 입력 요건을 임의로 동일하게 취급하지 않는다.
- 공개 사건·NPC·인물 사건·증거·가설·목표·약속·챕터·소지품은 stable id로 upsert한다. 재시도는 같은 id/같은 사실이다. 다른 사건에는 새 id를 쓴다. 빈 배열을 전체 삭제로 간주하지 않는다.
- 실제 제거는 도구가 지원하는 remove 계약과 해당 사실의 정당한 변경 범위를 확인한다. 과거 사건·인물 사건의 본문/발생 턴을 현재 상태로 덮어쓰지 않는다.
- 목표·약속·챕터가 바뀌면 해당 공개 사건과 상태 변경을 함께 전송한다. 가설은 플레이어가 실제 제시한 것만 포함한다.
- 파티 공통 사실은 같은 stable id·출처로 각 수첩에 공개할 수 있다. 실제 앱이 공유 데이터를 지원하면 그 표현을 재사용한다. PC별 접근 차단이나 자원 합산을 만들지 않으며 각 슬롯의 단일 Writer 계약을 유지한다.
- 변경이 없으면 전송하지 않는다. 사전 load/open을 매 턴 반복하지 않는다. 수첩 응답 실패로 게임 결과·난수·Checkpoint를 재실행하지 않는다.
- 기존 앱이 신규 시트에서 제거한 필드를 요구하면 어댑터 호환 문제로 보고하고 수첩 전송만 대기한다. 가짜 수치를 보내지 않는다.

## NOTEBOOK_MEDIA

이미 플레이어에게 공개한 지도·PC/NPC 초상·장면 사진과 웹 참고 이미지만 전용 이미지 도구로 저장한다. 웹 참고는 출처·설명과 reference_only 성격을 유지하고, 정본 초상·지도·증거 이미지 슬롯을 덮어쓰지 않는다. 서버가 참고 이미지를 구분해 저장할 수 없으면 이미지 전송을 보류하고 실제 지원하는 공개 메모/링크만 사용한다.
- 실제 원본 바이트를 얻을 수 있고 해당 서버의 MIME/크기/권한 제한을 통과할 때만 publish_map_image 또는 publish_notebook_image를 호출한다. 임시 경로·URL·설명을 이미지 원본인 것처럼 보내지 않는다.
- 이미지의 id·공개 턴·제목·subject는 실제 공개 사실을 사용한다. 같은 id/같은 원본의 재시도만 허용하고 수정 이미지는 새 id로 보낸다. 바이트를 일반 텍스트 patch에 넣지 않는다.
- 다른 Writer가 같은 슬롯을 기록 중이면 자동 쓰기/대기열 정리와 revision 재검증 후 전송한다. 충돌 여부가 불분명하면 이미지 전송만 보류한다.
- 원본 접근 도구가 없으면 실제 지원되는 사용자 업로드 경로를 안내한다. 채팅에서 이미지를 만들었다는 사실만으로 수첩에 보관됐다고 주장하지 않는다.
