# 지도·인물·장면 시각화

규칙판: 생존 호러 통합 경량판 2026-11-12. 상시 서사·묘사는 프로젝트 지침, 상황별 조회는 00-index.md. 필요한 절만 읽는다.

## CANONICAL_CAMPAIGN_MAP

세계/현재챕터 확정 때 장소·지역·경로·연결·이동수단·대략적거리/시간·접근/봉쇄와 공개/비공개 참조를 공간 모델에 고정한다. 필요한 범위만 만들며 정확한 실측좌표를 확인하지 않았으면 개략도임을 명확히 한다. 기존 지형/경로를 그림에 맞춰 바꾸지 않는다.
PC 시작 배치·사건 접점은 같은 장소/경로ref에 연결한다. 새챕터의 실제새지역은 기존세계결과를보존해추가한다. 파괴/개통/폐쇄는 현재세계상태를 상속한다. 플레이어지도는 실제공개된투영이다.

## MAP_RUNTIME_INTERACTION

지도 열람/공개 경로 질문은 시간정지, 목적지로 간다는 선언은 실제 이동이다. 현재위치·연속경로·수단·봉쇄/위험/시간을 ROUTINE_MOVEMENT_FAST_PATH로 처리한다. 의미 있는 경로 차이만 설명해 선택받고 미발견 지름길은 제안하지 않는다.
공개지도는 알려진 장소라벨·연결·방향·지형/경계·실제확인경로상태가 읽히는 기능형 지역도/도면으로 제공한다. 실제 확인된 PC위치/공개주석은 표시할 수 있다. 픽셀거리/장식건물은 새경로나 실제거리의 정본이 아니다. 클릭도구가 없으면 자연어로 장소/경로를 지정한다.
새공개/개통/폐쇄는 상태에반영하고 매턴 이미지를재생성하지않는다. 지도요청/필요한제공시 최신공개투영을쓴다. 비밀통로/미발견증거/적위치는발견전표시하지않는다.

## START_MAP_HANDOUT_GATE

신규게임 시작시 첫PC장면전에 공개시작지역의 기능형지도 이미지1장을 실제생성/전달한다. 별도A/B선택은없다. 현재공개지형/시설/경로·방향/범례·시대/계절감을사용하며 풍경삽화만으로 지도완료라하지않는다.
실제전달을확인한뒤 delivered로기록한다. 실패/미지원이면 같은 확정공간의 텍스트/간단연결도를제공해 첫장면을이어가고 이미지전달상태는미완료로구별한다. 지도 때문에 게임지형을다시생성하지않는다. 이미지/대체표시는시간/턴/자원/난수를진행하지않고 저장실패도첫장면을막지않는다.

## EVENT_DRIVEN_VISUAL_ROUTER

## CHARACTER_VISUAL_CANON

## HQ_NPC_FIXED_PORTRAIT_ASSET_ROUTER

**적용:** 시간요원 본부 ON의 고정 NPC 8명이 등장하거나 해당 NPC의 프로필/초상을 실제로 보여 줄 때. OFF의 일반 원작 NPC·PC·장면/지도 이미지에는 적용하지 않는다.

- **인물 정본:** `docs/development/TIME_AGENT_NPC_VISUAL_CANON.md`의 HQ-STAFF-01~04, HQ-AGENT-01~04 고유 ID별 외형/태도와 사용자가 승인하여 전달한 **8장의 공식 PNG 원본**이다. 배우는 인상 참고일 뿐이며, 배우 사진을 대체 프로필로 사용하지 않는다.
- **자산 색인:** 현재 통합 저장소의 `assets/hq-npc/manifest.json`에 **NPC 고유 ID → PNG 상대 경로 → Git blob SHA-1/SHA-256/화면 크기**가 있다. 각 상대 경로는 저장소의 `assets/hq-npc/` 아래에 해당한다. 같은 NPC에게 다른 이미지/새 랜덤 검색 결과를 배정하지 않는다.
- **실제 존재·정합성 확인:** **manifest의 텍스트가 있다는 것만으로 PNG 업로드/접근 성공을 주장하지 않는다.** 해당 브랜치에 실제 PNG가 존재하고 blob SHA-1이 manifest의 `git_blob_sha1`과 맞거나, 신뢰 가능한 동일 원본 바이트의 파일 참조가 실제 열릴 때만 공식 자산을 현재 호출 가능한 것으로 본다. GitHub 원본을 클라이언트에서 표시할 때는 **실제로 검증된 해당 파일의 원본 URL/첨부 파일 참조**를 지원되는 이미지 표현 수단으로 제공한다. 확인하지 않은 GitHub 주소·임시 채팅 이미지 ID·불명확한 URL을 재사용 가능한 asset ref라고 표시하지 않는다.
- **사용 방식:** 동일 NPC가 본부에 여러 번 등장하면 **승인된 동일 PNG**를 우선 재사용하고, 별도의 인물 사진 검색·재생성·AI 합성 얼굴 바꾸기를 실행하지 않는다. 장면에서 피/오염/복장 변화처럼 실제 시각적 상태 변화가 필요하면 별도 장면 이미지로 표현할 수 있으나 **기본 공식 초상 파일을 교체하거나 인물의 얼굴 정체성을 변경하지 않는다**. 초상은 본부 NPC의 처음 등장/명시 요청 등 필요한 시점에만 제공하며 대화마다 강제 반복하지 않는다.
- **실패 시 안전 대체:** 공식 이미지가 아직 GitHub에 업로드되지 않았거나 현재 환경에서 로드·표시할 수 없으면 **다른 사람의 웹 사진, 배우 사진, 범용 headshot, 새로 만든 비슷한 얼굴을 공식 초상으로 대신하지 않는다.** 해당 인물의 확정 외형을 텍스트로만 제공한다. 사용자에게 이미지가 미표시/미연결임을 말할 수 있으나 이미 표시했다고 주장하지 않는다.
- **영속 등록 경계:** 실제 바이너리 업로드 및 활성 브랜치 재조회·해시 검증을 완료해야 재사용 가능한 GitHub 자산 등록으로 간주한다. 이후 다른 채팅/프로젝트에서 그 GitHub URL을 로드할 수 있는지는 그 환경의 접근 가능성에 따른다. 별도 영속 DB 저장/프로젝트 파일 동기화를 자동으로 가정하지 않는다.

## HQ_FIRST_INDUCTION_PORTRAIT_REVEAL

**적용:** **시간요원 본부 ON에서 신입 요원이 실제로 처음 본부를 방문하는 첫 도입·입단식·첫 시설 안내 과정**에 한정. 기존 요원의 새 게임/재개·OFF·현지 원작 세계에는 이 자동 초상 공개를 적용하지 않는다. 이 특별 공개는 `HQ_NPC_FIXED_PORTRAIT_ASSET_ROUTER`의 이미지 정본/실제 로드 조건을 그대로 따른다.

1. **장면에 직접 등장한 인물만:** `HQ-STAFF-01~04` 및 `HQ-AGENT-01~04` 중 플레이어가 실제로 처음 만나고 **신원/얼굴을 알 수 있는 시점**에, **해당 NPC의 공식 PNG 한 장을 그 장면의 첫 소개·대사와 함께 보여준다.** 숨겨진 인물/화면 밖 인물·아직 만나지 않은 인물의 사진/이름/신분을 미리 공개하지 않는다. 신입 입단 첫날이라는 이유로 여덟 명을 한꺼번에 소개하거나 특별 출연을 강제하지 않는다.
2. **첫 제이든/마틴의 정확한 시점:** 본부 **외부 프롤로그에는 직원 사진이 없다.** 실제 `본부 입장` 선택 뒤 **내부 공간의 첫 인상 → 음악 듣는 제이든이 신입을 발견하고 볼륨을 낮춤 → 실제 얼굴과 이름/인사가 공개될 때 `HQ-STAFF-02` 공식 사진**을 붙인다. 플레이어가 마틴 면담 장소에 실제 도착하여 **마틴을 만날 때** `HQ-STAFF-01` 사진을 그 장면과 함께 보여준다. 도미닉/클라라/사미라/레오/최서린/마야도 **실제로 처음 등장할 때만** 같은 원칙. 나중에 처음 만난다면 입단식 중 억지로 미리 보여주지 않는다.
3. **사진은 별도의 포스터/강제 이벤트가 아니다:** 본문에서 인물의 실제 움직임·표정과 이름·첫 대화를 먼저 자연스럽게 연결하고, 그 **인물 소개 바로 아래/옆**에 파일 한 장을 배치한다. NPC의 나이·직업/관계·현재 장비를 그림을 위해 변경하지 않는다. 길게 프로필 전체를 읽어 주거나 장면/대화를 중단하는 승인 버튼을 만들지 않는다.
4. **정확한 로딩 주소:** `assets/hq-npc/manifest.json`의 해당 `npc_id`에 대응하는 **`image_url`**은 실제 업로드/파일 SHA가 확인된 PNG의 직접 원본 주소다. 이 URL 또는 지원되는 신뢰 가능한 동일 원본 첨부 참조를 사용한다. UI가 원격 이미지 임베드를 지원하면 그 지원되는 이미지/미디어 기능으로 실제 표시한다. 해당 화면이 표준 Markdown 원격 이미지 임베드를 지원하는 경우 `![제이든 콜 — 공식 초상](https://raw.githubusercontent.com/gusghdkrl-dotcom/TRPG-RULE/dev/time-agent-hq/assets/hq-npc/HQ-STAFF-02-jayden-cole.png)`처럼 **정확한 검증 URL**을 넣을 수 있다. **문자만 출력한 것/링크만 출력한 것을 '사진이 함께 표시됐다'고 주장하지 않는다.** 현재 환경에서 실제 이미지 렌더링이 불가능하면 같은 원본으로 이동하는 명시적 이미지 링크와 외형 설명을 제공하고, 인라인 표시 미지원임을 구별한다. 무관한 인터넷 검색 사진·배우 사진·재생성한 비슷한 얼굴로 바꾸지 않는다.
5. **반복/범위 종료:** 해당 신입 입단·초기 안내 구간의 **인물별 첫 실제 소개에 1회만** 표시한다. 같은 인물과 이어지는 대화/재방문/브리핑마다 자동 재표시하지 않는다. 현재 작업 맥락에 그 구간의 `hq_first_intro_image_shown_ids`(해당 NPC ID 목록)를 짧게 보존하며, 기존 인물 첫 만남 기록이 있으면 우선 재사용한다. 이 표시는 출력용 상태이지 새 DB 테이블·로그인·임무·세계 시간 이벤트가 아니다. 실제 저장 경계의 기존 허용된 맥락에 포함할 수는 있으나 새 저장 행위를 강제하지 않는다. **입단식·첫 안내가 끝나면 자동 사진 게이트 종료.** 이후 사진은 플레이어가 초상/프로필을 명시 요청한 때만 재사용한다.
6. **지원 범위의 한계:** GitHub에 PNG가 등록돼 있어도 게임 응답 UI가 외부 이미지를 바로 삽입할 수 있는지는 **별개로 실제 첫 등장 화면에서 확인**해야 한다. 지원되지 않는 정적 HTML·이미지 컴포넌트·임시 URL·잘못된 ref를 가짜로 쓰지 않는다. 사진이 미표시여도 실제 대화·게임 행동·판정·시간은 정상 진행한다.

## GOLD_START_PROFILE_REFERENCE

프로필이미지는 인물당1장의 조사자파일/dossier 계열을 기본으로한다. 실제제공된 gold_start_profile_reference가있으면 디자인계열과정보위계를참고한다. 같은캠페인의스타일을유지하되 원작/시대에맞지않는1920년대복식등을강제하지않는다.
이름/직업·대표초상·확정외형/배우·공개배경/현재목적·기능/자원·실제시작소지품/슬롯을읽기좋게배치한다. 이미확정된관계/사건연결만포함한다. 정확한블록좌표·사진수·문장수·대표물품개수는없고 삭제된태그/생활흔적항목을복원하지않는다.
초상구도/포즈/배경은직업·상황에맞게선택하고배우사진구도를그대로반복할필요는없다. 한글/수치오자는확정텍스트가정본이다. 이미지검사가실제가능할때만일치여부를보고하며 픽셀/문자정확성을보장하지않는다. 실패해도인물/수치를재생성하거나진행을잠그지않는다.

## EPILOGUE_CHARACTER_EVOLUTION_HANDOUT

전체종료뒤요청하면PC별1장의시작/종료변화카드를제공한다. 최초공개외형기준과실제종료상태를비교해인물정체성·남은상처/흉터/수척함·복장/장비·잃거나얻은것·공개관계/흔적을표현한다. gold_epilogue_profile_reference가있으면참고하고없으면시작dossier계열을사용한다.

## LOCATION_VISUAL_CANON
