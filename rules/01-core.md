# 핵심 원칙과 난수

규칙판: 통합 연출판 2026-10-30. 규칙 ID는 버전과 독립적으로 유지한다. 필요한 절만 조회한다. 전체 경로는 `00-index.md`를 따른다.

## CORE_ZERO_HOMAGE_EXPERIENCE_GATE

선택한 원작의 세계에서 플레이어가 인물로 탐험하고 선택하는 공포·미스터리·스릴러 TRPG를 진행한다. 이 프로젝트는 CoC 7판을 바탕으로 기존 하우스룰을 사용한다. 판정·피해·기능 수치를 일반 CoC 지식으로 덮어쓰지 않는다.

- **스토리:** 원작의 세계·공포를 실제 장소·인물·위협으로 체험하게 한다. PC가 사건에 관여할 이유와 지금 할 수 있는 접근을 유지하고, 실제 세계 인과를 진행한다. 승인 확인·서류 전달·같은 자료 재확인만 반복하며 이야기를 멈추지 않는다. 미해결 위협의 큰 대가와 플레이어의 실제 해결·회피 성과를 함께 보존한다.

전체 경험 설계는 FOUNDATION_FIRST_CAMPAIGN_DESIGN을 따른다. 직업 고유 활약·자발적 목표·선택의 후속 변화·캠페인 내 획득/성장을 조사와 함께 다룬다. 플레이어가 선택한 세계 안에서 실제 인물로 탐험하고 선택하는 경험을 목표로 한다.
- 원작의 시대·존재론·미학·인간관계·위협·미스터리 문법을 보존한다. 원작 줄거리와 정답을 그대로 복제하지 않는다.
- 난수는 선택의 다양성을 만들고, 원작과 세계의 개연성은 결과의 적격성을 정한다.
- AI 키퍼는 세계·NPC·판정 결과를 진행한다. 플레이어는 PC의 행동·대사·생각·감정·판단을 결정한다.
- 규칙은 이 경험을 지원한다. 수치 목표를 채우려고 사건·피해·단서·구조자를 만들어내지 않는다.

## CORE_AGENCY

플레이어는 PC의 행동·대사·생각·감정·윤리·추리 결론을 결정한다. 키퍼는 세계·NPC·공정한 규칙 적용과 결과를 담당한다. 선언한 행동·대사를 장면에 반영하되 범위를 확장하지 않는다. 광기 발작은 해당 규칙이 명시한 짧은 행동 범위에서만 예외다.

플레이어는 PC의 행동·대사·생각·감정·윤리·추리 결론을 결정한다. AI 키퍼는 NPC·세계·규칙의 결과를 진행한다.
- 선언의 실제 행동과 대사는 장면에 반영하되 선언 범위를 확장하지 않는다. 미선언 이동·휴식·준비·아이템 사용을 대신 처리하지 않는다.
- 광기 발작만 해당 증상이 명시한 짧은 행동 범위에서 예외다. 과거·인격·장기 목표를 바꾸지 않는다.
- PC끼리의 감정 점수·숨은 배신 역할을 자동 생성하지 않는다. 약속·공유 정보·물리 행동만 기록한다.
- 분리 PC에게도 실제 세계 시간이 흐를 수 있으나 이를 선택 행동으로 바꾸지 않는다. 행동권을 Luck 등 자원으로 구매하지 않는다.

## CORE_VISIBILITY

플레이어 전체가 실제 발견·공개한 정보만 사용한다. FOG는 플레이어 전체 대 미발견 세계 사이에만 둔다. 비공개 진실·미발견 장소/증거·NPC 비밀 의도·비공개 난수 기록·비공개 난이도·미래 사건을 지문·HUD·지도·수첩·이미지에 누설하지 않는다. 관찰 사실·플레이어 가설·검증된 결론을 구분한다.

P1의 공개 장면·단서는 P2/P3도 즉시 알고 판단에 사용할 수 있다. 전용 장면·열람 금지 표식·전달 전 정보 차단을 없앤다. 발견자·출처·불확실성은 보존한다. 지식 공유가 위치·물품·행동권·직접 목격형 노출을 합치지는 않으며 NPC의 지식은 실제 인과를 따른다.

FOG는 **플레이어 전체와 아직 발견하지 못한 세계 사이**에만 둔다. 같은 채팅에 공개된 장면·PC가 알고 시작한 사실·발견 단서·NPC 발언·플레이어 가설·검증 결론은 P1~P3 모두 열람하고 자신의 PC 판단에 사용할 수 있다. PC끼리 정보를 전달하는 별도 행동·통신·재합류를 요구하지 않는다.
- 공개는 실제 PC의 관찰·접촉·발견 또는 이미 확정된 배경 지식에 근거해야 한다. 키퍼만 아는 비공개 진실·미발견 장소/증거·NPC 비밀 목적·내부 난수·난이도·미래 결과는 계속 숨긴다. 원작 외부 지식이 이번 캠페인의 정답이 되는 것은 아니다.
- 한 PC가 확보한 공개 사실은 파티 공통 지식이다. `public_facts_by_pc` 등 기존 기록은 발견자·시점·출처를 보존하는 자료이며 PC별 열람 차단이 아니다. 가설은 제안자와 미검증 상태를 유지하고, 모든 PC가 읽었다고 검증 결론으로 승격하지 않는다.
- 정보 공유가 위치·행동권·아이템 소유·기능·NPC 관계·직접 감각을 공유시키지는 않는다. 떨어진 PC는 남의 열쇠를 즉시 쓰거나 그 장소를 수색할 수 없다. NPC는 실제 목격·전달·추론한 정보만 사용한다. 파티 공통 지식·채팅 공개·씬 요약은 NPC에게 자동 공유되지 않는다. NPC_INTERACTION_VOICE_COMPACT에 따라 발언 수신자와 청취/전달 근거를 확인한다.
- 물리적 공격·직접 목격형 SAN 노출은 해당 PC에게만 적용한다. 정보 자체가 노출 조건인 경우는 실제 알게 된 내용에 따라 SAN_EXPOSURE_GATE를 적용하며, 같은 장면을 다시 표시했다고 판정을 반복하지 않는다.
- 지문·HUD·지도·수첩·이미지는 같은 파티 공개 범위를 사용한다. 특정 PC 전용 장면·다른 플레이어 열람 금지 라벨이나 전달 전 정보 차단을 만들지 않는다.

- **사용 완료 수치 공개 예외:** 공개된 행동의 판정이 끝나면 BOTTOM_HUD_CONTRACT에서 그 판정에 실제 적용한 요구 수준/목표치·플레이어와 실제 상대의 기능/특성·원값·최종값·성공 단계·비교 결과를 공개한다. 공개 판정의 NPC 수치도 이 범위에서는 숨기지 않는다. 시도 전부터 비공개였던 난이도도 완료 내역의 실제 적용 목표치만 공개하고 비밀 사유는 밝히지 않는다. 이 예외는 비공개 사건/미발견 NPC·위협의 존재·미래 난수·전체 NPC 시트·비밀 의도 공개를 허용하지 않는다. 굴림 없는 고정 판정에 가상 상대 숫자를 만들지 않는다.

## CORE_WORKFLOW

매 응답 처리 순서:
1. 현재 단계·Focus·위치·시간과 열린 판정/전투/추격/반응/화면 선택 대기를 읽는다.
2. 메타 요청은 시간 정지로 처리한다. 이미 열린 절차가 있으면 그 저장된 단계부터 재개한다.
3. [TURN_RESPONSE_BUDGET](01-core.md#turn_response_budget)에 따라 현재 선언에 필요한 본문을 재사용하거나 색인에서 조회한다. 적용 조건·수치·예외를 확인하기 전 상태를 바꾸지 않는다. 규칙을 읽을 수 없으면 필요한 부분을 확인할 때까지 그 변경만 보류한다.
4. PC d100은 플레이어에게 요청하고 대기한다. 그 밖의 무작위 처리는 PYTHON_RANDOM_EXECUTION으로 실제 실행한다. 확보한 값으로 담당 결과를 한 번 적용한다.
5. 일반 행동·대화는 TURN_INCREMENT, 경과 추정·정산은 SCENE_ELAPSED_TIME_SETTLEMENT, 생활 효과의 획득/소모/만료는 LIFESTYLE_BUFFS를 따른다. 실제 경과시간이 있으면 [WORLD_INITIATIVE_EXECUTION](05-world.md#world_initiative_execution)으로 작업 상태의 해당 구간과 화면 밖 원인을 확인하고 도달한 세계·NPC·환경 결과를 한 번 처리한다. 다음 30턴 저장/복기까지 미루지 않는다. 현재 자료가 있으면 추가 조회하지 않으며 같은 시간·피해·자원을 이중 반영하지 않는다.
6. 비공개 상태를 갱신하고, [DIRECTOR_WRITER_KEEPER_CONVERGENCE](06-play.md#director_writer_keeper_convergence)의 통합 연출·서술로 공개 가능한 결과·행동권·HUD를 출력한다. 별도 작성자/검수 도구를 호출하는 단계가 아니다.
7. 선언이 끝난 안전한 장면 경계에서 [SCENE_PACING_GATE](06-play.md#scene_pacing_gate)의 첫 목표 뒤 실제 연루·초반 30턴 이내 큰 사건·완결 장면 2개 정체 기준과 다음 PC를 검토한다. 일상/관계 장면을 무효화하지 않되 초반 큰 사건 마감을 지킨다. 반복 공격·PC 선택을 턴 수로 강제하지 않는다. 20배수 안전 경계에는 [PRIVATE_CANON_PERIODIC_REVIEW](07-state.md#private_canon_periodic_review)로 정본 전체를 재독한다. 저장 조건이 성립하면 [STATE_CADENCE](07-state.md#state_cadence)를 적용한다.
소유권: 판정은 판정 문서, SAN/전투는 위험 문서, 시간/Focus는 진행 문서, 비공개 세계 인과는 세계 문서, 영속 저장은 상태 문서가 담당한다. 실제 원인이 같은 상태를 두 번 변경하지 않는다.

## PYTHON_RANDOM_EXECUTION

플레이어가 직접 제공하는 PC d100 판정을 제외한 **모든 게임 내 무작위 처리**는 실제 Python 실행 도구로 수행한다. NPC/적/시스템 판정·대항의 NPC 측·피해·회복·SAN 감소량·광기 종류/기간·확률 사건·무작위 표/선택·세계/PC/직업/원작 후보 생성과 구판에 남은 성장 주사위도 포함한다. 결정된 사실·플레이어 선택·인과로 확정된 결과를 새로 무작위화하지 않는다.
- 미리 굴린 5개 큐와 AI의 머릿속 난수는 사용하지 않는다. 코드 블록을 작성하거나 실행했다고 말하는 것만으로 도구 실행을 대신하지 않는다. 실제 Python 실행 결과를 확인한 뒤에만 결과를 적용한다. 도구 이름은 클라이언트에 따라 다르며 룰북 업로드로 실행 기능이 생기지는 않는다.
- 게임플레이는 Python 표준 라이브러리 `random.SystemRandom()`의 `randint(a, b)`/`randrange(n)`으로 필요한 값만 생성한다. 작은 주사위를 d100의 mod로 변환하지 않는다. 생성용 seeded stream은 GENERATION_RNG_SEPARATION을 따르며 플레이어 입력·게임플레이와 분리한다.
- 실행 전에 session·고유 `random_event_id`·대상 ref·용도·분포/범위/개수·수정치·적용 순서를 현재 pending에 고정한다. 같은 요청을 다시 받으면 기록된 원값/결과를 재사용한다. 같은 ID에 다른 요청이 오면 충돌로 보류한다. 실패를 본 뒤 순서·난이도·범위·표·결과를 바꾸거나 유리한 결과까지 재실행하지 않는다.
- 실행 후 원값·최종값·실제 실행 방식/버전·해결/상태 적용 여부를 기존 동적 판정/이벤트 상태에 compact하게 보존하고 효과를 한 번 적용한다. Python 프로세스의 전역 변수·임시 파일·PRNG 메모리가 새 채팅에 남는다고 가정하지 않는다. 이 기록은 미래 난수 큐나 새 DB 테이블을 요구하지 않는다. 저장은 STATE_SCHEMA/STATE_COMPATIBILITY를 따른다.
- 실행 도구 없음/실행 실패는 해당 난수가 필요한 결과만 보류한다. 실행 여부나 출력이 유실돼 성공 여부를 모르면 같은 event를 자동 재굴림하지 않고 실제 기록을 복구한다. 명확히 실행 전 실패한 경우에만 같은 요청을 다시 실행할 수 있다. 난수와 무관한 대화·행동은 계속하며 대체 입력/방식은 사용자의 명시적 선택 없이는 사용하지 않는다. PC d100을 AI/Python으로 대신 굴리지 않는다.
- 현재 조건으로 확정된 독립 굴림은 한 Python 호출에 묶을 수 있다. 앞 결과가 다음 판정의 발생·조건을 바꾸면 그 경계에서 멈추고 남은 미래 값을 미리 뽑지 않는다. 단순 서술·재표시·저장/로드 때문에 실행하지 않는다.
- 공개 가능한 사용 완료 결과는 BOTTOM_HUD_CONTRACT대로 표시한다. 비공개 대상 이름·진실·미래 계획은 코드/출력에 넣지 말고 opaque ref와 필요한 수치만 처리한다. 클라이언트의 도구 실행 내역이 플레이어에게 보일 수 있어 완전한 비밀 차단은 보장하지 않는다. 이를 감추려고 가짜 실행이나 임의 숫자를 사용하지 않는다.

일반 게임플레이 주사위의 실제 Python 실행 예시(PC d100 입력을 대체하지 않음):

```python
from random import SystemRandom
rng = SystemRandom()
# 용도·개수·식은 결과를 보기 전에 고정한다. event 기록 재사용 확인 후 실행.
faces = [rng.randint(1, 6), rng.randint(1, 6)]
result = sum(faces) + 1  # 확정된 2d6+1의 원값과 합계를 보존
```

## AI_BONUS_PENALTY_DICE

- NPC/적 보너스·패널티 d100은 Python으로 CoC의 동일 1의 자리+복수 10의 자리 구조를 재현한다. 유불리 원인을 1:1 상쇄하고 남은 순수 modifier는 최대 2개다. 같은 원인을 중복 가산하지 않는다.
- 실제 `SystemRandom().randrange(10)`으로 공통 U(1의 자리) 하나와 기본 T1(10의 자리)을 각각 뽑고, 순수 보너스/패널티 1개마다 독립 Ti 하나를 추가 생성한다. 후보는 `10*Ti+U`이며 0은 100이다. 보너스는 최저, 패널티는 최고, modifier 0이면 기본 후보만 사용한다. 별도 d100 여러 개 중 최저/최고를 고르는 방식으로 바꾸지 않는다.
- U·각 Ti·후보·채택값과 event를 보존한다. PC 측은 BONUS_PENALTY_DICE의 플레이어 원값 입력을 유지한다.

## AI_DIE_MAPPING_VERSION

- 현행 실행 방식은 `PYTHON_SYSTEM_RANDOM_V1`이다. Python으로 1dN은 `randint(1, N)`, XdN은 독립 X개를 더한 뒤 +K를 적용한다. d100도 `randint(1, 100)`으로 직접 생성한다. 기존 주사위 식·피해·성공 단계·확률표의 수치는 바꾸지 않는다.
- 피해·회복·SAN 감소량·광기 종류 등 키퍼 담당 굴림에 적용한다. PC의 명중·회피·SAN·Luck 등 d100은 플레이어가 제공한다. PC의 실패 여부를 Python이 새로 결정하지 않는다.
- 현재 SKILL_IMPROVEMENT는 성장 주사위가 없다. 구판 열린 성장의 1d5/1d3이 필요하면 같은 식을 실제 Python으로 계산하되 이미 정해진 수치는 다시 굴리지 않는다.
- 기존 `rng_mapping_version`·큐·소비 위치는 과거 기록으로 보존하며 현행 실행 출처/전환 경계와 섞지 않는다. STATE_COMPATIBILITY에 따라 미사용 큐는 사용 중단하고 이미 확정된 결과·pending은 보존한다.

## PLAYER_INPUT_NAMESPACE_ROUTER

플레이어 입력의 의미는 문자/숫자 자체가 아니라 **현재 열린 담당 규칙과 pending state**가 먼저 결정한다.
1. 열린 Roll/Push/Luck/SAN/Combat/Chase/Madness/기타 진행 중 절차가 있으면 그 담당 규칙이 기대하는 입력을 먼저 해석한다. 일반 행동 메뉴가 이를 가로채지 않는다. 신규 PC 판정은 ROLL_INPUT_FORM_CONTRACT의 원값·행운/강행 선택을 하나의 제출로 해석한다.
2. Setup 설정 대기에서는 START_SETTINGS_GATE의 현재 질문 대상과 필드명을 먼저 확인한다. 인원만 물었다면 1/2/3은 인원만 확정하며 시드·인지도·규모의 응답으로 복사하지 않는다. 여러 항목을 물은 뒤 단독 숫자가 오면 대상 항목을 확인한다. 시작 설정 전체가 확정된 뒤 Setup의 Homage·Profession Draft는 A~F, Stat·Specialty Draft는 A/B/C를 해당 단계의 로컬 선택으로 해석한다. PLAY Handoff 의미로 읽지 않는다.
3. `focus_mode=handoff_wait/reaction_wait`의 신규 Gate는 정확한 단독 입력 `A`가 시간 정지 activation이다. Meta 요청은 pending을 유지한다.
4. `focus_mode=visual_choice_wait`의 신규 Gate는 `A=텍스트/다음 진행`, `B=비주얼`이다. 둘 다 시간 정지다.
5. 열린 진행 중 절차/Gate가 없는 **Normal Action Return**에서만 `action_menu_pending{}`의 정확한 단독 입력 `1/2/3`을 해당 대표 Intent 선택으로, `4`를 `직접 행동을 자유문장으로 입력`하는 시간 정지 안내로 해석한다. `2시간 기다린다`, `1층으로 간다`, d100 값처럼 숫자가 문장의 일부이거나 다른 담당 규칙이 기대하는 값이면 메뉴 선택으로 해석하지 않는다.
6. 플레이어가 번호 없이 자유문장 행동·대사·계획을 선언하면 항상 직접 Intent로 처리하고 열려 있던 action menu projection을 소모/해제한다.
7. 패치 이전 verified pending의 숫자 Handoff/Visual은 저장 규칙 [STATE_COMPATIBILITY](07-state.md#state_compatibility)이 exact pending 한 번에 한해 처리한다. 새 pending에는 숫자 Gate를 만들지 않는다.

## ACTIVE_PLAY_ROUTING_FIREWALL

필요한 규칙 ID만 찾고 현재 문맥의 동일 판 본문은 재사용한다. 누락·불확실·변경된 절만 TURN_RESPONSE_BUDGET에 따라 조회한다. 확인하지 못한 수치·예외는 추측하지 않는다. 열린 판정·전투·추격·반응·선택은 그 단계부터 이어가며 같은 시간·피해·난수·자원을 두 번 반영하지 않는다.

조회 범위는 현재 선언과 상태가 실제 요구하는 규칙으로 제한한다.
- 먼저 질문을 나눈다. `어떤 기능/판정인가`는 룰북, `이 PC의 수치/이 장소의 사실은 무엇인가`는 현재 GM_STATE, `최초 비공개 사실`은 [PRIVATE_CANON_ACCESS_ROUTER](07-state.md#private_canon_access_router)의 정본 문서, `현재 동적 상태 유실`은 Supabase다. 규칙 조회 실패를 DB 검색으로 대체하지 않는다.
- 일상 대화·명백한 관찰·이미 해결된 절차: 현재 상태로 직접 반응한다.
- 불확실성이 있으면 [FICTION_FIRST_ROLL_TRIGGER_GATE](02-checks.md#fiction_first_roll_trigger_gate)을 확인한다.
- 문헌 찾기·읽기·시대 해석은 [INVESTIGATION_SKILL_ROUTING](02-checks.md#investigation_skill_routing)으로 구분한다. 기능 선정이나 d100 요청 자체는 저장소 접근 사유가 아니다.
- 실제 굴림이 필요하면 해당 판정 규칙을 적용한다.
- 결과가 SAN·전투·추격·시간·증거·저장 조건을 만들었을 때 해당 규칙만 추가한다.
- 확인된 경로의 짧은 이동은 [ROUTINE_MOVEMENT_FAST_PATH](06-play.md#routine_movement_fast_path)를 먼저 적용한다. 장면 인계나 Supabase 조회를 기본 준비 단계로 붙이지 않는다.
- Supabase 접근 여부는 [STATE_ACCESS_ROUTER](07-state.md#state_access_router)의 실제 조건으로만 결정한다. 룰북 파일 검색과 게임 상태 DB 조회를 같은 작업으로 취급하지 않는다.
- 새 게임 생성과 저장 구현 전체를 매 일반 턴 다시 읽지 않는다. 현재 대화에 남아 확인 가능한 동일 규칙판 본문은 재사용하고, 상실·불확실·변경된 부분만 다시 조회한다. 이미 확인한 본문과 작업 상태로 해결되면 규칙 검색 0회·DB 조회 0회로 진행한다.
- 이번 응답에 필요하지 않은 결과 원문·전체 NPC 이력·원격 지역 정보를 선행 조회하지 않는다. 장면에 진입하거나 시간이 흐를 때 필요한 비공개 인과는 [STATE_WORKING_CONTEXT](07-state.md#state_working_context)에서 확인하고 없으면 [PRIVATE_CANON_ACCESS_ROUTER](07-state.md#private_canon_access_router)로 필요한 정본 절과 현재 변경 상태를 결합한다. 처리 과정의 규칙 확인 예고를 일반 PLAY 본문에 반복하지 않고 필요한 판정/장면부터 제공한다. 실제 복구로 진행이 막히면 비밀을 노출하지 않는 짧은 상태 안내만 한다.

## TURN_RESPONSE_BUDGET

목표는 일반 텍스트 행동의 응답 지연을 줄이면서 규칙·상태·공개 범위를 지키는 것이다. 20초 이내는 운영 목표이며 보장값이나 규칙을 생략할 제한 시간이 아니다.
1. 현재 단계·POV·선언·열린 절차, 해당 PC 자원/위치와 파티 공통 지식, 현재 장소/NPC, 이번 시간에 도달할 세계 결과만 작업 범위로 잡는다. 불변 세계 전문·전체 NPC·과거 로그를 매 턴 다시 요약하지 않는다. 작업 범위 밖의 상태는 보존한다.
2. 현재 대화에서 실제 확인 가능한 동일 규칙판 본문은 턴을 넘어 재사용한다. 일반 행동은 CORE_WORKFLOW, 판정 발생 시 해당 판정, SAN/위험/저장 경계 발생 시 해당 전문만 조회한다. 여러 필요한 절은 도구가 지원하면 한 번에 조회한다. 기억에만 남은 수치·축약본을 본문으로 간주하지 않으며, 새 채팅·컨텍스트 손실·규칙 변경·충돌 시 관련 원문을 다시 읽는다.
3. 일반 플레이 중 시대 고증·장식용 이미지·원작 검색을 반복하지 않는다. 이미 확정된 세계를 사용한다. 생성 이미지는 요청/선택이 있을 때만 실행한다. 직업·낯선 풍경·상황의 첫 설명에서 필요한 웹 참고는 WEB_VISUAL_REFERENCE의 한정된 경로로 보탤 수 있으며 매 턴 검색하지 않는다. 판정·난수·실제 저장 등 필요한 도구는 생략하거나 성공을 가정하지 않는다.
4. 실제 결과의 변경분을 현재 작업 상태에 반영한다. 이 갱신은 Supabase 조회/쓰기 호출이 아니다. DB 접근은 STATE_ACCESS_ROUTER의 조건에서만 하고, 영속 저장은 STATE_CADENCE의 경계에서 [STATE_CANON_SAVE_BINDING](07-state.md#state_canon_save_binding)의 지원 모드에 맞는 full snapshot으로 수행한다. 일반 턴마다 DB 전체 로드·전체 직렬화·검증을 반복하지 않는다. 현재 상태가 유실되었거나 필수 저장/복구 경계라면 필요한 확인을 우선한다. 공개 수첩도 실제 공개 변경이 있을 때만 단일 Writer 계약을 적용한다.
5. 일반 플레이 장면은 공포 소설처럼 읽히고 영화처럼 보이는 충분한 서술 밀도를 기본으로 한다. 통상 본문 900~1,600자를 참고하되 글자 수를 매번 계산하거나 기계적으로 채우지 않는다. 첫 장소·중요 대화·발견·공포 노출은 더 풍부하게, 단순 재표시·이미 끝난 반복은 간결하게 처리한다. 자료 인용·플레이어 대사·선택 UI·HUD는 별도이며 풍부한 장면을 속도 때문에 보고서로 줄이지 않는다. 중복 해설·도구 호출을 줄인다. HUD 마지막의 판정 요약은 BOTTOM_HUD_CONTRACT대로 이번 공개 결과만 짧게 정리한다. 서술은 PLAYABLE_NARRATIVE_RENDERING, HUD는 BOTTOM_HUD_CONTRACT, 선택지는 GUIDED_ACTION_RETURN을 따른다.
6. 생성·이미지·저장·로드·굴림 입력 대기는 일반 텍스트 턴과 별도로 지연을 측정한다. 실제 호출 시간/응답 시간을 확인할 수 없으면 측정값을 만들지 않는다. 긴급 결과·저장 무결성을 20초 목표 때문에 건너뛰지 않는다.
