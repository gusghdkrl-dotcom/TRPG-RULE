# 공통 실행 원칙

규칙판: 생존 호러 통합 경량판 2026-11-08. 상시 서사·묘사는 프로젝트 지침, 상황별 조회는 00-index.md. 필요한 절만 읽는다.

## CORE_ZERO_HOMAGE_EXPERIENCE_GATE

적용: 게임의 공통 기준. 한국어 생존 호러 TRPG이며 CoC 7판 기반 하우스룰을 사용한다. 상시 서사·묘사·진행은 PROJECT_INSTRUCTIONS.md, 상황별 수치·예외는 이 룰북이 담당한다. 일반 CoC 지식으로 현행 수치를 덮어쓰지 않는다.
우선순위는 PC 주도권·공개 범위·확정 사실 보호 → 현재 담당 규칙의 조건/절차/예외 → 예시다. 충돌은 영향을 받는 처리만 보류해 확인한다. 예시는 설명 자료이며 특정 사건·인물·실패를 모든 캠페인에 복제하지 않는다.

## CORE_AGENCY

PC의 행동·대사·생각·감정·수락·추리 결론은 플레이어가 결정한다. 선언한 목적·방법·범위 안의 행동과 실제 반응을 처리하고, 새 결심·비용·약속·위험 감수가 필요한 지점에서 입력을 받는다. 광기 등 명시된 강제 효과만 해당 범위에서 예외다.
키퍼는 NPC·세계·판정 결과를 담당한다. 분리된 PC도 실제 시간과 외부 영향을 겪지만 미선언 행동·소모·휴식·성과를 자동 실행하지 않는다. PC 감정 점수·숨은 배신 역할을 자동 생성하지 않는다.

## CORE_VISIBILITY

공개 범위는 플레이어 전체와 아직 발견하지 못한 세계 사이에 둔다. 같은 채팅에서 공개된 장면·PC의 공개 배경·단서·NPC 발언·가설은 파티 공통 지식이다. PC끼리 전달·재합류를 요구하지 않는다. 발견자·시점·출처와 가설/검증 결론은 구분한다.
공유가 위치·행동권·소지품·능력·관계·직접 감각을 합치지는 않는다. NPC는 실제 목격·청취·전달·추론한 범위만 안다. 공개된 플레이어 사실을 NPC에게 자동 전달하지 않는다. 직접 목격형 SAN 노출은 실제 노출 PC에게, 정보 자체의 충격은 그 내용을 알게 된 PC에게 적용한다.
지문·HUD·지도·이미지는 미발견 진실·상대·의도·위협·미래 결과를 선행 공개하지 않는다. 원작 메타 지식도 이번 세계의 정답을 자동 확정하지 않는다.
사용 완료 수치 공개 예외: 공개된 행동의 판정 종료 뒤 실제 요구값·양측 기능/특성·원값·최종값·단계·비교 결과를 BOTTOM_HUD_CONTRACT에 공개한다. 공개 판정의 NPC 수치도 이 범위에서 포함하되 비밀 사유·전체 시트·비공개 사건·미래 난수는 숨긴다.

## CORE_WORKFLOW

현재 입력을 열린 판정/행동/반응/설정 단계에서 해석하고, 이번 처리에 필요한 상태와 규칙만 사용한다. 필요한 동일 판본 본문이 현재 확인 가능하면 재사용하고 유실·충돌·변경 부분만 조회한다. 메타 요청과 재표시는 극중 시간 정지다.
확정된 조건으로 필요한 PC d100을 받거나 실제 Python 난수를 실행하고 직접 결과를 한 번 반영한다. 활동에 맞는 경과와 관련된 WORLD_INITIATIVE_EXECUTION 결과를 함께 처리한다. 공개 가능한 장면·다음 판단·HUD를 제공하고 실제 변경분과 맥락을 STATE_WORKING_CONTEXT에 반영한다. 저장 경계만 STATE_CADENCE를 실행한다.
별도 작성자/검수 모델·매 응답 전수 점검·규칙 확인용 DB 조회 단계는 만들지 않는다. 현재 필요한 사실이 없으면 해당 처리만 복구하며, 규칙 조회 실패를 저장소 탐색으로 대체하지 않는다.

## PYTHON_RANDOM_EXECUTION

PC d100을 제외한 모든 게임 내 무작위 처리는 실제 Python 실행 결과를 사용한다. NPC/적 대항·피해·회복·SAN 감소·광기·확률 사건·후보/세계 생성 포함. 코드 제시나 머릿속 숫자는 실행이 아니다. 확정 사실·선택을 새로 무작위화하지 않는다.
게임플레이는 random.SystemRandom()으로 필요한 1dN은 randint(1, N), XdN은 독립 X개 합계에 확정 수정치를 적용한다. 미리 만든 미래 큐는 쓰지 않는다. 생성은 GENERATION_RNG_SEPARATION의 별도 seeded stream이다.
실행 전 random_event_id·대상 ref·용도·식/범위/개수·수정치·적용 순서를 고정한다. 실행 뒤 원값·최종값·실행 방식 PYTHON_SYSTEM_RANDOM_V1·해결/적용 여부를 기록한다. 같은 이벤트는 기존 확정값을 재사용하며 결과를 보고 조건/식을 바꾸거나 재굴림하지 않는다.
현재 조건으로 독립인 굴림은 한 호출로 묶을 수 있다. 앞 결과가 후속 판정의 발생/조건을 바꾸면 그 경계에서 멈춘다. PC d100을 AI/Python으로 대신 굴리지 않는다.
도구 없음/명확한 실행 전 실패는 해당 결과만 보류한다. 성공 여부를 모르면 같은 event를 자동 재굴림하지 않고 실제 기록을 복구한다. 난수와 무관한 진행은 계속한다. Python 커널/파일의 영속성을 세이브로 가정하지 않는다. 실행 내역이 플레이어에게 보일 수 있으므로 코드에는 비공개 이름/진실 대신 opaque ref와 수치만 쓴다.

```python
from random import SystemRandom
rng = SystemRandom()
faces = [rng.randint(1, 6), rng.randint(1, 6)]
result = sum(faces) + 1  # 사전에 고정한 2d6+1
```

## AI_BONUS_PENALTY_DICE

NPC/적의 유불리는 BONUS_PENALTY_DICE와 같은 분포다. 1:1 상쇄 후 남은 최대 2개를 적용한다. Python SystemRandom().randrange(10)으로 공통 U(1의 자리), 기본 T와 추가 T들을 독립 생성한다. 후보=10*T+U, 0은 100. 보너스는 최저/패널티는 최고를 채택하고 U·각 T·후보·최종값·event를 보존한다. 별도 d100 여러 개의 최저/최고로 바꾸지 않는다.

## PLAYER_INPUT_NAMESPACE_ROUTER

입력의 의미는 현재 질문/열린 절차가 결정한다. 굴림·행운/강행·SAN·전투·추격·광기·반응 입력이 일반 행동 메뉴보다 우선한다. 설정 중 단독 숫자는 지금 물은 항목에만 적용하고 후보 문자는 해당 단계/PC의 후보에만 대응한다. 지연/중복 응답을 다음 단계에 재사용하지 않는다.
일반 행동 메뉴의 단독 번호는 저장된 그 선택의 intent로 해석한다. 문장 속 숫자·굴림값을 메뉴로 읽지 않는다. 자유문장 행동·대사는 항상 직접 선언으로 받고 이전 메뉴를 해제한다. 불명확한 대상만 짧게 확인하고 이미 유효한 값은 보존한다. 교대 준비/이미지 선택을 위한 별도 A/B 대기는 만들지 않는다. 구판 pending은 STATE_COMPATIBILITY를 따른다.
