# 시작·원작·PC·세계와 시나리오 생성

규칙판: 생존 호러 통합 경량판 2026-11-08. 상시 서사·묘사는 프로젝트 지침, 상황별 조회는 00-index.md. 필요한 절만 읽는다.

## START_SETTINGS_GATE

적용: 신규 게임. 필수 입력은 참가 인원1~3명·인지도(메이저/기본/마이너)·이야기 규모(대사건/연대기)다. 신규 시작의 첫 설정 화면에 **`영구 성장 적용: ON / OFF`**를 함께 표시하며 미입력 시 **ON**이다. ON은 계정 누적 성장치의 새 PC 특성 적용, **OFF는 이번 캠페인 PC의 8대 특성에만 영구 성장 보너스0 적용**이다. OFF여도 계정의 영구 성장 레벨·성장/카드 보상·도감은 유지한다. 전원 공통 설정을 PC 연결 전에 확정해 `permanent_growth_enabled=true/false`로 시작 설정/정본·상태에 기록하고, PC 연결 뒤 기존 스냅샷을 소급 재계산하거나 변경하지 않는다. 시작 시드는 Python SystemRandom으로1~100 정수를 자동 생성해 start_seed에 기록한다. 플레이어에게 핵심/시작 시드 숫자를 입력받지 않는다.
선택 입력은 배제할 세계관·직접 지정 원작/장르/시대다. 최초 빈칸은 없음이며 이후 부분 응답에서 생략된 기존 값은 유지한다. PC 사전 관계의 별도 입력은 없다. 받은 유효 값은 보존하고 누락/오류/실제 모호함만 질문한다. 인원만 받은 숫자를 인지도/규모에 복사하지 않는다. 인원을2명으로 자동 결정하지 않는다.
설정을 돕는 검색·도구·시드 생성은 허용한다. 미확정 조건에 의존하는 원작/PC/세계 생성만 기다린다. 완료 입력은 짧게 정리하고 재승인 없이 다음 단계로 간다. 기존 캠페인은 신규 설정 대신 STATE_RESUME을 따른다.

## SETUP_UI_FIXED_CONTRACT

실제 입력 도구가 있으면 사용하고 없거나 실패하면 동일 항목을 일반 채팅으로 받는다. 별도 전환 승인이나 기능 설명을 매번 요구하지 않는다. 코드/그림/HTML을 입력 위젯으로 가장하지 않는다.
현재 대상PC·단계·후보 문자/값·필수 정보와 입력 의미는 보존한다. 제목·항목 순서·문장/행 수는 상황에 맞게 표시한다. 선택 대기는 하나의 현재 단계로 명확히 하고 무관한 플레이 메뉴/HUD를 섞지 않는다. 자동 처리는 다음 실제 선택까지 이어갈 수 있다.
잘못된 항목만 수정받고 이미 받은 값·생성 후보·수치를 다시 뽑지 않는다. 세계 브리핑/확정 프로필은 읽기 자료이며 표시를 위해 확인 질문을 만들지 않는다. 이미지 제공은08-visual을 따른다.

주 클래스 선택 화면은 닉네임·영구 보유 카드의 실제 조회 결과를 확인한 뒤 **`3단계 · 주 클래스 선택`** 제목과 짧은 설명 아래, **수호자→탐구자→무법자→기회주의자→생존자** 순서로 각각 한 장의 세로형 선택 카드/항목을 표시한다. 아컴호러 카드게임의 클래스 구별 방식처럼 다섯 고유 색을 일관되게 사용하되, 공식 카드 프레임/이미지를 복제하지 않는다. **수호자 파랑 `#54A9F3`, 탐구자 노랑 `#E6B63D`, 무법자 초록 `#39B77B`, 기회주의자 보라 `#A87BE2`, 생존자 빨강 `#DC5963`**으로 고정한다. 실제 UI의 색상/표면 스타일 지원 시 카드 테두리·좌측 강조선·클래스명·아이콘에 같은 색을 적용하고 어두운 배경 위 가독성을 유지한다. 지원되지 않는 색상·카드 꾸밈을 가짜 HTML/CSS나 그림으로 가장하지 않고 같은 순서의 선택 버튼/텍스트에 🔵/🟡/🟢/🟣/🔴를 각각 붙인다. 이미지 생성 요청으로 해석하지 않는다.
각 항목은 **클래스 이름 + 다음 한 줄 요약 + 클래스별 실제 보유 수치 한 줄**만 기본 표시하며, 개별 자산/강화 카드 이름·능력 설명·기본 지급 카드명/희귀도 목록은 이 화면에서 반복 나열하지 않는다. 요약 문구는 다음과 같이 고정한다.
- 수호자: `방어·보호·구조에 특화. 위험 앞에서 동료와 거점을 지킨다.`
- 탐구자: `관찰·분석·기록에 특화. 단서와 환경 정보를 빠르게 읽는다.`
- 무법자: `잠입·우회·이탈에 특화. 봉쇄와 추적을 비껴간다.`
- 기회주의자: `위험 감수·거래·변칙에 특화. 불리한 판을 뒤집는 데 능하다.`
- 생존자: `환경 적응·버티기·재활용에 특화. 실패 속에서도 다음 수를 만든다.`
수치 표시 형식은 `보유 카드 N장 · 자산 A · 강화 E`로 고정한다. **N=A+E**이고 A/E는 현재 입력 플레이어의 실제 검증된 영구 컬렉션에서 **해당 클래스 전용** 소유 카드 ID를 중복 없이 유형별로 센 값이다. **중립(NE) 카드는 어느 클래스 수에도 합산하지 않는다.** 새 계정의 클래스별 기본 1자산+1강화가 실제 지급·조회됐다면 `보유 카드 2장 · 자산 1 · 강화 1`로 표시할 수 있지만, 새/기존 계정의 소유를 확인하지 않고 2/1/1을 고정 숫자로 복사하지 않는다. 조회 불가/불완전이면 해당 수치에 `미확인`을 표시하고 확인된 소유를 조작하지 않는다. `보유`와 `장착`은 별개이며 비선택 클래스 소유도 정상 표시한다.
실제로 동작하는 선택 UI라면 각 카드/버튼의 선택 이벤트를 해당 클래스의 고정 ID(GU/SE/RO/WI/SU)에 연결하고 캠페인 가입/클래스 확정의 실제 기존 절차로 전달한다. 선택 클릭만으로 카드 장착·물품 지급·서버 성공을 가장하지 않는다. 실제 카드 UI가 없으면 동일 항목을 색상 표시 가능한 채팅 옵션으로 보여주고 문자/이름으로 입력받는다. 선택 대기를 다섯 번 쪼개거나 상세 카드 설명 단계를 강제하지 않는다.

**카드 시스템은 `전체 카드 도감`과 `4단계 · 영구 카드 장착` 두 화면으로 나눈다.** 도감은 전체 카드·효과·소유 현황을 열람하는 곳이며 장착 화면은 보유 카드로 4슬롯을 구성하는 곳이다. 도감은 클래스 선택 전·장착 도중·플레이 중 요청 시 열 수 있고, 열람/검색/효과 확인은 게임 시간·위험·PC 행동·카드 소유/장착/보상을 변경하지 않는다.

**전체 카드 도감:** 기존 정식 자산33장+강화33장 **전체 66장**을 모두 보여준다. **보유·미보유** 카드를 함께 열람하고 미보유 카드도 정확한 효과를 볼 수 있지만 장착할 수 없다. 실제 조회된 소유만 `보유 N/66`에 반영한다. **클래스 5종/중립·자산/강화·일반/희귀/영웅/전설·전체/보유/미보유 필터, 카드명 검색, 결과 수, 더 보기/페이지 이동**을 지원한다. 전량을 한 화면에 출력하지 않고 필터 결과만 페이지별로 보여준다. **영구 성장8종은 별도 `성장` 탭**에서 CARD_PERMANENT_GROWTH대로 실제 Lv.0~5·대상 특성·증가값·다음 단계 성공률을 표시한다. 성장8종은 66장 수집 카드나 4슬롯 장착 후보에 합산하지 않는다.

도감 카드 행은 클래스 아이콘·희귀도 이름색·카드 종류/소속/등급·실제 보유 상태·짧은 효과 설명을 보여주며, **`상세 보기`에서는 원래 발동 시점·전제 행동/성공 조건·효과 수치·한계·시대/실물 제한을 모두** 읽는다. 효과는 **`09-cards.md`의 동일 카드 ID 원문**을 사용한다. 운영 `card_catalog`에는 ID/제목/소속/유형/희귀도/기본 여부/순서만 있고 **효과 원문 칼럼은 없다**. 메타데이터와 소유는 기존 조회에, 카드 효과는 원문에 연결하며 효과를 추정/발명하지 않는다. 원문을 확인할 수 없으면 `상세 효과 확인 불가`, 소유를 검증하지 못하면 `보유 상태 미확인`으로 표시한다.

**4단계 · 영구 카드 장착은 4개의 슬롯을 먼저 선택**하게 한다. 상단에 `장착 가능 N장 · 선택한 카드 K/4장`과 슬롯 현재 선택/빈 상태를 표시한다. **`1 · 클래스 자산 전용`, `2 · 클래스 강화 전용`, `3 · 자유 슬롯 1`, `4 · 자유 슬롯 2`** 중 하나를 고르면 **그 슬롯에 장착 가능한 실제 보유 카드만** 아래 후보 목록에 표시한다. 최초에는 1번 슬롯을 선택한다. 1번은 주 클래스 소유 자산, 2번은 주 클래스 소유 강화, 3·4번은 주 클래스/중립 자산·강화만 허용하고 타 클래스/미보유·다른 슬롯에서 선택된 중복 카드는 제외한다. 후보에도 카드명 검색·자산/강화·주 클래스/중립·등급 필터·결과 수·더 보기/페이지 이동을 제공하며, 부적합 필터는 비활성이다. 26장까지 장착 가능 카드가 늘어도 전량 장문으로 펼치지 않는다. 상세 효과는 도감과 같은 카드 ID 원문을 사용한다.

이전 자산/강화의 **자산 펼침/강화 접힘** 고정 기본 화면 대신 종류별 표시를 슬롯 후보/도감의 선택형 필터로 통합한다. 필터·검색·접기·상세/도감 열람은 **선택·장착·소유 상태를 바꾸지 않으며** 다른 슬롯으로 이동해도 최종 확정 전 선택 4장을 유지한다. 플레이어가 4장 최종 확정을 명시하고 기존 장착 제약을 통과했을 때만 `save_loadout`으로 저장하며 그 전에는 확정 성공으로 표시하지 않는다. 실제 UI 컨트롤을 지원하면 슬롯·검색·필터·페이지·상세의 동작을 연결하고 미지원이면 `도감/카드 ID 상세/클래스·종류·등급·소유 필터/카드명 검색/슬롯1~4/더 보기` 요청으로 필요한 범위만 채팅에 표시한다. 정적 이미지·가짜 버튼으로 인터랙션을 가장하지 않는다.
카드 한 장의 기본 정보는 **`[카드 유형] [클래스/중립] [등급] 카드명` + 실제 효과/중요 제약 + 현재 선택 여부**를 명확히 표시한다. 유형은 `🧰 자산`/`⚡ 강화`, 소속은 **주 클래스 5색(3단계의 동일 색상), 중립은 회색 `#9CA3AF`**, 등급은 **일반 회색 `#9CA3AF` · 희귀 청록 `#28B8D8` · 영웅 보라 `#AD70E8` · 전설 금색 `#E9B949`**으로 구분한다. **이름 바로 앞에는 색상 있는 클래스 고유 아이콘**, **카드 이름 글자색에는 실제 희귀도 색상**을 지정한다. 클래스 아이콘은 **수호자 파란 방패(`shield`)**, **탐구자 노란 눈(`scan-eye`)**, **무법자 초록 열쇠(`key-round`)**, **기회주의자 보라 주사위(`dice-5`)**, **생존자 빨간 배낭(`backpack`)**, **중립 회색 원형(`circle-dot`)**으로 고정한다. 아이콘은 3단계와 같은 클래스 색, 이름은 위에서 정한 등급별 일반 회색·희귀 청록·영웅 보라·전설 금색을 사용한다. 각각 다른 의미이므로 카드 전체에 클래스/등급색을 한꺼번에 칠해 혼동시키지 않는다. 소속은 아이콘+클래스명, 등급은 이름색+등급명, 카드 종류는 자산/강화 라벨로 구분한다. 스타일·아이콘 미지원 시 🛡️/👁️/🗝️/🎲/🎒/⚪와 소속·등급·유형 텍스트로 대체하고 색만으로 구별하도록 만들지 않는다. 등급/소속은 실제 카드 카탈로그의 ID/원문을 쓰고 `[초록 열쇠] 우회 공구함(이름색 희귀 청록) · 무법자 · 희귀 · 자산`, `[회색 원형] 충격을 흘린다(이름색 일반 회색) · 중립 · 일반 · 강화`처럼 구별한다(표현 예시는 실제 카드의 소속/등급/유형에 맞을 때만 사용). 다른 클래스의 미소유/장착 불가 카드를 장착 후보로 표시하지 않는다.
클래스별 색은 정체성 표시, 등급별 색은 희귀도 표시이지 카드 능력의 추가 보너스가 아니다. **중립은 일반 등급이고 클래스 전용은 희귀·영웅·전설**이라는 기존 분류를 보존하며, 보유/선택/장착을 혼동하지 않는다. 슬롯 이름과 후보는 **`1 · 클래스 자산 전용`(선택한 주 클래스 자산만)**, **`2 · 클래스 강화 전용`(같은 주 클래스 강화만)**, **`3 · 자유 슬롯 1`/`4 · 자유 슬롯 2`(주 클래스/중립 자산·강화)**로 고정한다. 1·2번 드롭다운에는 중립 카드를 제외하고 3·4번에도 미소유·다른 클래스 카드를 넣지 않는다. 선택/해제는 해당 고유 카드 ID와 4슬롯의 실제 제약·중복/소유 확인에 연결한다. 접힘/펼침·정보 열람만으로 선택을 바꾸거나 `save_loadout`을 호출하지 않는다. 최종 장착 확정은 기존 승인/실제 검증 절차 이후에만 표시한다.


## CAMPAIGN_SETUP_PIPELINE

시작 설정 → 원작 A~D 선택(직접 지정이면 확정) → P1부터 전원 PC 생성 → 세계·시나리오와 연결 설계 → COMPATIBILITY_GATE → 공개 브리핑/최종 프로필·비공개 정본 → setup_bootstrap 저장 시도 → 게임 시작 입력 대기.
영구 카드 시스템 적용 신규 게임은 플레이어별 **고유 닉네임(2~24자)**을 받아 Supabase `trpg-state-v2`의 **`public.card_login` 공개 RPC 또는 권한 있는 키퍼 연결**로 **닉네임→영구 UUID**를 조회/등록한다. 신규 UUID에 기본 카드18장(자산9·강화9)을 한 번 영구 지급하고, 기존 닉네임을 입력하면 확인 절차 없이 기존 소유·성장으로 들어간다. **사용자 요청에 따라 별도 로그인·비밀번호·OTP를 요구하지 않는 2~3인 신뢰 운영**이며, 그 닉네임을 아는 누구든 다른 사람의 카드 계정에 접속할 수 있다. 공개 `card_*` RPC만 허용하며 비공개 GM 게임 상태/검증 세이브는 공개하지 않는다. 실제 연결 실패/조회 불명은 가입·지급 성공으로 표시하지 않고 관련 처리만 보류한다.
캠페인 고유 ID와 참가 UUID를 연결하고 플레이어별 주 클래스(수호자·탐구자·무법자·기회주의자·생존자)를 캠페인 시작 전에 선택·고정한다. 클래스 선택 화면은 SETUP_UI_FIXED_CONTRACT의 **다섯 색상·간결한 요약·검증된 소유 카드 자산/강화 집계·실제 선택 이벤트** 표시 규격을 적용한다. PC의 성장 적용 전 **8대 원본 기본 특성**을 확정한 뒤 설정의 `permanent_growth_enabled`를 `public.card_link_pc_with_growth_mode(p_nickname,p_campaign_id,p_pc_id,p_base_stats,p_permanent_growth)`에 전달하여 PC identity를 연결한다. ON에서는 누적 성장이 반영되고, OFF에서는 `applied_growth` 8종0·`applied_stats`=원본 특성임을 실제 반환값으로 확인한다. OFF여도 계정 성장 레벨은 보존한다. 모드 지원 RPC 연결이 실패하면 OFF를 ON 전용 RPC로 대체하지 말고 연결 성공 표시를 보류한다. 기존 연결된 PC의 스냅샷은 재사용한다. 반환된 `applied_stats`로 시트를 만들고 기존 PC 파생값을 산출한다. 연결 당시 영구 성장 단계만 반영하며 같은 PC의 재연결/재개로 재적용하지 않는다. 영구 카드 소유와 PC 실물 소유를 구별한다.
캠페인 시작 장착 화면은 SETUP_UI_FIXED_CONTRACT의 **4슬롯 우선 선택→적격 소유 후보 필터/검색·더 보기·카드 효과 상세·색상·실제 선택 개수**를 적용한다. 전체 도감은 66장/성장8종을 포함하되 미보유 카드와 성장카드는 장착 후보가 아니다. 캠페인 시작 장착은 **1번 주 클래스 자산 전용1·2번 주 클래스 강화 전용1·3/4번 자유2**로 구분하며, 1·2번은 주 클래스의 소유 카드만, 3·4번은 주 클래스 또는 중립의 소유 카드만 허용하고 `trpg_cards.save_loadout`의 실제 검증 결과로 고정한다. **직업 필수 시작물품 1개**는 종전대로 유지하되, 장착한 자산 카드의 실물/동행 동물은 **별도 카드 지급으로 처음 한 번만** 원작 시대·법칙에 맞춰 제공한다. 기존 메인/파우치 소지 제한과 물품 소모·분실/동물 상태를 그대로 적용한다. 시대에 없는 장비나 새로운 무게·하중 규칙을 만들지 않는다. **실제 카드 자산/강화의 소속·ID·발동 조건·효과·시대별 물품·실물 지급과 성장 수치**는 `09-cards.md`의 CARD_SYSTEM_SCOPE·CARD_EQUIP_AND_ASSET·CARD_ENHANCEMENT_TRIGGER·CARD_PERMANENT_GROWTH 및 해당 카드 절을 따른다. 상세 서버 호출과 Python 난수는 `docs/CARD_SYSTEM_RUNTIME.md` 및 `scripts/card_draft_rng.py`의 실제 계약을 따른다.
PC는 기본정보/특성+Luck A/B/C → APP 외형·배우 확정 → 직업 A~F 6개 후보 또는 직접 지정 → 취미 기능 1개 선택 → 직업 필수 시작 장비 1개·현금·프로필 순서다. 전문 분야 A/B/C 선택 단계는 없다. 전원 확정 전 비공개 사건을 맞춤 생성하지 않는다. 자동 이름/일상 배경은 실제 시대/문화·선택에 맞게 정한다.
게임 시작 선언 때 phase=play/scene_turn=1, 공개 시작 지도 handout 제공을 시도하고 play_start 저장 시도 뒤 첫 장면으로 간다. 지도 생성 실패는 동일 공간의 텍스트 대체로 첫 장면을 막지 않는다. 저장·검증 실패도 STATE_SAVE_FAILURE_CONTINUE로 진행한다. 설정 입력 자체는 게임 시작 선언이 아니다.

## GENERATION_RNG_SEPARATION

실제 무작위 생성만 Python으로 처리한다. 자동 start_seed는1~100, 이후 용도별 독립 named stream에 hashlib.sha256과 random.Random을 사용한다. 예: key=json.dumps(["PYTHON_GENERATION_V1", start_seed, axis_name, retry_index],ensure_ascii=False,separators=(",",":")); rng=random.Random(int.from_bytes(hashlib.sha256(key.encode("utf-8")).digest(),"big")). 내장 hash()는 쓰지 않는다.
직접 지정/이미 확정된 값은 재추첨하지 않는다. 현재 필요한 후보/표/분포를 추첨 전에 고정하고 축·원값·식/표·결과·retry사유를 보존한다. 부적격 미확정 항목만 해당 축으로 재생성하며 좋은 결과가 나올 때까지 재굴림하지 않는다. 서술/웹검색까지 seed로 동일해진다고 보장하지 않는다.
게임플레이 SystemRandom과 분리한다. 필수 독립 추첨축 목록은 없으며 원작/인과로 도출할 항목은 직접 설계한다. 선택지 다양성이나 실제 무작위가 필요할 때만 생성 난수를 쓴다. NORMALIZED_TABLE_INDEX는 기존1~100→N 참고표 매핑이며 엄밀한 균등 특성 생성은 전용 sampler를 사용한다.

## NORMALIZED_TABLE_INDEX

1~100 생성 시드 S를 N개 항목에 매핑할 때 index=floor((S-1)×N/100)+1을 사용한다. 이는 100개 값을 가능한 고르게 배분하는 기존 방식이며, N이 100의 약수가 아니면 항목별 확률이 완전히 같지는 않다. 엄밀한 균등성이 필요한 특성 생성은 전용 sampler를 사용한다. 서로 독립인 축은 서로 다른 named seed를 사용한다.

## GENRE_TABLE

원작/장르 직접 지정 우선. 미지정이면 start_seed의 독립 genre stream으로1d100을 실제 생성해 탐색 방향을 고른다. 장르는 작품 탐색용이며 괴물·초자연성·해결법을 미리 결정하지 않는다.
01~10 슬래셔/추격;11~20 붕괴/아포칼립스;21~30 실제 Cthulhu Mythos;31~40 밀실/구조적 위기;41~50 오컬트/초자연/고딕;51~60 서바이벌 호러;61~70 포크/지역 공동체;71~80 범죄/음모/사회;81~90 크리쳐/육체;91~100 심리/정체성.
매체·분위기·플레이 성향·공간 규모·영화적/극적/시스템적/고딕/기록물 등의 표현은 다양성 참고다. 모두 독립 추첨할 의무는 없으며 장르의 전형적 기믹을 한 세계에 합치지 않는다. 실제 법칙은 선정 원작과 사건에서 도출한다.

## HOMAGE_TIER

인지도는 플레이어가 선택하는 후보 풀의 성향이다. 메이저는 대중적 작품, 기본은 유명/중견/컬트/독립의 넓은 혼합, 마이너는 덜 알려진 작품 비중을 높인다. 숫자1/2/3과 이름을 같은 선택으로 받으며 미입력에 기본을 자동 적용하거나 난수로 고르지 않는다. 실제 세계를 구현할 만큼 확인 가능한 작품이어야 한다.

## AUTOMATIC_SF_HOMAGE_EXCLUSION

- 자동 Homage Candidate Pool에서는 **SF가 작품 정체성의 핵심 전제인 원작**을 제외한다. 우주선·우주 식민지·외계 행성 탐사, 미래 사회, 사이버펑크, AI/로봇 문명, 고도 미래기술 체계 자체가 세계의 기본 존재론·사회·위협 문법을 규정하는 작품은 Genre Family가 다른 호러와 겹쳐도 자동 후보로 올리지 않는다.
- **예외: Genre Family 21~30의 Cthulhu Mythos 전용 Pool에서는 실제 Mythos 정체성이 핵심인 적격 작품을 SF 요소만으로 제외하지 않는다.** 선택되면 그 작품의 SF/시대/기술 존재론도 원작 특징로 그대로 보존한다. 이 예외는 비-Mythos SF를 21~30에 넣는 우회로가 아니다.
- 단순히 현대 기술, 연구시설, 실험 장비, 컴퓨터, 생명공학, 비정상 장치가 등장한다는 이유만으로 SF로 판정하지 않는다. `그 SF적 세계 전제가 없어지면 작품의 세계 정체성이 무너지는가`를 기준으로 본다.
- 81~90 크리쳐·괴물·육체 호러도 SF 작품을 자동 허용하는 우회로가 아니다. 같은 크리쳐 구조라도 SF 세계가 핵심인 원작은 자동 후보에서 제외한다.
- 사용자가 특정 SF 원작을 직접 지정하면 HOMAGE_DRAFT_SELECTION가 우선하며 정상적으로 허용한다. 직접 지정된 작품에서는 그 원작의 SF 존재론을 원작 특징로 충실히 보존한다.

## HOMAGE_DRAFT_SELECTION

## CTHULHU_SOURCE_UNIT_ROUTING

## STAT_DRAFT_GENERATION

- 각 A/B/C 안은 STR/CON/SIZ/DEX/APP/INT/POW/EDU 8개, 합계 400, 개별 30~80, 5단위다. 세 안을 같은 숫자 묶음의 재배열로 만들지 않는다.
- 각 안의 Luck은 별도 생성 난수로 20~80 정수 하나를 정한다. 400 합계·5단위 제약에 포함하지 않는다.
- 8특성의 모든 적격 순서 배열을 표본공간으로 하는 균등 bounded-composition sampler를 사용한다. 각 안과 Luck에 독립 generation seed/sub-seed를 사용한다. 직업·사건·게임플레이 난수를 입력으로 쓰지 않는다.
- 생성 후 개수·합계·범위·5단위·Luck 범위를 실제 검산한다. 8특성 배열이 다른 안과 같으면 해당 안만 독립 retry seed로 재생성한다. 수동 교환·직업 최적화로 수치를 조정하지 않는다.
- 플레이어가 한 안의 특성과 Luck을 함께 선택한다. A 특성+B Luck 혼합과 키퍼의 자동 선택은 불가하다.
- 선택이 확정된 뒤 직업 후보를 생성하고 [PC_DERIVED_STATS](04-setup.md#pc_derived_stats)로 파생값을 계산한다. Luck 20은 플레이 중 소비 하한이 아니다.


실제 Python에서 사용할 수 있는 균등 표본 함수다. 각 안의 독립 seeded rng를 인수로 주고 Luck은 별도 stream으로 생성한다.

```python
from functools import cache

@cache
def ways(n, total):
    if n == 0:
        return int(total == 0)
    if total < 0 or total > 10 * n:
        return 0
    return sum(ways(n - 1, total - x) for x in range(11))

def sample_stats(rng):
    total, values = 32, []  # 8*30 + 5*32 = 400
    for n in range(8, 0, -1):
        ticket = rng.randrange(ways(n, total))
        for x in range(11):
            count = ways(n - 1, total - x)
            if ticket < count:
                values.append(30 + 5*x)
                total -= x
                break
            ticket -= count
    return values
```

## PC_DERIVED_STATS

확정된 8특성에서 계산한다. 생성 뒤 파생값의 공식으로 기존 특성을 바꾸지 않는다.
- HP=floor((CON+SIZ)/10).
- initial/current SAN=POW, 기본 max SAN=POW. 신화 상한은 [SAN_CORE](03-danger.md#san_core)를 적용한다.
- DB/Build는 [DAMAGE_BONUS_AND_BUILD](02-checks.md#damage_bonus_and_build) 표를 사용한다.
- MOV=8. DEX≥70이면 9, DEX≤40이면 7. 이 MOV는 기존 하우스룰이다.
- Luck은 선택한 특성 안에 붙은 20~80 생성값이다.
- 시작 기능은 [PC_SKILL_START_VALUES](04-setup.md#pc_skill_start_values)를 적용한다. 신규 신화 기능은 활성 세계에서 0으로 시작한다.

## STARTING_EQUIPMENT_MINIMAL

신규 PC는 실제 시대·직업·담당 업무를 수행하는 데 필요한 **직업 관련 필수 물품 정확히 1개**만 **직업 기본 지급분으로** 시작 인벤토리에 가진다. 선택해 장착한 영구 카드 **자산은 이 직업 기본 지급분과 다른 별도 캠페인 시작 1회 실물 지급**이며 CARD_EQUIP_AND_ASSET에 따라 소지 상태에 기록한다. 장비의 명칭·통상 기능·실제 소지 이유·소유자·사용 조건·메인/파우치 점유를 확정한다. 생존에 유리한 만능 물품보다 해당 직업에서 실제로 당장 사용할 수 있는 물품을 우선한다. 필요하면 직업 선택 뒤 이 1개를 구체화하되 무작위 장비 꾸러미는 만들지 않는다.
한 개는 물리적으로 하나인 물품이며, 별개로 사용할 수 있는 여러 도구가 든 키트·세트·추가 파우치 묶음이나 공짜 보조 무기/탄약/의약품/통신기/서류를 끼워 넣지 않는다. 일체형 구조와 실제 장착된 최소 작동 요소만 그 물품에 포함하고, 소모성 자원은 실제 수량을 기록하며 예비품은 주지 않는다. 통상 복식·이미 가진 직업 지식·법적 지위를 별도 무료 장비로 둔갑시키지 않는다. 물품이 메인/파우치에 들어가면 INVENTORY의 일반 점유 규칙을 적용하고, 빈 슬롯에 가상 기본 물품을 채우지 않는다.

## FULL_DIVE_CROSS_ANALYSIS

원작의 존재론·핵심 갈등·시대/생활·공간/미학·인물/사회·위협 작동·발견/대응/실패의 문법을 파악한다. 작품의 확인된 사실과 이번 각색을 구분하고 불확실한 핵심만 검색한다. 특징 개수나 세계 법칙 최소 개수는 없다.
산출물은 원작 요소→이번 세계의 실제 인물/공간/위협/물건→PC의 접촉/선택→결과/후속 국면으로 연결한다. 모든 요소를 설명문에만 두거나 같은 범용 창고/문서 조사로 번역하지 않는다. 다른 원작에 일률적인 교단/신격을 덧씌우지 않는다. 원작의 핵심을 살린 새 사건을 만들 수 있다.
먼저 원작 체험 모델을 만든다. PC가 어떤 일상/관계/공간에 들어와 무엇을 해보고, 무엇에 위협받으며, 어떤 수단/협력/지식으로 살아남고 목적을 이룰 수 있는지 연결한다. 원작 고유의 재미·생활감·유머·경이·공포와 적의 제약이 실제 행동을 바꾸어야 한다. 원작 이름·가면·지명·용어만 바꾸어도 같은 자료 수사로 진행되는 설계는 다시 구성한다. 등장인물의 직업이 체험 장르를 자동 결정하지 않는다.
원작의 깊은 원인/갈등 → 고유한 현상·공간·위협의 작동 → PC가 겪는 난관·관계/행동 선택 → 이해/준비로 달라지는 대응과 결말을 연결한다. 원작 명칭·괴물 외형·배경 설명만 남고 실제 진행이 범용 업무/재난 수습이면 핵심 체험 연결을 보완한다. 그 원작의 공포가 일상·몸/인식·관계/공동체·세계 이해 중 무엇을 어떻게 흔드는지 실제 경험으로 정한다. 인간의 폭력/의심·불가해한 존재·초자연 법칙을 원작에 맞게 사용하고 모든 세계를 같은 음모/유물/우주적 재앙으로 번역하지 않는다. 깊은 원인은 행동 속에서 체감하게 하며 전모 설명·새 신격·PC의 숨은 죄/과거를 의무로 만들지 않는다.

신규 캠페인의 주요 공포는 원작의 핵심 갈등/경험 → 그 세계에서 드러나는 형상·공간·행동 → PC가 실제로 겪을 접점과 난관 → 관측/이해·대응으로 이어지게 구체화한다. 어떤 모습/소리/움직임이 무엇을 드러내며, PC가 이동·구조·접촉·회피 중 무엇을 겪고 무엇을 시도할 수 있는지 정본의 해당 장소/위협/인물에 둔다. 의식/장치의 발동·중지 절차만 상세하고 공포는 ‘기괴한 공간/무서운 존재’로 비어 있으면 해당 체험을 보완한다. 인간의 행동과 신체적 위협·사회/생태·불가해한 현상도 원작에 맞는 내용이며 모든 형상을 죄책감/심리의 상징으로 만들거나 설정 해설을 들어야만 대응하게 하지 않는다.

## SCENARIO_BLUEPRINT

세계 생성의 필수 결과는 원작 체험을 진행할 조건부 진행 설계도다. 기본 순환은 당면 목적 → 세계의 변화와 직접 경험 → 행동/관계/수단 선택 → 실제 결과 → 달라진 상황과 다음 목적이다. 생존 대응과 발견·준비·탐험·구조·도주·대면·협력·돌파·성취·환기가 서로 이어지고 중대한 난관과 개입·해결·탈출·여파에 도달할 수 있게 한다. 이는 분기/단축 가능한 상황망이며 PC 행동/실패/부상/사망을 예약한 대본이 아니다.
비공개 정본의 기존 WORLD_BASELINE/HIDDEN_TRUTH/WORLD_RULES/DRIVER_BASELINES/ENDING_CONDITIONS에는 원작의 핵심 사건/세력·대표 적과 원작다운 공포의 실행력을 지탱하는 고정 축, 이번 시나리오의 새로운 주인공/사건/인물·진실/분기 축을 함께 구축한다. 선택한 원작의 중심 사건을 다른 시점에서 직접 체험하거나, 같은 인과와 교차하는 새로운 사건을 만들 수 있다. 매번 어느 쪽을 주로 겪는지 원작의 시대·세계 법칙·대사건의 실제 무게를 기준으로 달리하되, 원작 주인공의 경로나 영화의 특정 물품/감염/시설 순서를 복사하지 않는다. 원작 배경·소문·유명 인물 이름만 남긴 채 실제 사건을 사소한 고장·인양 사기로 축소하지 않는다.
정본의 중심은 살아 있는 세계와 플레이 가능한 상황망이다. 장소의 생활/사용·경로/출구·사람들의 관계/욕구·지금 하려는 일·접근 수단·위협의 접촉 경로·도움/준비/안전의 확보·실패 뒤 가능한 행동을 연결한다. 주요 소재의 원래 목적/중요성/악용/활용과 실제 소유/접근을 정한다. 정보만 얻는 방문을 기본 국면으로 반복하지 않는다. 조용한 관계/생활/준비도 실제 경험이며 모든 상황을 전투/추적으로 채우지 않는다.
미스터리는 체험을 설명하고 선택을 바꾸는 층이다. 중심 원인·숨은 진실·적의 목적/실행력·이미 시작된 과정·미개입 결과를 정하되 진상 입증을 모든 장면의 목표로 삼지 않는다. 무엇이 일어나고 누구를 믿을지, 어떻게 대응/구조/탈출할지가 행동 속에서 달라져야 한다. 제도적 조사/증거 수집은 원작·현재 목적에 필요하거나 플레이어가 선택한 경로다. 기본 진행을 기관 방문→증언→자료 대조→증거 확정의 사슬로 설계하지 않는다.
핵심 진실은 앞서 겪을 현상·물건·인물 행동의 의미를 바꾸는 사전 원인으로 설계한다. 처음 드러나는 사실/부분적 이해·그 이면의 실제 인과·행동 중 맞닿을 접점·드러난 뒤 달라질 위험/수단/관계/대가와 목표/신뢰를 다시 선택할 근거를 연결한다. 진실을 알아도 같은 판단·작업·결말만 남거나 뒷이야기에만 설명되는 구조는 서사 심화가 부족하다. 명백한 사실을 일부러 숨기거나 초기의 올바른 추리를 틀리게 만들지 않는다. PC의 감정·신뢰·목표 채택은 플레이어가 정하며, 반전 횟수/고정 단계·인물 배신·필수 희생은 할당하지 않는다.
이번 사건의 의미와 결정적 선택을 떠받치는 내막은 ‘알 수 없는 힘’으로 비워 두지 않는다. 정본에는 이번 사건에서 확정한 원인의 역할·이해관계·주요 소재의 의미와 한계, 그것이 드러날 실제 흔적/행동/위해를 둔다. 우주론 전체와 원작이 남긴 불가해함은 미지로 남길 수 있고, 설명되지 않은 근원도 실제 영향·한계·대응은 일관되게 운용한다. 새 진실을 만들기 위해 확정 과거·능력·소유·성과를 소급 변경하지 않는다.
핵심 원인은 행위자·수단/권한·접근/정보 전달 경로·발동 조건·관측 결과·차단 방법까지 실제로 연결한다. 중요한 기록/물건은 생성·변경·복사·이동 경로와 한계를 정하고 시간 항목/지도/고정 ID를 일치시킨다. 이것은 키퍼 내부 인과이며 플레이어의 매 단계 검증 과제가 아니다. 모든 방/문서/통신 절차를 사전 작성하지 않는다.
**첫 장면과 재앙의 발동 시점:** 주요 재난의 희생·중요 전환을 게임 시작 전에 모두 끝낸 뒤 PC에게 뒤늦은 수사/구호만 맡기지 않는다. 가능하면 평범한 목적/생활을 직접 경험한 뒤, **게임 시작 후 중대한 사고·습격·봉쇄·변형·붕괴·구조 위기 등의 실제 발동 또는 확대**를 PC의 관측과 대응 가능한 범위에서 일으킨다. 시작부터 이미 사고가 발생한 상황이라면 **이후 실제 진행하는 중요한 변곡점과 PC가 예방/저지·완화/회피/구조할 구체적 기회**를 둔다. 사고 발생/피해를 무조건 예약하지 않고 비공개 정본에 주체·수단·발동/취소·전조·대응/실패 결과를 연결한다.
**PC 중심 접촉:** 원작의 중심 사건을 화면 밖에서만 진행시키지 말고, 실제 인물·세력·대표 적의 행동이 PC의 **직업/업무·일상·확정 관계·이동/생활수단·동료·안전**과 충돌하도록 구성한다. 의뢰·직무 요청·우연한 현장 사고·거래/책임·관계 갈등·위험한 물품 등의 경로는 시나리오마다 다르게 만들되 PC의 미선언 동의·부채·계약·감정을 발명하지 않는다. 그 접촉은 단순 업무/아이템 지급을 넘어 중심 갈등의 이해관계·NPC의 협력/적대·대응/퇴로·결말을 바꿀 수 있어야 한다. 세계의 사실과 후속 진행은 자립하지만 **실제 위험과 중요한 선택이 PC에게 도달**해야 한다.
**초반 철수의 난관:** 신규 시나리오에서 평범한 일을 마치고 **원작다운 적·공포·위협을 실질적으로 경험하지 않고 아무 난관 없이 귀가하는 경로는 미완성 설계**다. 가장 빠른 정상 귀가/관여 거절/우회·도주 경로를 포함해, 출발 지점과 안전권 사이에 이미 존재하는 위험의 접근/활동 범위를 인과적으로 설계한다. 원작의 대표 적·괴이가 **직접 행동하며 PC가 관찰·회피·대처해야 할 실제 접촉 기회**를 만들고, 해난/화재·봉쇄·추적/구조 등 생존 난관이 실제 경로/대응·실패와 이어지게 한다. 괴물 흔적·소문만으로 원작을 충분히 경험했다고 처리하지 않는다. 그러나 이 목표는 **전투 의무·적 출현 횟수·고정 부상/피해를 요구하지 않는다**. PC가 원인을 실제 사전 차단하거나 위험을 돌파해 안전권에 도달했다면 즉시 유효한 철수를 인정하고 나중에 새 적·길막·공격을 발명하지 않는다.
조사/의뢰 수락은 사건 발생 스위치가 아니다. 인물과 위협이 PC의 위치·관계·목적·안전에 먼저 닿는다. 초반의 작은 이상은 더 큰 원인·영향권과 연결되고, 밝혀진 사실은 대응법·목표·다음 난관을 바꾼다. 설명용 원인만 있고 실제 결과·해결이 사소한 설계는 수정한다.
일반 진행은 조건 성립을 우선하고 실제 일정이 있을 때만 시간 조건을 쓴다. 세밀한 시간표/숨은 마감/필수 왕복은 만들지 않는다. 큰 세계를 긴 피해 없는 조사로 대신하지 않는다. 실제 위협과 손실 가능성, 대응·획득·안전·성취가 진행 중 체감돼야 한다.
확정할 것은 원인·능력·주요 조건과 가능한 구조다. 주변 미확정 세부·후속 상황은 플레이에서 일관되게 창작할 수 있다. 성공을 취소할 새 비밀·능력·봉쇄를 소급 추가하지 않고 조기에 해결한 성과도 인정한다. 정본은07-state, 실제 국면과 처리 결과는 현재 상태에 보존한다.
주요 연결은 실제 원인/장소/인물·발동/억제 조건·관측 현상·접근/피해·가능한 대응·차단/실패 뒤 상태로 구체화한다. ‘위협이 커질 수 있다’·‘안전하면 탈출한다’는 가능성만으로 설계 완료라 하지 않는다. 평범한 목적에서 깊은 관여와 큰 난관으로 이어질 근거를 두되 발견/준비/관계가 실제 다음 선택을 바꾸게 한다. 정해진 순서/피해/결말을 예약하지 않으며 조기 차단/철수도 남긴다. 필수 물건의 기준 소유/위치는 하나로 정하고 실제 복수 사본은 각각 구분한다. 문장 틀/추가 필드/별도 파일은 강제하지 않는다.

신규 캠페인은 시작 배치부터 자연스러운 귀가·우회·관여 축소와 의도적 도주가 실제 위험권을 지나는 생존 경로가 되게 설계한다. PC가 위험권에 들어온 근거·현재 영향 범위·정상 이동/이탈 경로·바깥 안전 경계를 정하고, 경로별 기존 위협의 접근/추적·차단 조건·관측/대응·준비/우회·실패 뒤 상태를 연결한다. 서로 다른 경로/수단은 위험과 이점·필요한 준비가 달라지게 한다. 조사/의뢰/핵심 장소 방문에 동의해야만 모든 위험이 켜지고 초반 귀가에는 아무 원인도 닿지 않는 설계는 보완한다. 출발 의도 자체를 공격 스위치로 쓰지 않고 NPC는 실제 인지/전달·위치/시간·수단이 있어야 가로막을 수 있다. 탈출 선택 뒤 적·봉쇄·능력을 소급 발명하거나 모든 경로를 같은 장면으로 돌려보내지 않는다. 실제로 접근 원인을 끊거나 유효한 안전 경계에 도달한 성과는 유지한다.

## FINAL_THREAT_DESIGN

최종 위험은 괴물·조직·환경·확산 과정·복합 원인일 수 있다. 다음 8개 내용이 서로 연결되어야 한다: 실체 / 목적과 진행 / 능력·한계 / 격화·차단 조건 / 결정적 난관 / 개입·제압·생존·탈출 수단 / 필요한 이해·준비·획득 / 실패·방치 영향.
독립5축 추첨이나 추가축 추첨은 의무가 아니다. 원작·중심 인과로 도출하고 실제 무작위가 필요할 때만 적격 목록을 먼저 고정해 Python을 쓴다. 수치/피해/방어/이동·실제 파급은 사용 전에 확정한다. 전투 Tier와 SAN Tier는 분리한다.
현재 세계에 존재/진행하는 위협이어야 하며 최후에 갑자기 무관한 보스를 붙이지 않는다. 앞선 정보·도구·동료·환경 변화가 최종 대응을 바꾸게 한다. 선제 제압·예방·우회·철수와 원인 차단이 성립하면 인정하고 억지 페이즈/재난으로 연장하지 않는다.
결정적 난관은 현재 원인이 만든 구체적 상황과 접근/실패 영향으로 정한다. 어떤 준비·도구·동료·이해가 무엇을 가능하게 하거나 위험을 줄이는지 연결한다. 심층 인과가 실제 진행으로 드러난 분기에서는 알게 된 의미와 앞선 선택/관계·준비·치른 대가가 해결 방식·생존·손실·여파에 함께 쓰이게 한다. 작업 완료 보고나 더 강한 적의 등장만으로 절정을 대신하지 않는다. 해결·구조·실제 이탈의 완료 경계와 남은 위험을 구분하고 원작에 맞는 생존/탈출도 유효한 결말로 준비한다. 근원 전체의 소멸·고정 보스전·모든 진상 규명은 공통 필수가 아니다.

신규 캠페인의 결정적 난관에는 앞서 겪을 주요 사건·형성 가능한 관계·얻거나 잃을 준비/수단이 어떤 구체적 행동·협력·차단·구조·포기/탈출을 가능하게 하고 생존/해결 방식·대가/여파를 어떻게 바꾸는지 조건부로 연결한다. 단순히 ‘동료/아이템이 유용함’이라 쓰거나 마지막에 회상/설명하는 것으로 완료하지 않는다. 실제로 형성된 신뢰·역할·준비와 현재 인과가 성립한 경우만 활용하고 미형성 관계·미선언 희생을 가정하지 않는다. 모든 경험/인물/물품의 사용, 고정 보스전·새 퍼즐·필수 손실은 요구하지 않는다. 예방/우회로 난관을 없애거나 간단한 차단으로 해결해도 인정하고 실제로 지킨 것과 남은 여파를 결말에 반영한다.

## WORLD_RULE_HOMAGE_DNA

원작의 정수와 테마에서 실제 필요한 세계 법칙을 도출한다. 기술·사회·환경·초자연 모두 가능하며 고정 개수는 없다. 법칙별 적용 조건·효과·한계/예외·감지 가능한 현상·차단·회피/대응을 정한다. 플레이어는 현상과 단서·실험·실패 결과로 체득한다. 이미 확정·검증한 법칙을 난이도 조절을 위해 바꾸지 않는다.
중요한 변화는 어떤 기존 상태/원인이 성립하면 어느 범위의 공간·접근·위해·사람/정보 전달이 달라지고 무엇은 유지되는지 정한다. ‘전환될 때 전환한다’처럼 조건을 되풀이하거나 필요할 때 길/능력을 바꾸는 설명은 운영 기준이 아니다. 원작의 설명 불가능한 공포는 남길 수 있지만 키퍼가 적용할 조건/범위·관측·대응은 일관돼야 한다. 모든 초자연 현상을 인공 스위치·정밀 시간표·해독 문제로 바꾸지 않는다.

## HARM_ECOLOGY

사건 진입·발견·탐사·대면·대응·탈출에 부상·죽음·정신적 붕괴가 실제 가능한 위험을 연결한다. 전투 외에도 참극·침해·끔찍한 이해 등 적격 SAN 노출 가능성이 있어야 한다. 효과·발동/노출 조건·실패/방치 결과·대응/처치를 사용 전에 정한다.
준비·관찰·정보·아이템·협상·우회·성공으로 피하거나 줄일 수 있다. 정해진 피해 횟수·필수 희생·강제 감염은 없다. 도달한 위해는 REACHED_DANGER_EXECUTION_GATE로 실제 처리하고 경고로 되돌리거나 원인 없는 구조로 취소하지 않는다.

## CAUSAL_ENDGAME_PRECOMMIT

진실에 도달할 예상 접점과 그 뒤의 의미/대응 변화를 준비하되, 원인을 조기에 차단하거나 이미 진실을 이해한 선택도 인정한다. 반전을 보여주려고 해결을 취소하거나 성공 뒤 숨은 다음 적을 추가하지 않는다. 조기 예방/철수의 결말은 실제로 지킨 사람·일상·관계와 남은 세계의 여파로 마무리한다. 미발견 정답을 결말 전 지문에서 대신 설명하지 않는다.

## COMPATIBILITY_GATE

세계 확정 전 원작/인과/진행/생존/실행을 함께 대조한다. **가장 빠른 초기 귀가/관여 거절**에서 원작 대표 적·공포의 실제 접촉/대응과 생존 난관이 존재하는지, 직업·생활·관계가 **PC를 중심 사건에 직접 연결**하는지, **게임 시작 후 중대한 위기가 실제 발생·확대되며** PC의 선택으로 막거나 완화할 수 있는지를 정본 ref로 대조한다. 문제 발견 시 시작 전 원인/공간/행동 연결을 보강하고 플레이 중 소급 장애물은 만들지 않는다. 기존 비공개 정본의 HIDDEN_TRUTH·WORLD_RULES·DRIVER_BASELINES·ENDING_CONDITIONS에 기록된 실제 원인·진행·위해·부재 분기·결과 ref를 따라 주요 경로를 대조한다. 수문 고장·종 원판·한 사람의 범죄처럼 현장 장치/소규모 동기를 제거하고도 원작의 중심 위협·큰 피해와 해결의 의미가 성립하는지 살핀다. 그 하나를 제거하면 사건이 실제로 끝나는 설계도 허용하지만, 그 행동이 사전에 존재했던 중대한 위험을 실제로 막은 것인지 정본에서 확인한다. PC가 평범한 업무만 하고 귀가할 경우 세계와 NPC의 실제 진행/차단·위험권/안전·남는 여파를 확인한다. 단지 떠나도 아무 위협이나 변화가 없고 해결해도 아무 차이가 없다면 규모·사건 연결 미완료다. 반대로 실제 예방/조기 차단과 확보한 안전을 손해·추가 괴물로 뒤집지 않는다. 원작 요소가 실제 체험되는가, 중요한 소재의 의미와 큰 원인/위협·해결이 탄탄한가, PC별 직접 연루와 현재 접근/후속 국면이 연결되는가, 실제 위험과 성취 가능한 대응이 있는가, 수치·지도·NPC·단서·정본이 실행 가능한가를 본다.
의미 없는 공정·문서·왕복을 압축하고 유효한 교류/선택·고유 전문 성과는 보존한다. 처음부터 모든 방/직원을 작성하거나 개수/턴/회차 목표를 채우지 않는다. 미래의 선택 결과를 검수 명목으로 실행하지 않는다.
주요한 진행을 따라 당면 목적·행동/관계 선택·위험과 대응·준비/획득·여파가 실제로 달라지는지 대조한다. 단서와 범인의 동기가 있어도 나머지가 문의/서류 확인뿐이면 체험 설계 미완료다. 서로 다른 원작/선택에서도 같은 수사 절차만 남으면 다시 설계한다. 원작을 체험한 평가와 인과/참조 일치 검사를 구분하며 표를 채웠다는 이유로 실플레이 검증 완료라 하지 않는다.
완료 판단은 실제 정본의 참조된 원인·조건·장소/인물·대응·결과로 한다. 가능성만 적고 발동/억제·체험 접점·대응·실제 안전/종결이 비었으면 그 연결은 미완료다. 주된 경로의 진행·다른 수단/조기 차단·실패/철수를 조건부로 대조해 준비/관계와 성과가 살아 있는지 확인한다. 고정 분기 수나 전모 공개는 요구하지 않는다. 시작 전 한 번, 새 챕터/주요 미확정 국면 설계·실제 관련 모순/누락 발견 때 해당 연결만 보완한다. 기존 성과/진실을 지키며 미확정 미래의 빈 연결을 메우고, 매 응답 전수 검토·검토표 출력·추가 검수 모델/저장 호출은 만들지 않는다.
운용 가능한 인과와 서사의 깊이를 따로 대조한다. 주요 진실의 전후에 경험·문제의 의미·관계 선택·위험/대응·대가·결말 중 무엇이 실제로 달라지는지 정본에서 확인한다. 그 진실을 빼도 모든 경험/선택/결과가 같고 피해 대상 수·작업량·설명 분량만 늘면 서사 심화를 보완한다. 주 경로와 조기 이해/예방·다른 대응의 분기에서 이 차이를 살피며, 모든 진실이 모든 항목을 바꾸거나 반전/새 피해를 반드시 거치게 만들지는 않는다. 기술적 조건을 갖췄다는 이유만으로 시나리오 품질 검토를 완료하지 않는다.

공포의 형상/공간 체험과 절정 활용을 구체화하는 위 생성 기준은 신규 캠페인에 적용한다. 기존 캠페인의 새 채팅 재개는 신규 생성이 아니며 이 보강을 이유로 저장된 정본·진행을 재설계하지 않는다. 주요 동기를 더 복잡하게 만들거나 목표를 뒤집는 충격적 반전을 합격 조건으로 추가하지 않는다. 신규 설계에서는 핵심 공포의 실제 접촉/행동과 누적 경험이 쓰이는 결정적 대응을 해당 본문/ref로 대조한다. 공포를 기술 절차 뒤 설명으로만 두거나 관계/준비가 결말 회상에만 등장하면 그 연결은 미완료다. 소박한 동기·간단한 해결도 의미 있는 체험/선택/결과로 이어지면 유효하다.

신규 정본 확정 전 정상 동선을 따라 관여를 줄이는 분기와 초반부터 의도적으로 이탈하는 분기에서 위협 원인→접근/관측→대응/판정→실제 결과→바깥 안전 경계가 본문/ref로 연결되는지 대조한다. 단순 운항 일정/요금만 두고 생존 위협이 없거나, 본편 수락/최종 의례에만 모든 위해를 모아 두면 이탈 설계는 미완료다. 원작별로 다른 생존 난관을 사용하고 고정 관문 수·필수 보스/상처·정밀 마감은 추가하지 않는다. 조건을 제거한 예방/우회·실제로 확보한 안전은 그대로 인정한다. 이 생성 보강은 이후 신규 캠페인에 적용하며 기존 캠페인 재개를 소급 재설계하지 않는다.

## START_BRIEFING_FOG

원작/장르의 정확한 명칭은 세션 메타 정보로 공개한다. PC가 당연히 아는 시대·지역·기술·사회·화폐·교통·직업/기관·일상과 현재 방문 이유·이미 들은 사건을 선택에 필요한 만큼 알려준다. 백과사전식 전체 설명은 하지 않고 필요할 때 상식을 보충한다.
숨은 원인·진실·비공개 세계 법칙·능력/약점·미발견 장소/증거·미래 결과는 발견 전에 해설하지 않는다. 원작명 공개가 이번 사건의 정답 공개는 아니다. 이미 알고 온 의뢰·피해까지 숨겨 시작 동기를 지우지 않는다.
